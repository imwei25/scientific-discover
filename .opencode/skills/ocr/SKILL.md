# OCR 图片识字技能

> **产物位置**：写到当前工作目录（会话产物目录），裸文件名，别拼 `outputs/` 前缀、别写仓库根。

把"文字印在图片里、选不中也复制不了"的内容识别成可用文本。典型场景：国自然把申请代码表、学部注意事项等**以 JPG 发布**，普通网页抓取（WebFetch）只能拿到目录框架、拿不到图里的字；用户拍照/扫描的表格、公文、证件；图片版 PDF 的书页。

## 铁律：signal not verdict（先读这条）
OCR 是**辅助提取**，不是权威原件。Engine3 中文准确度很高，但**个别生僻字、相近字形（O/0、己/已、末/未）、密排数字仍可能出错**（Windows 兜底通道的错字率更高，实测会把 `58.00` 识成 `58 · 00`）。因此：
- **凡是"错一个字就出事"的内容**——申请代码、金额、批号、注册号、剂量、身份证/银行卡号、日期——**必须人工/交叉核对**后再用，别把 OCR 结果当定稿。
- 交付时**标注这是 OCR 结果、说明走的是哪条通道、建议对关键字段复核**；能对照原图的就对照，能找到官方文字版的以官方为准。
- 完整性可自查：连续编号（代码表、条目表）OCR 后检查有没有跳号，跳号=漏行。

## 三条通道（脚本自己选，**正常情况下你不需要配任何 key**）
| 顺序 | 通道 | 识别在哪跑 | 额度 | 准确度 |
|---|---|---|---|---|
| ① | **平台代理**（网关注入 `SCI_OCR_URL` 即代表可用，桌面打包版走这条） | 云端 OCR.space Engine3 | 服务端按人/按平台扣 | 最好，含表格排版 |
| ② | **本机 key 直连**（`OCR_SPACE_API_KEY`） | 云端 OCR.space Engine3 | 你自己那把 key 的 | 同上 |
| ③ | **Windows 内置 OCR**（`win_ocr.ps1`，`Windows.Media.Ocr`） | **本机，离线** | **不限次、不花钱** | 兜底档，无表格版面 |

- ①：图片发到本机网关 → 网关贴登录票据转给服务器 → 服务器贴 OCR key 调上游。**key 只留在服务器，客户端拿不到**；引擎由服务端定，次数由服务端扣。
- ②：本机手动跑先 `export OCR_SPACE_API_KEY=<key>`（免费注册 https://ocr.space/ocrapi ，邮箱即可，**别写进仓库**）。
- ③：**Windows 自带的离线识别引擎，不用装任何东西、不用联网、图片一个字节都不出本机**（含患者信息的图走这条最稳妥）。要求：Windows 10 及以上，且系统里装了对应的**识别语言包**（设置 → 时间和语言 → 语言 → 中文(简体) → 可选功能 → 光学字符识别）。**只在 Windows 客户端可用**；Linux 服务器上这条不存在，脚本会如实说没有可用通道。
- **前一条整体不可用（不是这一张失败）就自动换下一条**，并在 stderr 打印`[换道] …：<原因>`。三条都不行才报错，并逐条说清各自缺什么。

### 什么时候会换道（照抄给用户看即可，别自己另找办法）
- `服务器没有识字接口（HTTP 404）` → 线上版本还没更新到带 `/ocr` 代理的那版，或反代没放行。**换 ③ 继续干**，同时提醒用户"这需要管理员部署一次，之后就能回到更准的云端通道"。
- `平台还没有配置图片识字服务`（`OCR_UNCONFIGURED`）→ 管理员没配 `OCR_SPACE_API_KEY`。换 ③。
- `今天的图片识字次数已用完` / `平台今天的总次数已用满` / `上游额度已用尽` → 换 ③（免费、不限次），并明确告诉用户这一批是本地引擎出的、准确度较低。
- `连不上本机网关` → 桌面版主进程没在跑或端口变了。换 ③。

> **别自己发明兜底**：不用去查 tesseract、paddleocr、easyocr 装没装，也不用自己写 PowerShell 调 WinRT——`ocr.sh` 已经把这条路做完并测过了。云端一报错就手写替代方案，只会把一次排查拖成十几轮。**看到 `[换道]` 就是正常工作**，照常往下读结果。

### 其它依赖与额度
- **Python**：项目根 `.venv`（脚本自动解析，随包装好；报错先查路径引号，别重建）。`requests` 必需，`Pillow` 用于压缩 >1MB 的图（**只有云端两条通道需要压缩**，③ 用原图），`PyMuPDF` 用于把 PDF 逐页渲染成图（喂 PDF 时才用到）。
- **免费额度**（云端两条，**全平台共用同一把 key 的配额**，注意别刷爆）：Engine3 **2500 次/月**、Engine1/2 25000/月、500 次/天/IP、**单图 ≤1MB**（脚本自动压缩超标图）。走平台代理时还有两层闸：每人每天若干次（档位定）、全平台每天/每月上限（`OCR_DAILY_CAP` / `OCR_MONTHLY_CAP`）。撞到闸时脚本**说清是哪一层**（自己的次数用完 vs 全平台池子满了 vs 平台没配），不会把剩下的图一张张再撞一遍。

## 用法

**入口有三个，等价，挑你手上能跑的那个**（逻辑都在 `ocr.py`，两个壳只负责找 `.venv` 的 python）：

```bash
# 有 bash（Linux / macOS / Git Bash）
bash "${REPO_ROOT:-/app}/.opencode/skills/ocr/scripts/ocr.sh" 图片URL或路径
```
```powershell
# 只有 PowerShell（Windows 桌面版常见）
powershell -NoProfile -ExecutionPolicy Bypass -File .opencode\skills\ocr\scripts\ocr.ps1 图片路径
```
```bash
# 手上已经有 .venv 的 python，最省事
"${REPO_ROOT:-/app}/.venv/bin/python" .opencode/skills/ocr/scripts/ocr.py 图片路径   # Windows: .venv\Scripts\python.exe
```

```bash
# 多个按顺序识别，输出间以 "===== FILE: <名> =====" 分隔；PDF 直接喂，不用自己拆页
bash .../ocr.sh a.jpg scan.pdf c.png > out.txt

# 只用某一条通道（排查时用；proxy | key | win）
OCR_FORCE_CHANNEL=win bash .../ocr.sh a.jpg

# 官方页面里的图先解析出真实图片 URL 再喂进来（页面常是 <img src=...jpg>）
```

> **⚠ 别直接调 `win_ocr.ps1`**。它不是入口，是三条通道里**最差的那条**（本机离线兜底：不做表格版面、
> **不认 PDF**、错字率高于云端 Engine3）。绕过 `ocr.py` 直接调它 = 主动放弃云端 Engine3，还会在
> PDF 上直接失败。**"看到 `.sh` 跑不了 → 自己找别的脚本"是个已知的踩坑路径**：正确做法是换成上面
> 的 `ocr.ps1` 或 `ocr.py`，通道选择交给它。

脚本做的事：取图（URL 下载 / 本地读）→ **PDF 在需要时用 PyMuPDF 逐页渲染成 PNG**（本地通道必转，云端在 >1MB 时转）→ 云端通道用 Pillow 把 >1MB 的图压到 1MB 内 → 按 ①②③ 顺序挑一条能用的通道（云端 `language=chs, OCREngine=3, isTable=true`）→ 识别文本走 **stdout**（多页 PDF 以 `----- PAGE n -----` 分页），通道/换道/额度/失败信息走 **stderr**（所以 `> out.txt` 拿到的是干净文本）。

## 典型流程（官方图片文件 → 可用文本）
1. 目标是网页里的图 → 先用 `.venv` 的 requests+bs4 解析页面 `<img>` 的 src，拿到真实图片 URL（NSFC 等站点直接抓页面可能 412，加 User-Agent）。
2. 逐图跑 `ocr.sh`，**顺手看一眼 stderr 的 `[通道]` / `[换道]`**——它决定了这批结果的可信度档次，也决定你交付时要说什么。
3. **核对**：对照原图抽查关键字段；连续编号查跳号；关键数字/代码交叉核实。走了 ③ 的话核对力度再加一档。
4. 落地：写进产物或（维护场景）更新对应参考资料，并注明"OCR 自官方图片、口径年份、关键字段建议系统内复核"。

## 局限（如实告知用户）
- 云端两条：单图 ≤1MB（脚本自动压缩，极密的大图压缩后可能掉精度 → 可让用户提供更清晰的原图或分块）。
- 手写体、艺术字、极低分辨率、盖章/水印遮挡处准确度下降。
- 不做版面语义理解（不还原合并单元格的复杂表格逻辑）——只出文字与大致行序。
- 免费额度共享，大批量扫描前先估算张数；不够时降 Engine1/2 或换其他后端。
- **Windows 兜底通道（③）额外的三条**，用了就得说：
  - **完全不做表格版面**（云端有 `isTable`，它没有）——多栏表格会被拍平成行，列的对应关系要人工还原。
  - **引擎本身不认 PDF**（云端可以）——但脚本会替你用 PyMuPDF 把 PDF 逐页渲染成 PNG 再识别（200dpi），所以**你照常把 .pdf 喂给 `ocr.sh` / `ocr.ps1` 即可**；只有 `.venv` 里没装 PyMuPDF 时才需要用户自己导图片。
  - 错字率高于 Engine3，尤其是小数点、密排数字与生僻字；脚本已把小图放大 2 倍来补一点，但**关键字段务必逐个核对**。

## 衔接
- 官方以图片发布的标书/政策文件 → 本技能提取后供 `grant-proposal` 更新要求卡（那边"动态核实闸"遇到图片文件即走本技能）。
- 图片版 / 扫描版 PDF → 先用 `fulltext-retrieval` 取得 PDF，再逐页图 OCR（或直接喂图片版页面）。
- 含患者信息的图 → 提取后若要入库分析，先走 `deidentify` 脱敏。

## 约定
- **交付时说清用的是哪条通道**（云端 Engine3 / Windows 本地兜底）。用户据此决定核对到什么程度；含混带过等于把风险悄悄转给他。
- 不虚构：识别不出的地方标"[识别不清]"，别脑补填字。
- 关键字段（代码/金额/批号/剂量）一律标注"待人工复核"，不下"就是这个"的定论。
