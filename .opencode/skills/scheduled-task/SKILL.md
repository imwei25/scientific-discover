# 定时任务技能（scheduled-task）

> **决策规约（照 AGENTS.md §六）**：要用户拍板的地方一律**在正文里列 2–4 个编号候选**（推荐项放第 1 个），让用户**回一个数字即推进**。**问完本轮就结束、等用户真的回答**——注册定时任务是会自己花钱的动作，绝不替用户拍板。

## 这是什么、不是什么

到点时，一个**无头进程**会在后台起来，像用户自己发了一条消息那样跑完整轮对话（走无人值守模式：遇到编号选项自己选推荐项、缺信息标"待补充"继续），产物落在一个新会话里，用户下次打开软件会收到提示。

- **软件关着照跑**；但**机器关机 / 睡眠时不跑**（开机后会尽快补跑一次），**注销或切换 Windows 账户时也不跑**。
- **只支持 Windows**（执行体是 Windows 任务计划）。非 Windows 部署下 `task-cli` 会明确报错，如实告诉用户，别硬试。
- **前提：用户在这台机器上登录过一次**（无头进程靠已存的登录态自己续 token）。

## 先看档位：这个账号能建什么样的任务

**动手之前先跑一次 `doctor`**，第一行就是档位。三种情况，做法完全不同：

| 档位 | 能建什么 | 你该怎么做 |
|---|---|---|
| **未开通** | 什么都建不了 | 如实告诉用户「你的账号档位没有开通定时任务，需要联系管理员」。**别去试，也别提议绕过。** |
| **只能用模板** | 只能用内置模板，参数由用户填 | 走下面的「模板档做法」。**用户要求自由指令时如实说做不到**，并把模板能做的说清楚 |
| **自由指令** | 任意任务 | 走「第 1 步」起的完整流程 |

**模板档做法**：`task-cli add --preset` 会列出所有模板及其参数（直接跑一次看清单）。你的活是
**把用户那句话映射成模板参数**——比如"帮我盯着胰腺癌早筛的新文章"→ `--preset lit-push --param topic="胰腺癌 早期筛查"`。
参数照样要跟用户确认（尤其检索词，太宽泛会推来一堆不相关的）。**模板档下 prompt 由系统拼，
你写的自由指令会被丢弃**——所以别费劲写 prompt，把力气花在把检索词问准上。

模板档的任务还会被**强制用管理员指定的模型**（通常是便宜的那个）。用户问起就照实说：这是账号档位决定的，改不了。

## 铁律

1. **绝不擅自建任务**。任何注册 / 修改 / 删除之前，把**完整任务卡**（做什么、什么时候、产物是什么、每次大约花多少积分、上限多少）摆给用户，按编号选项让他确认。本轮到此为止，等他回话。
2. **写出来的 prompt 必须自足**。到点跑的时候没有人能回答问题、没有人能补文件。凡是"要看用户手上的数据""要用户先选个方向"的活，**不能**做成定时任务——如实告诉用户哪一段不适合，并给出可自动化的替代版本。
3. **必须设单次积分上限**。默认给 50，并向用户说明它的作用（跑飞了到点就停，不会把当天额度吃光）。用户说不限就写 0，但要提醒一句。
4. **不虚构运行结果**。任务注册完就是注册完了，别说"已经帮你跑好了"。用户问结果时去读运行记录。

## 怎么做

### 第 1 步 · 把想法翻成自足的任务内容

用户说的往往是"每周帮我看看有什么新文献"。这句话直接做成任务会跑出一坨没法用的东西。要补齐四件事，缺哪件就问哪件（能枚举的列编号候选）：

| 要素 | 为什么非要不可 |
|---|---|
| **范围**（检索式 / 领域 / 期刊 / 时间窗） | 没有它，每次跑出来的东西都不一样，且多半跑偏 |
| **动作**（检索？筛选？读全文？写成什么？） | 决定派哪些技能、跑多久、花多少 |
| **产物**（**明确的文件名**，如 `weekly.md`） | 无人值守时没人能确认"你要的是哪个文件" |
| **判据**（什么算做完 / 挑几篇 / 详略） | 没有它，模型自己定标准，两周的产物没法比 |

写成一段**像用户自己发的消息**那样的 prompt，直接可执行。反例与正例：

- ✘ 「每周帮我看看有什么新文献」
- ✔ 「检索 PubMed 最近 7 天关于 <具体主题> 的新文献，筛出与「<用户课题一句话>」相关的，最多 8 篇；每篇给一句话要点、研究设计与 DOI，按相关度排序写成 `weekly.md`；一篇都没有就在文件里写明"本周无新增"。」

### 第 2 步 · 摆任务卡，等用户确认

把任务卡写清楚，然后给编号选项，例如：
**1)** 就按这个建（推荐） **2)** 改时间 / 频率 **3)** 内容再调整。**本轮结束，等回答。**

### 第 3 步 · 注册

用 `${REPO_ROOT:-/app}/web/task-cli.mjs`（node 直接跑，无需 .venv）：

```bash
node "${REPO_ROOT:-/app}/web/task-cli.mjs" add \
  --title "每周文献扫描" \
  --prompt-file task_prompt.md \
  --weekly 1 --time 07:30 --max-credits 50
```

- `--prompt-file` 优先于 `--prompt`：任务内容通常有几百字、含换行与引号，**走文件不会被 shell 拆坏**。先把内容写进当前目录的 `task_prompt.md`（它也留作用户以后要改时的底稿）。
- 频率三选一：`--daily HH:MM` ／ `--weekly 1,4 --time HH:MM`（0=周日）／ `--once YYYY-MM-DD --time HH:MM`。
- 其它子命令：`list`（含下次运行时间与上次结果）、`enable/disable <id>`、`rm <id>`、`run <id>`（立刻跑一次）、`sync`（定义与系统对账）、`doctor`（装没装好）。

**注册完必须复述给用户**：任务名、下次什么时候跑、产物会出现在哪（新会话 + 下次打开软件的提示）、以及上面那三条限制（关机不跑、注销不跑、产物要过目）。

### 第 4 步 · 排查"它怎么没跑"

按顺序，别跳：

1. `node "${REPO_ROOT:-/app}/web/task-cli.mjs" doctor` —— 一次性看出：**账号档位开到什么程度**、环境快照有没有、node 与运行器路径在不在、**定义与系统里的计划任务对不对得上**、登录态有没有。
2. 报"有定义没注册" → 跑 `sync`。
3. 都正常但没产物 → `list` 看上次结果，再让用户在软件的定时任务面板里看运行记录（失败原因、花了多少积分都在里面）。
4. 记录显示"未登录""积分已用尽""上一次还在跑" → 照实说明，这三种都不是故障，是前提没满足。
5. 记录显示「剩余积分低于你设的下限」→ 不是故障：用户自己在定时任务面板设了保护线（把额度留给白天自己用）。要么充值，要么让他把那个数字调低。
6. 到点根本没启动（运行记录里连一条都没有）→ 多半是**那个时刻机器关着或用户注销了**。如实说，并给编号选项：**1)** 改到一个机器通常开着的时间（推荐） **2)** 保持不变，接受偶尔漏跑（开机后会补跑一次）。

## 什么样的活不该做成定时任务

直说，别硬接：

- 要用户当场提供数据文件、伦理批号、原始记录的（无人值守时没人能补）；
- 需要方向性拍板才能往下的（选题定案、目标期刊、PICO 收敛——无人值守会自己选推荐项，等于替用户做了决定）；
- 一次性的、下周就不需要的（用 `--once`，或干脆现在就做完）；
- 极长的流水线（整篇标书 / 论文成稿）——它会在轮数上限处停下，留一堆半成品。**建议拆成几个可自动化的小步**（如"每周只更新文献证据表"），成稿仍由用户在场时推进。
