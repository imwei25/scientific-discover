# 推送到微信 / 企业微信（push-chat）

把当前会话（或用户指定路径）的文件与一段文字，经「聊天接入」推到用户手机上的微信 / 企业微信。
**所有脏活网关都封装好了**（目标平台选择、会话 key、只推主产物、自动落款、失败暂存下次补发、
每平台独立报错）——本技能只做三件事：预检定位、能修的自动修、修不了的把「用户需要做什么」说清。

## 用法

```bash
node "${REPO_ROOT:-/app}/.opencode/skills/push-chat/scripts/push.mjs" [--to weixin|wecom|all] [-m "配文"] 文件.pdf
```

- `--to`：推给谁。`all`（默认）= 所有已连接平台；用户点名"发微信"→ `weixin`、"发企微"→ `wecom`。
- `-m`：配文（可省；省了且有文件时只发文件）。**不要自己加落款**——网关会统一附
  「来自Niuma Science科研小助手」。
- 文件：相对当前目录或绝对路径均可。**≤15MB 一律直接作为附件推送**；超过 15MB 的告知用户
  在软件端查看或打包下载。一次最多 5 个（网关限制）。

## 失败闭环（脚本内置，输出按行前缀读）

脚本先做全链路预检（不占发送额度），**能自愈的当场修，修不了的输出明确的用户指令**：

- `OK` 推送成功；`INFO` 过程说明。
- `FIXED` 脚本自己修好了（两类会自动修：聊天接入已启用但桥进程没在跑 → 自动重启桥；
  发送层连不上 cc-connect socket（残留）→ 重启桥后自动重试一次推送）。
- `FAIL` + `ACTION`：修不了，`ACTION` 行就是**要转告用户做的事**，逐字转述别改写。
  典型：软件没开（打开软件）、总开关没开（去「手机接入」勾启用——开关是设置，不替用户改）、
  平台没配置/登录过期（去「手机接入」配置或重新扫码）、平台自软件启动后没收到过用户消息
  （请用户在该平台里给机器人发条"在吗"，然后再推一次）。
- 文件超 15MB：脚本会拒收——先如实告知用户"该文件超 15MB，请在软件端查看或打包下载"；
  用户要的话也可**你来修**：换更小的产物（推 md 而不是 pdf）、压缩、或拆分后重试。

两个平台一成一败时脚本会分别输出，**必须把失败的那半如实告诉用户**（含 ACTION），别只报喜。
推送失败的内容网关已暂存，用户下次在手机上对机器人说话会自动补发——转述时带上这句，
用户就不必再催一次重发。

## 硬约束

- **只在用户明确要求推送时用**（"发我微信/推到手机"）；不要主动、批量、循环推送——个人微信有
  每日发送额度，烧完当天就发不出去了，也别拿发送当探活。
- 服务器/容器部署形态下接口会答 `supported:false`：如实告诉用户此功能仅桌面版，不要另想旁路。
- 推送失败时网关已把内容暂存（用户下次在手机上说话会自动补发）——转述失败原因时顺带说明这一点，
  用户就不必让你重发。
