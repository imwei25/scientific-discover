# 机制示意图（Mechanism Figure）

把**用户自己的机制描述**变成一张构图可控、标签可核的机制示意图。面向组会汇报、标书插图、投稿前的构思稿与图形摘要草案。

## 一、先划清边界（派错技能是最常见的浪费）

| 要画什么 | 用哪个技能 |
|---|---|
| 由**数值**画出来的统计图：森林图、KM 生存曲线、火山图、ROC、箱线图、热图 | **`nature-figure`**（matplotlib/seaborn，出 300dpi + 矢量，可直接投稿） |
| **没有数据**的机制/通路/流程**示意图**、图形摘要 | **本技能** |
| PPT 里的配图、封面图、幻灯片版式 | `ppt-master` |

一句话判据：**图上的形状是由数字决定的 → `nature-figure`；是由生物学关系决定的 → 本技能。**

## 二、能做到什么、做不到什么（先说清楚，别让用户被审稿人打回来才知道）

**能**：几秒钟出一张信息密度高、构图规整、带全量英文标签的机制图，用来讲清"我这套机制是怎么走的"。改一版只要改 spec 再跑一次。

**做不到 / 必须提前告知用户的三件事**：

1. **这是 AI 生成的位图，不是矢量图，不能当投稿终稿。**多数期刊对"生成式 AI 制图"有明确限制：**Nature 系基本禁止**在稿件中使用 AI 生成的图像，**Science/AAAS** 需事先获许可，**Cell Press / Elsevier** 要求披露且限制对图像的 AI 生成与修改。**以目标期刊最新稿约为准**——用户给了目标期刊就 `WebFetch` 它的 Instructions for Authors 核一遍，别凭印象替他下结论。正确的交付路径见 §六。
2. **标签一定会被画错一部分。**文生图模型写字不可靠：`GPX4` 画成 `GXP4`、`↑` 丢掉、同一个标签画两遍都很常见。所以脚本每次都输出**必核清单**，逐个核对是**必做步骤**，不是可选建议。发现错字只能重出或重绘，不要手动 PS 掉——那正是各刊明令禁止的图像操作。
3. **不生成数据、不生成结论。**图上每一个分子名都必须来自用户的材料。`build_prompt.py` 带**反编造闸**：给了 `--source`（稿件/摘要原文）就逐个核对实体标签，找不到就中止。**不要为了让图"好看完整"去补一个用户没测的分子**——那是造假，而且是审稿人一眼能看出来的那种。

## 三、三步工作流

```
用户的中文机制描述 / 稿件
        │
   ①  你（agent）自己读懂并填 spec.json      ← 不调任何外部 LLM，见下方说明
        │
   ②  build_prompt.py  →  锁死构图的英文 prompt + 负面词 + 反编造闸
        │
   ③  render_figure.py →  出图 + 必核清单 + 复现记录(.meta.json)
```

> **为什么第 ① 步不再调一个"提示词重构模型"**：原始规范里这一步是去调火山引擎的 DeepSeek 把中文改写成英文提示词。在本项目里这一步是**纯浪费且有害**的——你自己就是大模型，读中文填 JSON 本来就是你的活；多调一家等于多一把 key、多一次失败点，更要紧的是**它会顺手"补全"机制**（把用户没提的经典通路成员加进去），而那正是本技能要防的头号风险。所以：**你直接填 spec**。

### 第 ① 步：填 spec

拷模板改内容：

```bash
cp ${REPO_ROOT:-/app}/.opencode/skills/mechanism-figure/templates/spec.example.json fig1.spec.json
```

spec 的字段（完整例子见模板，一份可直接跑通的真实案例见 [references/worked-example.md](references/worked-example.md)）：

| 字段 | 说明 |
|---|---|
| `style` | `flat`（默认，多栏全景通路图）/ `realistic`（高拟真 3D，封面与 Key Figure）/ `structure`（结构生物学）。选哪个见 [references/styles.md](references/styles.md) |
| `aspect_ratio` | `1:1`（多栏通路图默认）/ `4:3` / `16:9` / `3:4` … |
| `panels[]` | 每一栏 = 机制的一步。`name` 这步叫什么、`bg` 背景色、`scene` 这一栏的场景、`elements[]` 画哪些结构、`labels[]` 这栏的文字标签 |
| `arrows[]` | 关系。`type` 取 `activate`(实线箭头) / `inhibit`(红色 T 形抑制线) / `translocate`(转位) / `convert`(转化) / `block`(红叉阻断)；`label` 可选 |
| `membrane` | `horizontal-top`（顶部横贯一条双层磷脂膜，多栏通路图标配）/ `none` |
| `extra_negative[]` | 额外负面词（本图特有的"别画什么"） |

**填 spec 的三条硬规矩**（对应下方的构图铁律）：

- **栏数按机制真实步数来，1–6 栏，不要为了凑"4 栏"编内容。** 原始规范把 4 栏写成铁律，但真实机制常是 3 步或 5 步——凑数就要编，编就违背 §二.3。
- **每栏 ≤ 8 个标签、全图 ≤ 24 个**（脚本强制）。超了不是缩字号的问题：实测标签越密，模型越会把字画糊、画串、画重。超了就拆成两张图。
- **`labels` 只写实体名**（分子/基因/细胞归宿/结构），关系描述写到 `arrows[].label` 里。两者的核验严格度不同：实体逐字严查，关系只提醒（关系是英文表述，中文材料里本来就没有原词）。

### 第 ② 步：编译 + 过闸（离线，不花钱）

```bash
${REPO_ROOT:-/app}/.venv/bin/python \
  ${REPO_ROOT:-/app}/.opencode/skills/mechanism-figure/scripts/build_prompt.py \
  --spec fig1.spec.json --source manuscript.md --json fig1.built.json
```

- `--source` **正式出图前必须传**（稿件 / 摘要 / 用户那段描述存成 .txt 都行）。不传只会 warn，但那就等于关掉了反编造闸。
- 被拦下来时**照报错改 spec**，不要绕：
  - 材料里是中文全称、图上要用国际缩写（草酸钙 → `CaOx`）→ `--allow 'CaOx'` 显式声明，会记进复现记录并回显给用户；
  - 确实是本研究没测的分子 → **从 spec 删掉**。
- 输出：`fig1.prompt.txt`（人读）+ `fig1.built.json`（喂给第 ③ 步）。

### 第 ③ 步：出图

```bash
# 先空跑看要发什么（不需要 key、不花钱）
${REPO_ROOT:-/app}/.venv/bin/python \
  ${REPO_ROOT:-/app}/.opencode/skills/mechanism-figure/scripts/render_figure.py \
  --built fig1.built.json --dry-run

# 真出图；构图不稳时出 2–3 张挑一张
${REPO_ROOT:-/app}/.venv/bin/python \
  ${REPO_ROOT:-/app}/.opencode/skills/mechanism-figure/scripts/render_figure.py \
  --built fig1.built.json --name fig1 --outdir figures --n 2
```

产出：`figures/fig1.png`（或 `fig1_v1.png`/`fig1_v2.png`）+ `figures/fig1.meta.json`（模型、完整 prompt、负面词、尺寸、标签清单、AI 生成披露说明——**审稿问起来或半年后要改版，全靠它**；图片 URL 会过期，只存链接等于没存）。

出图后**逐条走必核清单**，把结果如实报给用户：哪些标签画对了、哪些画错/画糊/画漏了。别只说"图已生成"。

## 四、构图铁律（这几条是构图可靠性的全部来源）

脚本已经把它们编译进骨架，**不需要你手写**；列在这里是为了让你知道改 spec 时哪些地方不能动，以及出了问题该往哪看。

1. **N 栏垂直色块 + 顶部 (1)(2)(3)… 数字圆圈**——把"多步骤"这件事变成版面结构，模型才不会把几步糊成一团。
2. **顶部横向双层磷脂膜贯穿全栏**——并显式写明"左侧没有竖向细胞壁、没有巨大刷状缘"。不写这一句，模型极易画成"左边一个占满高度的巨大竖细胞"，多栏通路图就此报废（这是最高频的翻车形态）。
3. **每栏都要有位置锚 + 实体标签 + 方向箭头 + 这一步的结局图标**——四件里缺一件，那一栏就会退化成一块空色块或一堆没有指向的图标。
   > ⚠️ 原始规范在这条里把 `GRP78/CHOP/ATF4/PERK/IRE1/CHAC1/GSH/GPX4/CaOx` 写成了"每张图 Stage 2/3/4 必须包含"。**本技能刻意不这么做**：那是一条具体的通路（ER 应激→铁死亡→草酸钙沉积），当成通用铁律就意味着**给每一张图都塞进一套与本研究无关的分子名**——直接违背"不虚构"。它在这里的正确身份是**一个示例**，见 [references/worked-example.md](references/worked-example.md)。
4. **负面词是排版的第二道锁**——脚本自动合成四组：排版翻车形态、文字质量（糊/串/重）、画风冲突（扁平风排掉 3D、拟真风排掉扁平）、科学噪音（教科书套话、装饰性 DNA 双螺旋、无关细胞器）。标签全是拉丁字符时还会自动排掉中文（Qwen 系模型爱自作主张加中文注释）。
5. **`prompt_extend` 必须关**（脚本已写死 `false`）。开着的话模型会自己"润色"提示词、往里加没有的细胞器和分子——等于绕开反编造闸，也会把锁死的构图重新打散。

## 五、失败排查

| 现象 | 原因与处置 |
|---|---|
| 左边一个巨大的竖向细胞，右边挤成一团 | 铁律 2 没生效。确认 `membrane: "horizontal-top"`、栏数 ≥ 2；再出 2–3 张候选（`--n 2`） |
| 标签糊成一片 / 拼错 / 画两遍 | 标签太多。砍到每栏 ≤ 5–6 个，或拆成两张图。这是模型能力边界，不是提示词问题 |
| 图里冒出用户没提的细胞器/分子 | `prompt_extend` 被打开了，或 spec 的 `elements` 写得太发挥。`elements` 只写要画的结构，别写形容词堆 |
| 图上出现中文注释 | 标签里混了 CJK 字符导致自动的中文负面词没加上。把标签统一成英文，或在 `extra_negative` 手动加 `chinese characters` |
| `今天的生图张数已用完（N/M 张）` | **不是故障，别重试**。张数按档位算，每天 0 点(UTC) 重置；要更多让管理员调档位。提示词已经做好了，明天拿同一份 `.built.json` 重跑即可，不用从头来 |
| `平台的生图服务额度已用尽…不是你的张数` | 平台自己的上游额度没了，**你的张数没被扣**。只能等管理员充值，重试没用 |
| `!! 既没有平台生图通道，也没找到本机 key` | 登录平台账号即可（正常情况不用配 key）；自设 API 形态才需要设 `QWEN_API_KEY` |
| `HTTP 429` | 上游限速，脚本已退避重试 3 次；仍失败就等几分钟。**不要**改成无限重试 |
| 4 栏里有一栏几乎是空的 | 机制没有 4 步却按 4 栏填了。**减栏，不要编内容填满** |

## 六、交付路径：构思稿 → 投稿终稿

**默认交付**（组会 / 标书 / 预印本 / 投稿前讨论）：PNG + `.meta.json`，并把 §二 的三条限制原话告诉用户。

**用户要拿去正式投稿时**，按顺序做：

1. `WebFetch` 目标期刊的 Instructions for Authors，查它对 generative AI images 的规定，如实转述（禁用 / 需披露 / 需许可）。查不到就说查不到，**别替期刊编一条政策**。
2. 把这张图当**版面草图**，交一份**重绘规格**给用户，让他（或美编）在 BioRender / Illustrator 里落成矢量图：栏数与顺序、每栏的实体与位置、每条箭头的起止与类型、配色、字号。`fig1.built.json` 里已经有全部这些信息，照它逐条转写即可——这一步是机械的，不需要再做任何判断。
3. 如果期刊允许且用户选择直接用 AI 生成图，**必须**在 Methods 或图注里披露（模型名、日期、提示词可作补充材料）。`.meta.json` 里的 `disclosure_note` 就是给这一步用的。

## 七、什么时候在流水线里用它

本技能是**单步技能**（AGENTS.md §四 直派），不在任何固定 pipeline 里——机制图是可选配图，不是成稿必需环节。常见用法：

- `paper` 流水线出稿后，用户要一张图形摘要 → 单派本技能；
- `grant` 标书写完，要一张"研究方案总览图" → 单派本技能（标书不投期刊，AI 生图限制不适用，这是本技能最合适的场景）；
- 用户同时要"机制图 + 数据图" → 机制图走本技能、数据图走 `nature-figure`，分别出，别混在一次里。
