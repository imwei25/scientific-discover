# 选题 / 假设生成技能

> **决策规约（照 AGENTS.md §六）**：本技能任何要用户拍板的抉择——方向 / 方案 / 目标刊 / 作图后端 / 纳排标准 / 下一步等——一律**在正文里列 2–4 个编号候选**（推荐项放第 1 个并写明“推荐 X，因为……”），让用户**回一个数字即推进**；**别用开放式提问逼用户打字，也别弹交互选项卡（如 AskUserQuestion）**。只有无法枚举的纯事实（手上的数据文件、伦理批号、代表作清单等）才开放式问。

把"想做研究"变成几个**具体、可评估、可执行**的候选课题。参考 K-Dense 的 hypothesis-generation 思路。

## 定位（本技能在套件中的位置）
顶层主控（AGENTS.md 常驻指令）负责判意图、定范围、派发；派到本技能就**直接做，别回绕**。产物直接写**当前工作目录**——网关已把本会话的 cwd 指到该会话的产物目录，用裸文件名即可（如 `table1.csv`），别再拼 `outputs/…` 前缀，也别写到仓库根。

## 流程
1. **意图对齐（先写 brief，别急着查）**：主代理先把理解到的用户意图复述成一份**研究简报（research brief）**，写清：目标方向、范围与边界、隐含约束（学科/子领域、手上已有的数据或样本、可用方法与周期/经费、新颖性门槛、目标期刊或资助）。**cwd 有 `requirement_card.md`（grant 流水线定标模式的出件）→ 其受理范围/指南方向/资助强度直接写进 brief 作硬约束**，候选课题不许出受理范围（出界的可提但标注"该渠道不受理，仅供换渠道参考"）。缺的约束**主动问用户**（如"你手上有什么数据/样本？""想冲顶刊还是求稳发出去？""偏机制研究还是临床应用？"）。若是高投入调研，**先把 brief 给用户确认一次**再往下。这份 brief 是后续所有子任务共读的同一份规格。
2. **摸清现状**：按 brief 用 `research-scan` 或 `literature-review` 拿真实文献，梳理该方向的空白与争议（别拍脑袋）。子问题多且相互独立时可并行取证，否则串行；**运行时不支持子代理就串行**。
3. **收敛漏斗：从模糊方向逐层降到具体 PICO**（这是"收敛"的心脏，别跳过直接拍候选）。沿下面五层**逐层收窄**，**每层照 §六 列 2–4 个编号候选让用户拍一个数字**再进下一层——这样 narrowing 过程透明、可复现，用户看得懂"为什么收到这里"：
   1. **锁子方向**：宽方向下有哪些可切入的子领域？（如"肠道菌群与肥胖"→ 菌群组成关联 / 特定菌属机制 / 益生菌或 FMT 干预 / 菌群-宿主代谢轴）
   2. **锁人群/亚型**：具体研究谁？（如 成人 BMI≥28 / 儿童青少年 / 减重术后 / 特定合并症）
   3. **锁暴露或干预**：具体测什么/给什么？含剂量、时点、测法（如 某菌属丰度 / 某益生菌 12 周 / FMT 单次）
   4. **锁可测主结局**：一个可测、有临床或机制意义的主结局（如 体重变化 / HOMA-IR / 内毒素血症标志物）
   5. **定可行设计**：横断面关联 / 前瞻队列 / RCT / 动物机制（无菌鼠 FMT）——**据申请人类型与资源选**（见 3.5）。
   > 走查样例（"肠道菌群与肥胖"）：方向→"益生菌干预" → 人群→"成人 BMI≥28" → 干预→"某益生菌 12 周" → 结局→"HOMA-IR 变化" → 设计→"双盲 RCT"。一句话收敛成："某益生菌能否改善肥胖成人的胰岛素抵抗（HOMA-IR）——12 周双盲 RCT"。
3.5 **按申请人类型分流可行路径**（同一方向，不同身份能做的设计天差地别，别给临床医生推需湿实验室的机制题）：
   | 申请人 | 手上典型资源 | 常见可做设计 |
   |---|---|---|
   | 临床医生 | 患者/标本/病历 | 横断面/回顾队列/前瞻观察/单中心 RCT |
   | 基础研究者 | 细胞/动物/湿实验室 | 机制实验（无菌鼠 FMT、敲除、通路） |
   | 流行病学者 | 人群数据库/队列 | 大样本关联、孟德尔随机化、Meta |
   | 交叉/有合作 | 上述组合 | 临床表型 + 机制验证的桥接设计 |
4. **生成候选课题**：漏斗收敛后（或方向已较具体时直接）围绕空白提 3-6 个，每个写清：
   - **一句话课题名**
   - **科学假设**（可证伪的陈述）
   - **PICO**（临床题）：Population / Intervention / Comparison / Outcome
   - **拟用方法/数据**
   - **预期贡献**
5. **多棱镜评分**：对五个维度各评 **1–5 分**（每个分数都要附一句证据/理由，别只给数字），汇总排序——**支持子代理时，每维派一个专门 lens 的评审各自独立取证打分**，主代理综合；不支持时由主代理逐维度顺序自评。这样避免单一视角的乐观偏差。
   | 维度 | 说明 | 打分方向 |
   |---|---|---|
   | 新颖性 | 是否已有人做透；增量还是突破 | 越新越高 |
   | 可行性 | 数据/样本/技术/周期/经费是否够 | 越可行越高 |
   | 价值 | 临床或科学意义大小 | 越大越高 |
   | 竞争度 | 热门=易撞车，冷门=易被忽视 | **适中最高**（太热撞车、太冷无人问津都扣分） |
   | 伦理/合规可行性 | 涉及人/动物/人遗资源/隐私的审批与合规难度 | 越可行越高；**根本过不了伦理→一票否决** |
   - **与申请人条件匹配**也要纳入考量（brief 里问过的手上数据/样本/方法/周期）——再好的题，手上条件够不着也要下调可行性。
   - **cwd 有 `requirement_card.md` 时加第六维 funder-fit（1–5 分）**：按卡的受理范围/指南方向/经费档位与年限打"这个题投这个渠道合不合身"；**根本不在受理范围 → 一票否决**（同伦理维），别让一个渠道不收的题排到推荐位。
   - **可行性别停在定性**：样本量/把握度存疑时，调 `clinical-stats` 做一次样本量/power 粗算再定分——别口头判"样本够"，实际做不到检验的题最坑。
6. **引用核验（分两步，别把两件事混为一谈）**：
   - **存在性核验**：把候选与评分所引文献先导出成 `topic_refs.txt`（每行一条 DOI/PMID/标题），交 `reference-check` 技能核验**真实存在、标题吻合**。⚠️ `reference-check` 只查"这篇文献是否真的存在"，**不能判断它是否支持你的论断**。
   - **支持性核验**：文献"是否真的支持该论断"由主代理**自己回读摘要**确认（必要时用 `fulltext-retrieval` 下全文再读）。别因为脚本跑完就宣称"已核实支持"——那恰恰是本步要防的编造。
7. **完备性自查**：收尾前自问"还漏了什么——没查的来源、没验证的空白判断、没考虑的相邻方向？"，有明显缺口就补一轮。若因成本只查了部分来源/方向，**如实说明**，别让用户误以为覆盖完整。
8. **推荐 + 下一步（编号选项，回一个数字就推进）**：把候选按评分排好序，**给用户编号候选**——推荐主攻方向放 **1**、次选放 **2**、备选放 **3**（每个一句话说明理由与主要风险），照 AGENTS.md §六 让用户**回一个数字即选定该方向往下走、不必打字复述**。选定后再用同样的编号方式问下一步：**1)** 就该方向做一次**对抗式研究**（尽力证伪、查是否已被人做过；成本较高但能提前暴露选题阶段最贵的错误）　**2)** 直接进 `novelty-check` 做新颖性裁定 + 预注册　**3)** 先停一停。对抗式研究要解释清楚是什么、意义何在，**用户选了才跑**（不自动执行）。

## 对抗式研究（按需，需用户确认）
- **是什么**：不再找支持该方向的证据，而是**反过来尽力推翻它**——派一个"反方"子代理专门去找：这个 idea 是否已被人做过（及做到什么程度）、有没有致命的不可行点、隐含假设是否站得住。默认"存疑即真"，能扛住反驳的方向才算真新颖、真可行。
- **意义**：选题阶段最贵的错误，是投入大量精力后才发现方向早被做过或根本走不通。对抗式研究用一次集中的证伪把这个风险提前暴露；同时顺带产出**邻近工作地图**——别人在相似方向做了什么、你的增量差异在哪。
- **为何按需**：它要额外多轮检索与子代理，成本明显高于常规选题，所以只对用户**最感兴趣的 1 个方向**、在用户同意后做。
- 需要时直接衔接 `deep-research`（做该方向的 prior-art / 新颖性复核）与 `research-scan`（画邻近工作地图）。
- **与 `idea-forge` 的分工**：对抗式研究是 agent 对文献**单方面**证伪（用户不参与）；用户想**亲自下场**被拷问、把"凭什么是我做/假设可证伪吗/竞争差异在哪"逐条对话锻硬 → 派 `idea-forge`（选题包）。两者可先后用：对抗式研究出的反证，正好作 idea-forge 的拷问弹药。

## 约定
- 产出写 `topics.md`（含 brief 摘要、候选表、评分、推荐、风险、下一步建议）。
- **出 PDF（正式报告默认交付版）**：写完后把 `topics.md` 交给 `render-pdf-doc` 技能渲染成 `topics.pdf`。中文报告务必指定中文字体（`--cjk-font`：本地 `Microsoft YaHei`，服务器 `Noto Sans CJK SC`），否则会漏字。
- 假设必须可证伪、边界清楚，别写成宽泛口号。
- 空白判断要有文献支撑；**不要虚构"尚无人研究"**——拿不准就说需进一步检索确认。
- 区分**检索事实 / 模型推断 / 观点**；关键论断至少 2 个独立来源，冲突就并列标分歧。
- 衔接：选定 1–2 个主攻方向后，动手写标书/建库前先用 `novelty-check` 做**严格新颖性裁定 + 预注册锁**（把这里的"新颖性打分"升级为可辩护的裁定，并在采数前冻结假设与分析计划）；之后 `grant-proposal` 写标书、`literature-review` 做综述；深挖用 `deep-research`。
