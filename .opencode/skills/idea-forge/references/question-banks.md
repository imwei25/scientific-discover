# idea-forge 场景包（问题库）

每个包给三样东西：**分支顺序**（决策树骨架，也是纵深优先的行进顺序）、**节点表**（问法模板 / 好答案判据 / 检索验证策略）、**轮次预算**。
问法模板是骨架不是台词——照当轮语境改写，但**判据不许放水**：答案没达到判据就还没锻完，达到了就立即标 ✅ 进下一节点，别恋战。

**通用规则（所有包适用）**
- 节点间依赖 = 分支顺序：后面的分支以前面的结论为前提，前面改了要回头看后面哪些节点被牵连（在 forge_log 里把受牵连节点改回 ❓）。
- "检索验证策略"列写的是**什么样的回答值得花一次检索**。没列的节点默认不检索，靠逻辑拷问。
- 检索式围绕**科学问题/主张本身**构造（干预+人群+结局、方法+对象），不要只查疾病名——那只会捞回一万篇背景。

## 一、标书包（立意 → 创新点 → 方案）

对齐 `grant-proposal/references/rationale-and-innovation.md` 的论证骨架；产物直接映射 grant-proposal 第 3.5 步的四件套（closest_work.md、gap 归因、关键科学问题、创新点五要素）。
**前置材料**：渠道要求卡（含评审评价维）；指标驱动渠道（重点研发/四大慢病）另取指南方向与考核指标。

### 分支 1 · 立意（预算 ≤6 轮）

| 节点 | 问法模板 | 好答案判据 | 检索验证策略 |
|---|---|---|---|
| 痛点具体化 | "临床/科研上**哪个具体决策点**因为这个问题卡住？现在只能采取什么次优做法，代价是什么？" | 落到具体决策场景+可量化代价；"发病率上升危害健康"不算 | 无（吃用户独有的临床观察，检索替代不了） |
| 最接近工作 | brainstorm：检索后呈现"我查到最接近你想法的是这 3–5 项工作……" | 每项能说清"它回答了什么+在什么条件下失效"（八类失配之一，具体到设计参数） | **必检**：干预/方法+人群+结局构造检索式；这是本包最重的一次检索，结果直接建 closest_work.md。**同轮加注册库快查**（ClinicalTrials.gov/ChiCTR 各 1–2 条定向查"在研撞车"；查不通如实标"留给 novelty-check"）。**方向转向后本节点重开**：对新方向把文献+注册库快查再跑一遍，别拿旧结果背书新方向 |
| gap 归因 | "这个空白**为什么至今还在**？**1)** 技术不可及 **2)** 数据不可得 **3)** 概念没人提出 **4)** 做过但证据互斥" | 四选一且答得出依据；答不出=空白可能是假的，回上一节点 | 选 4 时检索验证"互斥"是否属实；选 1 时要求用户给技术可及性证据（前期数据/平台），给不出→⏸ 待补充 |
| why-now | "为什么是**现在**能解决？三年前差在哪，你现在多了什么？" | 指向具体的新技术/新数据/新概念/自有前期工作 | 主张"新技术刚出现"时查该技术首篇应用文献年份 |
| 关键科学问题 | "把它压成**一句可证伪的问题**：……这句对吗？**1)** 对 **2)** 改成……" | 单句、可证伪、能追溯到 closest_work 的某一行 | 无 |
| 指南对表（指标驱动渠道限定） | "指南列的方向/考核指标是 X，你的立意挂在哪一条上？" | 逐条对得上；对不上=立意再好也出局，回痛点节点 | 无（对表用阶段 0 已取的指南文本） |

### 分支 2 · 创新点（每条预算 ≤4 轮，2–3 条为宜）

| 节点 | 问法模板 | 好答案判据 | 检索验证策略 |
|---|---|---|---|
| 对照物 | "这条创新的**对照物是谁**？（没有对照物的'首次'不可证伪）" | 指向别人的具体工作+引文；只找得到自己团队的 → 降级为"new to me"，如实改写 | **必检**：宣称"首次/没人做过"一律查；查到反例即拿证据挑战并给出路（转多中心/上移机制层/换人群亚型） |
| 增量类型 | "增量属于哪类？**1)** 方法 **2)** 人群 **3)** 机制层次 **4)** 尺度 **5)** 裁决互斥证据" | 单选，且与 gap 归因对得上 | 无 |
| 为何以前做不到 | "别人为什么没做成这条？你凭什么做得成？" | 答案落在 gap 归因 + 自有条件（数据/平台/队列） | 无 |
| 可证伪检验 | "这条创新**用什么结果检验**？什么样的数据出来算它不成立？" | 有具体可观测的检验；答不出=口号不是创新点 | 无 |

### 分支 3 · 方案（预算 ≤6 轮）

| 节点 | 问法模板 | 好答案判据 | 检索验证策略 |
|---|---|---|---|
| 被否方案 | "为什么不是 RCT/前瞻队列/动物模型？（评审一定会问）" | 有明确排除理由（伦理/可行性/阶段不匹配），写进"被否决备选" | 无 |
| 终点硬度 | "主要终点是 X——它是替代终点还是硬终点？评审接受吗？" | 终点与科学问题匹配；替代终点有验证依据 | 替代终点的验证状态可查（如该标志物与硬结局的相关性文献） |
| 样本可及性 | "样本量大概要多少、你的中心一年能收多少？"（粗算调 clinical-stats） | 有数量级估计且可及；差一个数量级 → 挑战设计本身 | 无（算比查准） |
| Aim 依赖链 | "Aim 2 是否押在 Aim 1 成功上？Aim 1 阴性时 Aim 2 还成立吗？" | 各 Aim 可独立成立，或有明确 Plan B | 无 |
| 失效模式预演 | "closest_work 里你指出别人栽在 X——你的方案怎么不栽在同一处？" | 逐条有应对（结构上避开/写成风险+缓解）；这是评审高频砍点 | 无 |

## 二、论文包（故事线；数据已在手）

产物 = design_brief.md 论文变体（故事线卡），喂 write-paper 的引言末段/讨论/选刊与 nature-figure 的作图清单。
**前置材料**：统计输出、图表、数据描述；有草稿先跑 hollowness_check。

分支顺序：主张 → 定位 → 目标刊 → 防御。预算合计 ≤12 轮。

| 节点 | 问法模板 | 好答案判据 | 检索验证策略 |
|---|---|---|---|
| 主张梯度 | "你的数据最多撑到哪一级：**1)** 有关联 **2)** 独立关联（校正后）**3)** 可预测 **4)** 因果？我看了统计输出，建议压在 X 级，因为……" | 主张级别 ≤ 设计与统计能支撑的级别；回顾性数据用"improves/causes"一律拷问 | 无（对着统计输出判，不用查） |
| 惊喜点 | "结果里**最反直觉/最出乎你意料**的是哪个数字？" | 找得到一个（它往往就是故事核）；找不到→故事线走"填补证据空白"型 | 无 |
| 与最接近论文的差异 | brainstorm：检索后"与你最像的是这 3 篇，你的一句话差异是什么？" | 一句话说清增量（人群/方法/结局/结论方向）；说不清→警告 desk-reject 风险"换个人群做一遍不算新" | **必检**：同主题+同设计检索，直接给 write-paper 的讨论对比段备料 |
| 读者与目标刊 | "谁会引用这篇？**1)** 同专科临床医生 **2)** 方法学研究者 **3)** 政策/指南制定者" → 据此给三梯队刊。**用户已指定目标刊 → 本节点改做 scope 校验**：查该刊 aims & scope 对一遍，匹配就锁定（grill 通过），不匹配才呈证据并给三梯队候选 | 读者画像明确；目标刊 scope 对得上（防最大 desk-reject 主因） | 查候选刊 aims & scope（WebFetch），别凭印象 |
| 局限反脆弱 | "这三条局限里，**哪条会被审稿人升级成拒稿理由**？我们现在能补什么分析挡住它？" | 每条局限有偏倚方向判断+缓解（补敏感性分析/如实降级主张） | 无 |
| 反驳预演 | "我扮审稿人攻三点：……你各怎么答？"（每轮只攻一点） | 每点有可写进讨论/回复信的答案；答不上的记入开放项 | 攻击点若涉文献之争，查后再攻，别虚空树靶 |

## 三、选题包（方向已有雏形、还没过 novelty-check 时）

与 topic-selection 衔接：漏斗已收敛出 1–2 个候选后，把最心仪的一个拿来锻打；锻完指路 novelty-check。
分支顺序：动机 → 可行性 → 竞争。预算合计 ≤8 轮。

| 节点 | 问法模板 | 好答案判据 | 检索验证策略 |
|---|---|---|---|
| 动机拷问 | "这个题**为什么是你来做**？你手上有什么别人没有的？" | 指向自有资源（队列/标本/技术/临床场景） | 无 |
| 假设可证伪性 | "假设阴性时你认吗？什么结果算推翻？" | 答得出阴性判据；答不出=假设是口号 | 无 |
| 前人覆盖 | grill："你说这方向没人做透——我查一下。" | 检索后如实呈现覆盖图景 | **必检**；查到高覆盖即给转向出路（亚组/机制层/裁决互斥证据）。**同轮加注册库快查**（在研试验/SR 也算"有人在做"） |
| 竞争与时窗 | "如果 XX 大组也在做，你的差异化是什么？两年后这题还新吗？" | 有差异化或速度优势之一 | 近 2 年同方向发文趋势可查 |

## 四、通用包（任何决策的兜底；无匹配场景包时用）

来源：grill-me 的问题类型轮换，适用于实验设计、技术选型、职业/项目决策等一切"想清楚再做"。
分支顺序即下表顺序；预算合计 ≤10 轮。

| 节点 | 问法模板 | 好答案判据 |
|---|---|---|
| 范围 | "这件事的边界在哪——**不做**什么？" | 有明确排除项 |
| 前提假设 | "这个方案成立的**最脆弱前提**是什么？它错了会怎样？" | 找得出 1–2 条并有验证办法 |
| 失效模式 | "最可能失败的方式是什么？失败了损失多大？" | 有具体失效场景+量级 |
| 被否方案 | "你放弃了哪些替代方案，为什么？"（一个都没考虑过 → 先 brainstorm 出 2–3 个再回来） | 至少认真比过一个替代 |
| 成功标准 | "半年后怎么判断这事成了？给一个可观测的标准。" | 可观测、有时限 |
| 可逆性 | "走错了能回头吗？回头的成本是什么?" | 分清单向门/双向门；单向门决策提高确认门槛 |
| 资源与归属 | "谁来做、花多少、挤掉了什么?" | 有明确的人/钱/时间账 |

通用包也可检索：涉及事实性主张（"业内都这么做""X 比 Y 快"）时用 WebSearch 核一次再挑战。
