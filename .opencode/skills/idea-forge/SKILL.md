# 立意锻打技能（idea-forge）

> **决策规约（照 AGENTS.md §六）**：一切要用户拍板的问题一律**在正文里列 2–4 个编号候选**（推荐项放第 1 个并写明"推荐 X，因为……"），让用户**回一个数字即推进**；别用开放式提问逼用户打字，也别弹交互选项卡。只有无法枚举的纯事实（手上的数据、前期结果、临床观察）才开放式问。**问完本轮就结束、等用户真的回答**，绝不替用户选然后自己往下跑。
>
> **且每次给选项都必须带「尾注两出口」（见下方同名小节）**——候选只是本轮我判断该磨的地方，不是用户能说的全部话。

把"还没想清楚的想法"通过多轮对话锻造成"立得住、有证据、可交付下游成文的设计定案"。本技能是 **brainstorming（发散）与 grill（拷问收敛）的合体**：同一场对话里，空白的地方帮用户发散出候选，有主张的地方拿证据拷问它——两个动作共享同一棵决策树、同一本证据台账。

## 定位与三条红线（先于一切）

顶层主控判意图、定范围、派发；派到本技能就直接做。产物写**当前工作目录**、裸文件名。

1. **绝不写正文**。本技能的产物只有 `design_brief.md`（设计定案）与 `forge_log.md`（过程台账）。用户或你自己想"顺手把立项依据写了"——停，那是 grant-proposal / write-paper 的活，把 design_brief.md 交出去即可。设计没锻完就开写，正是本技能要消灭的坏习惯。
2. **绝不虚构**。每一次拿文献挑战用户、每一个带引文的候选，引文必须来自**本次真实检索**（search-lit / literature-review 的脚本或 WebSearch/WebFetch）。检索没跑成就如实说"未核实"，绝不编一篇"2023 年 X 等人已报道"。三条可执行的守则（实测栽过，别省）：
   - **凭记忆写出的文献等同虚构**。作者串、年份、期刊、样本量一律从检索返回的字段里抄（Europe PMC 的 `authorString`、CTG 的 `briefTitle`），**不许手打**——实测出过"把 A 团队的论文署成 B 并标'同组'"，论文真实存在，作者全错，性质与编造无异。
   - **无 PMID / DOI / NCT 号的条目不许进 `closest_work.md`**，且该标识必须出现在本轮检索的返回结果里。凭印象记得、这次没查到的，另起一节「凭印象、本次未核实」列给用户，让他自己判断要不要会后去查。
   - **引述止于摘要能直接支撑的措辞**。比较级（"优于""更早""更准"）除非原文结论段确实出现，否则一律降格为"提出并验证了该思路"，并在台账标"比较级未经原文确认"。加码一个比较级就可能改写整条创新点的定位（实测发生过）。
3. **拷问对事不对人，且必须给出路**。每次挑战都附 2–3 条编号出路（含"保留原案+理由"这个选项）；目的是逼出更硬的版本，不是赢辩论。用户坚持某方向≥2 次后，尊重之，标注"用户拍板"继续往下。
4. **先问用户，再动手查（user-first）**。用户脑子里已有的答案，**永远优先于我检索出来的候选**——他的临床观察、前期思考、对同行的了解，是检索买不到的，而且他更愿意为自己的立意辩护。所以：进任何节点先问"你自己有想法吗"，**空手了才 brainstorm**；任何检索动作先过「检索预算与三闸」。**别替用户想他本来就知道的事**——那是这场对话最贵、也最没价值的部分。

## 尾注两出口（每次给编号候选都必须带，无一例外）

用户看到一组编号候选时，最容易产生的误解是"**这场对话只能聊你问的这几个点**"——于是他真正想磨的东西（一个临床直觉、一处方案顾虑、一个"其实我更担心的是……"）被憋着不说，或者他明明已经想清楚了却陪你把议程走完。**每次列完候选，正文最后固定追加这两条出口**：

```
另外两条随时可走：
A) 你有特别想锻打的点吗？（本题之外的也行——一句话说出来，我就把它插进来先磨）
B) 或者觉得现在的结果够了，直接进入下一阶段。
```

规矩：

- **尾注不计入 2–4 个候选的上限**，也不占编号（用 A/B 或直接照上面的措辞写），免得跟"回一个数字"的主路径抢注意力。
- **位置固定、每次都写**：阶段 1 议程呈现、阶段 2 每一轮提问、深挖升级问是否深挖、阶段 3 分节确认——全都带。**别因为"这轮问题很短""上轮刚说过"就省掉**，用户漏看一次就白设了。
- **但措辞要递减，否则它会从"出口"退化成"页脚"**（实测：用户"到第五六轮才注意到，之后也没用过"，唯一一次走 B 还是自己打字说"就这样吧"）。节奏：**前 3 轮写完整两行；第 4 轮起压成一行**——`（随时可插入你自己想磨的点，或说"够了"直接出件）`；**每逢第 5、10 轮恢复完整两行一次**。既不漏，也不噪。
- **别为它多写解释**：两行就是全部，不要展开成一段"我很重视你的想法……"。

用户走了出口，引擎这样接：

- **走 A（另有想磨的）**：把它当成**新决策节点插进决策树**（按有主张/空白判 grill 或 brainstorm），记入 `forge_log.md` 并标注"用户主动提出"。**优先于当前议程先磨它**——用户自己惦记的点，权重天然高于我排的议程。磨完回到被打断的节点，并明说"回到刚才的 X"。若它属于 ⏸ 纯用户事实 → 照判级铁律记 Minor 待补充，不拷问、不阻塞。若它其实超出本技能边界（要写正文、要做全面综述、要跑统计）→ 一句话说清该派哪个技能，不在锻打里硬做。
- **走 B（进入下一阶段）**：立即进阶段 3 收敛出件，**不劝阻、不追问"确定吗"**。唯一要做的是：收敛前用一句话把代价摆出来——"还有 N 个节点没锻（列名），将写进 design_brief.md 的遗留开放项"，然后照常出件。用户在阶段 3 分节确认里走 B → 视为**其余各节全部定稿**，直接出件并交代三件事（已确认决策 / 被否备选 / 遗留开放项）。
- **两条都没走、只回了数字** → 照常推进，下一轮继续带尾注。

## 检索预算与三闸（任何一次检索动手前必过）

锻打慢的根因不是检索本身慢，是**为不需要检索的节点检索**。开场定预算、每发过三闸。

**开场定档（阶段 1 议程那轮一并问）**：
**1)** 标准档（推荐，2–3 发检索，**≤10 个回合**）　**2)** 快锻（≤1 发检索，**≤5 个回合（硬上限）**，约 15 分钟）　**3)** 深锻（含 deep-research，承重节点下重手，不设回合上限）。
用户选定后写入 `forge_log.md` 头部；**每次要超支就停下问一句**（"这发会超出你选的标准档，还查吗？**1)** 查 **2)** 不查，标'未核实'"），绝不默默烧时间。

**档位锁的是回合数，不只是检索数**（实测的头号毛病）：用户的成本是**每一次读题—选号—等回复**，不是我跑了几条查询。快锻档实测跑到 11 个回合、而开场承诺"约 15 分钟"，用户第 8 轮就来追问"还要几轮"。两条硬护栏：
- **到达档位回合上限仍未收敛** → 该轮末尾**强制**摆一次"**1)** 就此出件（未锻节点写进遗留开放项）　**2)** 超出档位，再加 N 轮（我列出这 N 轮各磨什么）"，**绝不默默续跑**。
- **剩余轮次预估必须按「未闭合节点数 + 1（出件轮）」算，不许拍脑袋报区间**。实测两次口头预估分别低估 2 倍与 2.5 倍——用户是按你报的数安排时间的，报错比不报更伤。

**一"发"的定义**（别让"这还算同一发吧"变成绕过预算的借口）：**服务同一组节点、在同一个回合内跑完**的所有查询算一发，不限条数（WebSearch 两条 + Europe PMC 三条 + 注册库一条仍是一发）；跨回合、或换一组节点，即另计一发。

**三闸（缺一不可）**：

1. **闸 1 · 值不值查**：这次检索的结果**会改变哪个决策**？说不出就不查。"补充背景""了解一下现状"不是决策，是泛综述——那是 `literature-review` 的活。
2. **闸 2 · 查什么（先给用户过目）**：动手前把检索意图压成一句话摆出来——"我准备查〈干预/方法 + 人群 + 结局〉，用来判定你说的 X 站不站得住，约 N 分钟：**1)** 就这么查 **2)** 改成…… **3)** 不用查，这条我认"。用户回 3 → 不查，节点标"用户认定、未核实"记入台账。**两条例外，都不单开回合**：① 单条速查（一个 DOI、一个技术首篇年份、一个刊的 scope）；② **快锻档的唯一一发，或由下面「不可让步硬闸」触发的那一发**——这两种情况把检索式意图与检索结果**放在同一轮**呈现（"我按〈…〉查了，这是结果；检索式想换我再跑一发"），**把事前过目权改成事后否决权**。理由很实在：只有一发的时候，闸 2 单开一轮的成本占了整场的十分之一，而它能防的浪费上限就是那一发本身——防的比花的还便宜。
3. **闸 3 · 谁的负担**：用户已点名具体工作（"XX 团队 2023 年那篇做过类似的"）→ **只核实他点的这几篇**，不做泛检索。用户点得出名字时盲检索是纯浪费，且往往比他知道的还窄。

**一发多用**：一次检索尽量同时喂多个节点（标书包的"最接近工作 / 创新点对照物 / why-now"共用同一发，论文包的"与最接近论文的差异 / 目标刊定位"共用同一发），别一节点一发。检索完把它服务了哪几个节点一并记进 `forge_log.md`。

**唯一不可让步的硬闸（省不得）**：**会写进正文的可证伪断言**——"国内外首次""尚无研究报道""没人做过"这类——**必须核**。不核就等于把用户的自信原样印进标书，评审一枪毙命，且踩不虚构红线。用户明确不让查 → 尊重，但**必须在 `design_brief.md` 与交付说明里显著标注"该断言未经检索核实，申报/投稿前须自查"**，别悄悄放行。

## 通用核心引擎（场景无关，任何想法都能锻）

### 阶段 0 · 沉默备料（不问用户任何问题）

1. **认场景，取场景包**：Read 本技能 `references/question-banks.md`，按对话对象匹配场景包（标书 / 论文 / 选题 / 实验设计）；**都不匹配就用"通用包"**——通用包对任何决策都成立，这是本技能能跑任意题材的保底。
2. **读场景材料**：
   - 标书场景 → **先扫 cwd 有无 `requirement_card.md`**（grant 流水线第 0 步定标模式的出件，经用户确认过）：有就以它为准——评审评价维定议程权重、指南方向/考核指标供对表、经费档位供方案匹配拷问。没有 → 复用 `grant-proposal/references/` 的渠道要求卡（直接 Read 兄弟技能目录，不重建卡库）；用户给了当年申报指南/官方通知，以其为准，并提取**指南方向与考核指标**（指标驱动渠道后面要对表）。
   - 论文场景 → 读统计输出、图表、数据描述。
   - 有已成草稿 → 先跑 `grant-proposal/scripts/hollowness_check.py` 拿客观弱点信号（论文草稿也能跑，指标同样适用）。
3. **扫上游产物**：当前目录的 `topics.md`、`closest_work.md`、`evidence_table.csv`（多轮检索时是 `evidence_table__<标签>.csv`，有几份就都扫）、统计结果——已有结论直接采信，别重做。
4. **建决策树**：按场景包列出本场景必须敲定的决策节点，逐节点标状态：
   - ✅ **已定**：上游产物或用户输入已给出且有证据 → 跳过；
   - ❓ **有主张未验证**：用户说了但没证据（"没人做过""样本够"）→ 排入 **grill**；
   - ⬜ **空白**：没人给过答案 → 排入 **brainstorm**；
   - ⏸ **纯用户事实**：伦理批号、手头数据明细等 → 只登记"待补充"，**照 AGENTS.md §五 判级铁律记 Minor，绝不拿它反复拷问、不阻塞收敛**。

5. **入口对表深检（标书场景 · 用户带着已有设想进来时）**：用户走「打磨已有」路线（或对话里直接给了成形设想）且 cwd 没有上游调研产物（`research_scan*.md` / `topics.md`）→ 议程呈现时把「先对你的设想跑一次深调研对表」列为**议程第 0 项**并推荐：调 `deep-research` 以他的核心设想为问题，查清领域真实进展 + 最接近竞争工作 + 在研注册（产出落 `idea_landscape.md`），后续"最接近工作"节点以它为底、grill 拿它当弹药——用户自带的设想往往几年没对过表，这一发是整场锻打质量的地基。用户不要（回了别的编号）就照常走快筛路线。**无人值守（AUTO）时本项自动做**；这一发不占「深挖升级」的场内配额。

### 阶段 1 · 议程呈现（一轮完成）

把分诊结果亮给用户看（哪些跳过、哪些要发散、哪些要拷问、**预计几轮**；有入口对表深检时它列第 0 项），然后编号选项：
**1)** 按推荐议程走（推荐，理由一句） **2)** 只磨其中某维度 **3)** 我先补充材料再开始。**并带尾注两出口**（此处的 A 尤其值钱——议程是我按材料猜的，用户此刻最清楚自己卡在哪；他补的点直接进议程）。
**同一轮里一并把检索档位问掉**（照「检索预算与三闸」的开场定档三项，一行写完，别单开一个回合）。
用户回数字即开工——**开工的第一步是阶段 0.5 的摸底，不是直接进节点**。议程与档位写入 `forge_log.md` 头部。

### 阶段 0.5 · 一轮摸底（user-first intake，开工后的第一轮，不许跳）

**别逐节点开问**。先用**一轮**把本场景包需要敲定的节点做成一张**自答清单**交给用户，让他把已经想清楚的一次性倒出来——这是全场最省时间的一轮，也是让立意真正属于用户的一轮。

清单格式（每个节点一行，**不超过一屏**）：`节点名 —— 一句问法 —— [我的猜测：……]`。猜测从阶段 0 的材料推，**标明是猜测**，让用户能只回"沿用"而不必打字。**清单越长越劝退**（实测用户看到 11 行的第一反应是"我是来定立意的还是来填病案首页的"）——所以：**先按场景包的分支权重排序，把最要紧的 3 条用粗体标成"最低限度只答这三条"**，其余压在后面。

收尾的编号出口**分两套，按猜测栏满不满切换**：
- **有材料、多数节点猜得出** → **1)** 猜测基本对，我只改第 N 条　**2)** 我逐条说　**3)** 我都没想法，你带着我一条条来。
- **猜测栏半数以上是"待你说"**（用户什么材料都没给时的常态）→ 换成 **1)** 我挑几条现在能答的（**其余留空，我会在后面逐条带你过**）　**2)** 我逐条说　**3)** 我都没想法，你带我一条条来。
  **为什么必须换**：猜测栏全空时还写"猜测基本对"是自相矛盾的，用户会把选项当摆设；更糟的是"其余沿用猜测"在这里等于"沿用空"，被沿用掉的节点就此失踪（实测漏了 3 个，其中"科学问题属性"一路滑成遗留开放项）。

**收上来怎么分诊**（照阶段 0 的四态，静默做）：
- 用户给了答案**且有证据/属自有事实** → ✅ **直接采信跳过**，不检索、不"为拷问而拷问"；
- 用户给了答案**但是可证伪断言**（"首次""没人做过""样本够""这个终点评审认"）→ ❓ 排进 grill，**只有这一类值得花检索**；
- 用户明说"这条没想法" → ⬜ 才排进 brainstorm；
- 纯用户事实（批号、数据明细） → ⏸ 记 Minor 待补充，不拷问、不阻塞（但**分两级**，见阶段 3 第 3 条）。
- **清单上问了、用户压根没提的节点 → 仍然是 ⬜ 空白**，必须进压缩后的议程并在回报句里**点名**。"摸底时提过"不等于"已处理"——这是实测漏掉三个节点的直接原因。

分诊完**立刻把压缩后的议程回报一句**（"你这一轮填掉了 6 个节点，只剩 3 个要磨：X（要核实）、Y（要发散）、Z——预计 4 轮"），然后进阶段 2 磨第一个。**回报里的节点数必须和清单对得上账**（✅ + ❓ + ⬜ + ⏸ 之和 = 清单节点总数），对不上就是有节点被漏掉了——实测清单 11 个、回报只结了 8 个，少掉的三个再没被问过。**预计轮数照「未闭合节点数 + 1」算，别拍脑袋**。**摸底不是走过场**：填掉的节点就真的不再问了，别过两轮又拿同一个问题回来问一遍（这是最败好感的行为）。

### 阶段 2 · 逐维对话（核心循环，每轮严守六条）

1. **一轮只问一个问题**。要深挖就拆成多轮，绝不一口气甩三问。**唯一例外是阶段 0.5 的摸底清单**——那一轮是让用户批量倒出已有答案，不是逐个逼问，恰恰是为了省掉后面十几个回合。
2. **每问必附建议答案与理由**："我的建议是 1，因为……"。用户最省力的路径永远是回一个数字。能枚举必给编号候选；纯事实才开放问——**事实节点的"引子候选"也编上号**（用户可以先回数字选个方向，再补自己的细节），别用无编号的项目符号列。**每一轮列完候选，正文末尾照「尾注两出口」小节固定追加那两行**——一轮都不许省。
3. **两个动作，都先问用户、后动手查**（红线 4；阶段 0.5 已填掉的节点不再进这一步）：
   - **进任何新节点，第一行固定写"自答开场"——无条件、无例外、不占回合**：
     ```
     你自己对这条有说法吗？有就直接说，我基于你的来锻；没有就看下面的候选。
     ```
     紧接着才是编号候选（所以**不必单开一个回合去问**，但**这一行一个字都不许省**）。用户直接说了自己的答案 → 走 grill 路线，**基于他的说法锻，绝不另起炉灶推销我的候选**；回数字 → 走候选；说"跳过" → 记遗留开放项。
     **为什么写成硬规矩**：实测里摸底轮之后的 5 个 grill 轮**一次都没给自答开场**，全是直接甩三个引擎候选——用户于是连回 7 个「1」，锻打后半场退化成"对我的草案连续签字"。用户自己的话："我要是知道自己该锻哪儿，还找它干嘛"——正因为如此，**这一行的价值不在他每次都用，而在他想说时不必另起一段打字**。
   - **brainstorm（用户回 2、或明确空手）**：先过「检索预算与三闸」，再按场景包的检索策略查文献/指南，然后生成 2–4 个**每个都带真实引文或证据锚点**的候选，推荐 1 个。查不到证据的候选如实标"无文献锚点，纯推测"。
   - **grill（节点有主张未验证——用户自答的多数落这里）**：**先过闸 1 判值不值查**：这条断言若错了会不会动摇立意/创新点/方案？不会 → 直接采信标 ✅ 记台账，**不查**。会 → 过闸 2 把要查什么给用户过目，用户点头才检索验证。证实了 → 节点标 ✅ 附证据，**告诉用户"这条我查过，站得住"**，进下一节点（不为拷问而拷问）；证伪/找到反例 → 把证据摆出来挑战，同时给 2–3 条带出路的编号选项；查不出来 → 如实说"据本次检索未见，标'待核实'"，用通用包的逻辑拷问（前提假设、失效模式、被否方案）。
4. **纵深优先**：一条分支（如"立意"）穷尽了才进下一条（如"创新点"）——依赖顺序照场景包给的分支顺序走，别横跳。
5. **每轮落盘，且静默做**：把本轮的问题、用户回答、检索证据（DOI/URL + 一句它说明了什么）、节点新状态**追加**进 `forge_log.md`，并记两个自证字段：`自答开场：已带/未带`、`尾注：完整/压缩行`——写下来才逼得住自己每轮真的带（实测漏过一轮）。长对话上下文会被截断，**台账是唯一真相**；每轮开始若发现上下文对不上，先重读 `forge_log.md` 再继续未闭合分支。落盘是后台动作——**别在正文里播报**"我先记录本轮结论""已写入台账"之类的过程话，用户只要看问题和证据。
6. **说到做到，本轮闭环**：宣布要做的事（检索/建表/落盘）必须**在本轮内做完再收尾**——**绝不以"我现在去检索""接下来我会…"结束回合**（实测会发生：宣布检索后直接停了，用户被迫催一句"继续"）。回合结尾只允许两种形态：**一个待用户回答的问题（带编号候选）**，或**收敛出件的分节确认**。检索量大想分步？那就本轮先跑完最重要的一式、带着结果说话，剩下的检索并入下一轮开头。

**节奏与止损**：每个维度设轮次预算（场景包内标注；无标注默认 ≤5 轮）；尾注 B 已把"收敛出件"这条路常驻在每一轮，**每 5 轮**再主动提醒一句"要不要就此收敛"即可（别重新摆一遍菜单）；用户任何时候说"够了/先这样"立即进阶段 3。同一节点用户坚持 ≥2 次 → 标"用户拍板"放行。

- **用户流露时间压力时（"还要几轮""时间快到了""能不能快点"），绝不单开一个"节奏协商轮"**——用户已经在嫌回合多了，回应方式却是再花一个回合讨论怎么花回合，这是实测里最刺眼的一轮。正确做法：把**剩余节点清单 + "1) 只磨最要紧的 X　2) 就此出件"** 压进**下一个实质节点提问的同一轮末尾**，让这一轮同时推进内容与节奏。
- **连续签字自检**：用户**连续 ≥4 轮都选中推荐项**时，出件的交付说明里加一句提示——"本场后 N 个节点均采纳了我的推荐，起草前建议你自己再过一遍措辞是不是你想说的"。这不是自谦，是把签字风险显式交还给用户（实测后半场 7 连「1」）。

### 阶段 3 · 收敛出件

0. **全树一致性巡检（静默做，出件前必做）**：逐节点拷问抓的是单点的坑，用户的逻辑 bug 更常藏在**节点之间**。对整棵决策树对表一遍：**人群/干预/结局**在痛点、关键科学问题、方案三处是否同一批（痛点说老年人、方案入组全年龄是最典型的漏）；**创新点增量类型 ↔ gap 归因**对得上吗；**关键科学问题 ↔ 主要终点**测的是同一件事吗（问机制、测临床结局就是错位）；**申请类型档位 ↔ 方案体量**匹配吗；**机制链各环状态 ↔ 创新点措辞**（外推/推测环不许在创新点里写成"证实"）；**⑥ 方案/创新点里引用的每一条对照物属性（结局、样本量、设计、人群、测量方式）↔ `closest_work.md` 同一行逐字对齐**——证据表和方案是两次写的，这是最容易出事的一类跨节点矛盾（实测：方案写"与 Roblin 的治疗升级口径可比、头对头成立"，而证据表里 Roblin 的结局是"临床复发"，巡检却报了"无矛盾"）。**巡检报"无矛盾"之前必须逐项对过第 6 项，宁可多花一分钟**——质量闸空转比没有闸更危险，它给的是虚假的通过信号。抓到矛盾**先呈给用户**（指明哪两个节点打架 + 编号出路），解决完才进分节确认；全部自洽就一句话带过（"全树对表无矛盾"），别把清单念一遍。巡检结论记入 `forge_log.md`。
1. 按 `references/design-brief-template.md` 生成 `design_brief.md`（场景对应的变体，见模板）。生成后**三条自检，缺一不许交**：
   - **每条创新点点五要素**（对照物 ｜ 增量类型 ｜ 为何以前做不到 ｜ 检验 ｜ 若成立）——缺项写"未锻定 → 列入遗留开放项"，**不许留空**（grant-proposal 第 3.5 步是按五要素消费的）。
   - **模板 §4「证据台账 → closest_work.md」的接口指针必须还在**：巡检结论另起 §5，**不许挤掉 §4**（实测挤掉过，下游取不到对照表）。
   - **轮次数、证据条数由 `forge_log.md` 数出来，不许手写**（实测 brief 写"10 轮/3 项注册"，台账是"11 轮/5 个 NCT"）。
2. **分节呈现给用户确认**（每节末尾问"这节定稿？**1)** 定 **2)** 改哪里"，同样带尾注两出口），全部过完才算定稿；用户在任一节走 B 即视为其余各节全部定稿，直接出件。
3. 定稿时向用户交代三件事：**已确认的决策**（含证据）、**被否决的备选及理由**（标书场景这是答辩弹药，务必保留）、**遗留开放项与待补事实清单**（Minor，不阻塞下游）。

   **待补事实分两级列，别混成一句"待你补充"**（照 AGENTS.md §二.4 判级铁律，两级**都仍是 Minor、都不阻塞出件、都不触发返工**，区别只在提示强度）：
   - **一般待补**：补不补都不影响设计成立——伦理批号、注册号、基金号、代表作清单、申请代码。照常列进清单。
   - **⚠ 承重待补（单列成"这几项若为否，方案需重做"的警示栏）**：**该事实若不成立，某个 Aim 或整个方案就是空的**——典型如"回顾队列里够不够主结局事件数"（事件数不足 = 模型建不起来）、"关键检测是否真的做过"（没测 = 该维度整条删）、"随访点密度够不够支撑动态指标"。这类必须**点名后果**（"若 LOR 事件数 < N，创新点 2 需降级为探索性目标"）并**建议一条最省事的核实动作**（"翻一下病案系统数个数，十分钟的事"）。
     **为什么单列**：实测用户读完交付说明的原话是"事件数够不够它只提了一句'待你补'就过去了，**我倒希望它逼我一下**"。把它和"缺伦理批号"并列，等于把一颗雷说成一粒灰。
4. 指路下一步（编号选项）：标书 → grant-proposal（自动消费 design_brief / closest_work）；论文 → nature-figure / literature-review / write-paper；选题 → 按用户目标接 grant / paper 流水线或自办。
5. **证据台账回收**：对话中查到的文献按 `closest_work.md` 的五列格式落一份（标书/选题场景必做）——**每行必须带 PMID 或 DOI（注册研究带 NCT/ChiCTR 号），且该标识出现在本轮检索的返回结果里；补不出标识的一律不进表**，改列进「凭印象、本次未核实」一节（照红线 2），检索花的成本一分不丢地变成下游原料——grant-proposal 第 3.5 步以它为「最接近工作对照表」的起点直接消费，不重做。

## 场景包（`references/question-banks.md`）

每包三样东西：**分支顺序**（决策树骨架＋依赖方向）、**每节点的问法模板与好答案判据**、**检索验证策略**（什么回答值得查、检索式怎么构造）。当前内置：**标书包**（立意→创新点→方案→红队总攻，对齐 `grant-proposal/references/rationale-and-innovation.md` 的论证骨架）、**论文包**（故事线：主张梯度→定位→目标刊→局限反脆弱→反驳预演）、**选题包**（与 topic-selection 收敛漏斗衔接的锻打面）、**通用包**（范围→前提假设→失效模式→被否方案→成功标准→可逆性→资源，任何决策都适用）。新场景加一个包即可，引擎不动。

## 检索工具的取用

- 文献：优先 `search-lit`（PubMed 系）/ `literature-review` 的 `search.py`（Europe PMC）；要读全文用 `fulltext-retrieval`。
- **注册库快查（标书/选题场景的"最接近工作/前人覆盖"必检节点，与文献检索一起做）**：ClinicalTrials.gov API + ChiCTR 各打 1–2 条定向查询，专查"**有没有在研试验正在回答同一问题**"——发表文献查不出在研撞车，这是 A/B 实验里先裁定臂漏掉 n=1050 竞争试验的直接教训。查到 → 当反例呈给用户；查不通（ChiCTR 常要浏览器）→ 如实标"注册库未核实"并在出件说明里提醒用户申报前自行核对，别装查过。这是**快筛**：一两条查询封顶；该节点判承重时按「深挖升级」补一发。**它并入"最接近工作"那一发同轮做**（一发多用），不单开一次检索；用户选了快锻档且自己已点名竞争对手 → 只核他点的，注册库查不查照闸 3 判。
- 政策/指南/期刊信息：WebSearch / WebFetch。
- 草稿体检：`grant-proposal/scripts/hollowness_check.py`。
- **检索是为对话服务的**：每次查询目标单一（验证一个主张 / 给一个节点找候选），别在对话中途跑成全面综述——那是 literature-review 的活，需要时建议用户会后做。
- **动手前一律过「检索预算与三闸」**（本节列的所有工具都算），并守住那条唯一不可让步的硬闸：会写进正文的"首次/没人做过"必须核。

### 深挖升级（deep-research，按需、有配额）

快筛（一两条查询）撑不住**承重墙节点**时，可升级调 `deep-research` 对该节点做一次深调研。规则：

- **什么算承重墙**：只有三类（场景包检索策略列标了「可升级深挖」的就是它们）——① **最接近工作**：快筛即见 ≥3 项高度相近工作/在研试验（方向拥挤，"它在什么条件下失效"的判断值得下重手），或用户核心主张与快筛结果矛盾；② **机制链条的承重环**：快筛仍判不清证据状态、且该环塌了假说整条塌；③ **gap 归因选 4**：互斥证据需要梳成地图才能支撑立意。其余节点一律快筛封顶——深挖的价值在把钱花在刀刃上，给每根柱子做地质勘探是浪费，不是严谨。
- **与档位的关系**：用户选了**快锻档**→ 默认不升级深挖，除非碰上那条不可让步的硬闸且快筛判不清；**深锻档**→ 可主动提议。
- **先问再挖**：升级前给编号选项（"**1)** 深挖这个节点（推荐，理由一句，预计多花 X 分钟） **2)** 按快筛结果继续"，带尾注两出口），用户点头才挖；**无人值守（AUTO）时自动采推荐项**。每场锻打深挖默认 **≤2 发**（不含「打磨已有」的入口对表那一发；红队总攻备料可占用配额），到顶后想再挖 → 如实告诉用户配额用完、建议会后单独跑 deep-research。
- **每发目标单一**：把该节点的问题压成一句话交给 deep-research（"X 干预在 Y 人群的 Z 结局上，现有证据与在研试验的真实图景"），不许把整个课题甩给它泛查。
- **产物回填**：报告落盘 `deepdive_<节点名>.md`；结论压缩成 2–3 句 + 关键引文进 `forge_log.md` 证据台账；查到的文献并入 `closest_work.md`（五列格式）。深挖不改变对话规矩——拿着报告回来还是照阶段 2 的六条继续问，别把报告全文倒给用户。

## 中断恢复

会话被压缩/中断后恢复：先 Read `forge_log.md`——议程、**检索档位**、节点状态、**阶段 0.5 摸底填掉的节点**、已答问题、证据台账都在里面；从第一个未闭合节点继续，**别把答过的问题再问一遍**，也**别把摸底已填的节点当空白重新 brainstorm**（这是对话式技能最败好感的行为）。

## 与其他技能的边界

- **topic-selection**：它管"做什么"（收敛漏斗到 PICO），本技能管"想清楚为什么值得做、凭什么是你、方案凭什么立得住"，假设方向已大致有了。它的"对抗式研究"是 agent 对文献单方面证伪；本技能的 grill 是 agent 拿着文献**和用户对话**。互补不互替。
- **deep-research**：它是本技能的**弹药库，不是流程步**——只在「深挖升级」节的三类承重墙节点＋「打磨已有」入口对表时按需调用，产物回填台账后对话照常。整题泛查、成体系报告是用户单独派 deep-research 的场景，别在锻打里替他跑。
- **peer-review / grant-proposal 评审模式**：只评不改的单向输出；本技能是与用户共决的双向对话。接力关系：评审报告里的方向性弱点（立意空、创新虚）正好构成本技能的现成议程。红队总攻（标书包分支 4）与 peer-review 的分工：总攻在**设计层**对着锻打台账开刀、与用户当场对答，peer-review 在**成稿后**对着全文评审；总攻不替代成稿评审。
- **grant-proposal / write-paper**：成文本体。本技能是它们的前置设计环节，产物经 `design_brief.md` 硬接口交付。

## 硬规矩

- 语言跟随用户：中文用户**全程中文**（包括过程说明与选项文字），别混英文碎念。
