# 立意锻打技能（idea-forge）

> **决策规约（照 AGENTS.md §六）**：一切要用户拍板的问题一律**在正文里列 2–4 个编号候选**（推荐项放第 1 个并写明"推荐 X，因为……"），让用户**回一个数字即推进**；别用开放式提问逼用户打字，也别弹交互选项卡。只有无法枚举的纯事实（手上的数据、前期结果、临床观察）才开放式问。**问完本轮就结束、等用户真的回答**，绝不替用户选然后自己往下跑。

把"还没想清楚的想法"通过多轮对话锻造成"立得住、有证据、可交付下游成文的设计定案"。本技能是 **brainstorming（发散）与 grill（拷问收敛）的合体**：同一场对话里，空白的地方帮用户发散出候选，有主张的地方拿证据拷问它——两个动作共享同一棵决策树、同一本证据台账。

## 定位与三条红线（先于一切）

顶层主控判意图、定范围、派发；派到本技能就直接做。产物写**当前工作目录**、裸文件名。

1. **绝不写正文**。本技能的产物只有 `design_brief.md`（设计定案）与 `forge_log.md`（过程台账）。用户或你自己想"顺手把立项依据写了"——停，那是 grant-proposal / write-paper 的活，把 design_brief.md 交出去即可。设计没锻完就开写，正是本技能要消灭的坏习惯。
2. **绝不虚构**。每一次拿文献挑战用户、每一个带引文的候选，引文必须来自**本次真实检索**（search-lit / literature-review 的脚本或 WebSearch/WebFetch）。检索没跑成就如实说"未核实"，绝不编一篇"2023 年 X 等人已报道"。
3. **拷问对事不对人，且必须给出路**。每次挑战都附 2–3 条编号出路（含"保留原案+理由"这个选项）；目的是逼出更硬的版本，不是赢辩论。用户坚持某方向≥2 次后，尊重之，标注"用户拍板"继续往下。

## 通用核心引擎（场景无关，任何想法都能锻）

### 阶段 0 · 沉默备料（不问用户任何问题）

1. **认场景，取场景包**：Read 本技能 `references/question-banks.md`，按对话对象匹配场景包（标书 / 论文 / 选题 / 实验设计）；**都不匹配就用"通用包"**——通用包对任何决策都成立，这是本技能能跑任意题材的保底。
2. **读场景材料**：
   - 标书场景 → **先扫 cwd 有无 `requirement_card.md`**（grant 流水线第 0 步定标模式的出件，经用户确认过）：有就以它为准——评审评价维定议程权重、指南方向/考核指标供对表、经费档位供方案匹配拷问。没有 → 复用 `grant-proposal/references/` 的渠道要求卡（直接 Read 兄弟技能目录，不重建卡库）；用户给了当年申报指南/官方通知，以其为准，并提取**指南方向与考核指标**（指标驱动渠道后面要对表）。
   - 论文场景 → 读统计输出、图表、数据描述。
   - 有已成草稿 → 先跑 `grant-proposal/scripts/hollowness_check.py` 拿客观弱点信号（论文草稿也能跑，指标同样适用）。
3. **扫上游产物**：当前目录的 `novelty_verdict*.md`、`topics.md`、`closest_work.md`、`evidence_table.csv`、统计结果——已有结论直接采信，别重做。
4. **建决策树**：按场景包列出本场景必须敲定的决策节点，逐节点标状态：
   - ✅ **已定**：上游产物或用户输入已给出且有证据 → 跳过；
   - ❓ **有主张未验证**：用户说了但没证据（"没人做过""样本够"）→ 排入 **grill**；
   - ⬜ **空白**：没人给过答案 → 排入 **brainstorm**；
   - ⏸ **纯用户事实**：伦理批号、手头数据明细等 → 只登记"待补充"，**照 AGENTS.md §五 判级铁律记 Minor，绝不拿它反复拷问、不阻塞收敛**。

### 阶段 1 · 议程呈现（一轮完成）

把分诊结果亮给用户看（哪些跳过、哪些要发散、哪些要拷问、预计几轮），然后编号选项：
**1)** 按推荐议程走（推荐，理由一句） **2)** 只磨其中某维度 **3)** 我先补充材料再开始。
用户回数字即开工。议程写入 `forge_log.md` 头部。

### 阶段 2 · 逐维对话（核心循环，每轮严守六条）

1. **一轮只问一个问题**。要深挖就拆成多轮，绝不一口气甩三问。
2. **每问必附建议答案与理由**："我的建议是 1，因为……"。用户最省力的路径永远是回一个数字。能枚举必给编号候选；纯事实才开放问——**事实节点的"引子候选"也编上号**（用户可以先回数字选个方向，再补自己的细节），别用无编号的项目符号列。
3. **两个动作，都先检索后开口**：
   - **brainstorm（节点空白）**：先按场景包的检索策略查文献/指南，再生成 2–4 个**每个都带真实引文或证据锚点**的候选，推荐 1 个。查不到证据的候选如实标"无文献锚点，纯推测"。
   - **grill（节点有主张未验证）**：先检索验证。证实了 → 节点标 ✅ 附证据，**告诉用户"这条我查过，站得住"**，进下一节点（不为拷问而拷问）；证伪/找到反例 → 把证据摆出来挑战，同时给 2–3 条带出路的编号选项；查不出来 → 如实说"据本次检索未见，标'待核实'"，用通用包的逻辑拷问（前提假设、失效模式、被否方案）。
4. **纵深优先**：一条分支（如"立意"）穷尽了才进下一条（如"创新点"）——依赖顺序照场景包给的分支顺序走，别横跳。
5. **每轮落盘，且静默做**：把本轮的问题、用户回答、检索证据（DOI/URL + 一句它说明了什么）、节点新状态**追加**进 `forge_log.md`。长对话上下文会被截断，**台账是唯一真相**；每轮开始若发现上下文对不上，先重读 `forge_log.md` 再继续未闭合分支。落盘是后台动作——**别在正文里播报**"我先记录本轮结论""已写入台账"之类的过程话，用户只要看问题和证据。
6. **说到做到，本轮闭环**：宣布要做的事（检索/建表/落盘）必须**在本轮内做完再收尾**——**绝不以"我现在去检索""接下来我会…"结束回合**（实测会发生：宣布检索后直接停了，用户被迫催一句"继续"）。回合结尾只允许两种形态：**一个待用户回答的问题（带编号候选）**，或**收敛出件的分节确认**。检索量大想分步？那就本轮先跑完最重要的一式、带着结果说话，剩下的检索并入下一轮开头。

**节奏与止损**：每个维度设轮次预算（场景包内标注；无标注默认 ≤5 轮）；**每 5 轮**主动给一次"**1)** 继续磨 **2)** 按现状收敛出件"；用户任何时候说"够了/先这样"立即进阶段 3。同一节点用户坚持 ≥2 次 → 标"用户拍板"放行。

### 阶段 3 · 收敛出件

1. 按 `references/design-brief-template.md` 生成 `design_brief.md`（场景对应的变体，见模板）。
2. **分节呈现给用户确认**（每节末尾问"这节定稿？**1)** 定 **2)** 改哪里"），全部过完才算定稿。
3. 定稿时向用户交代三件事：**已确认的决策**（含证据）、**被否决的备选及理由**（标书场景这是答辩弹药，务必保留）、**遗留开放项与待补事实清单**（Minor，不阻塞下游）。
4. **裁定过期护栏**：出件前查 cwd 有无 `novelty_verdict*.md`——有、且定稿的科学问题相对它已**转向**（换人群/换干预/换主结局/换机制层）→ 在出件说明里**显式标注"该裁定已过期，须对新问题重跑 novelty-check"**，绝不让下游拿旧裁定背书新问题（旧注册库结论对新问题不成立，撞车风险恰恰藏在这——A/B 实验实测过）。
5. 指路下一步（编号选项）：**标书 → novelty-check**（对定稿科学问题做严格裁定+预注册锁；已有裁定且未转向可跳）→ grant-proposal（自动消费 design_brief / closest_work / novelty_verdict）；论文 → （新颖性主张要紧时先 novelty-check）→ nature-figure / literature-review / write-paper；选题 → novelty-check。
6. **证据台账回收**：对话中查到的文献按 `closest_work.md` 的五列格式落一份（标书/选题场景必做），检索花的成本一分不丢地变成下游原料——novelty-check 会以它为最接近文献表的起点补严，不重做。

## 场景包（`references/question-banks.md`）

每包三样东西：**分支顺序**（决策树骨架＋依赖方向）、**每节点的问法模板与好答案判据**、**检索验证策略**（什么回答值得查、检索式怎么构造）。当前内置：**标书包**（立意→创新点→方案，对齐 `grant-proposal/references/rationale-and-innovation.md` 的论证骨架）、**论文包**（故事线：主张梯度→定位→目标刊→局限反脆弱→反驳预演）、**选题包**（与 topic-selection 收敛漏斗衔接的锻打面）、**通用包**（范围→前提假设→失效模式→被否方案→成功标准→可逆性→资源，任何决策都适用）。新场景加一个包即可，引擎不动。

## 检索工具的取用

- 文献：优先 `search-lit`（PubMed 系）/ `literature-review` 的 `search.py`（Europe PMC）；要读全文用 `fulltext-retrieval`。
- **注册库快查（标书/选题场景的"最接近工作/前人覆盖"必检节点，与文献检索一起做）**：ClinicalTrials.gov API + ChiCTR 各打 1–2 条定向查询，专查"**有没有在研试验正在回答同一问题**"——发表文献查不出在研撞车，这是 A/B 实验里先裁定臂漏掉 n=1050 竞争试验的直接教训。查到 → 当反例呈给用户；查不通（ChiCTR 常要浏览器）→ 如实标"注册库未核实，留给 novelty-check 补全"，别装查过。这是**快筛**：一两条查询封顶，严格全查是 novelty-check 的活。
- 政策/指南/期刊信息：WebSearch / WebFetch。
- 草稿体检：`grant-proposal/scripts/hollowness_check.py`。
- **检索是为对话服务的**：每次查询目标单一（验证一个主张 / 给一个节点找候选），别在对话中途跑成全面综述——那是 literature-review 的活，需要时建议用户会后做。

## 中断恢复

会话被压缩/中断后恢复：先 Read `forge_log.md`——议程、节点状态、已答问题、证据台账都在里面；从第一个未闭合节点继续，**别把答过的问题再问一遍**（这是对话式技能最败好感的行为）。

## 与其他技能的边界

- **topic-selection**：它管"做什么"（收敛漏斗到 PICO），本技能管"想清楚为什么值得做、凭什么是你、方案凭什么立得住"，假设方向已大致有了。它的"对抗式研究"是 agent 对文献单方面证伪；本技能的 grill 是 agent 拿着文献**和用户对话**。互补不互替。
- **novelty-check**：严格裁定+预注册锁。**标准顺序是本技能在前、它在后**（A/B 实验定的）：本技能的快筛负责早杀与定向，它对锻打**定稿**的科学问题做一次严格裁定（以 `closest_work.md` 为起点补严，不重做）并锁预注册。上游已有 verdict（用户先跑了它、或旧会话带来）→ 照阶段 0 消费；但科学问题在锻打中转向后旧 verdict 即过期，出件时按阶段 3 护栏提示重跑。
- **peer-review / grant-proposal 评审模式**：只评不改的单向输出；本技能是与用户共决的双向对话。接力关系：评审报告里的方向性弱点（立意空、创新虚）正好构成本技能的现成议程。
- **grant-proposal / write-paper**：成文本体。本技能是它们的前置设计环节，产物经 `design_brief.md` 硬接口交付。

## 硬规矩

- 语言跟随用户：中文用户**全程中文**（包括过程说明与选项文字），别混英文碎念。
- 每轮回复克制：问题一针见血，一轮正文尽量 ≤300 字（引证据可放宽），别把思考过程倒给用户。
- 不虚构（红线 2）；判级铁律（⏸ 节点一律 Minor）；不替用户拍板（§六）。
- 产物：`forge_log.md`（每轮更新）、`design_brief.md`（收敛出件）、`closest_work.md`（标书/选题场景）。均写当前工作目录、裸文件名。
