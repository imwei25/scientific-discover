# 基金标书技能

> **决策规约（照 AGENTS.md §六）**：本技能任何要用户拍板的抉择——渠道 / 类别 / 方案 / 下一步等——一律**在正文里列 2–4 个编号候选**（推荐项放第 1 个并写明"推荐 X，因为……"），让用户**回一个数字即推进**；**别用开放式提问逼用户打字，也别弹交互选项卡（如 AskUserQuestion）**。只有无法枚举的纯事实（手上的数据文件、伦理批号、代表作清单等）才开放式问。

帮用户把课题写成有说服力、结构完整的标书。**内容基于用户提供的真实课题与前期工作，不编造数据、成果或报价。**

## 定位（本技能在套件中的位置）
顶层主控判意图、定范围、派发；派到本技能就**直接做，别回绕**。本技能是 grant 流水线的正文起草环节；单独直呼（已有明确课题+前期工作、只要起草/润色）也直接做。产物直接写**当前工作目录**、用裸文件名（如 `proposal.md`），别拼 `outputs/…` 前缀，也别写仓库根。

## ⚠️ AI 使用合规红线（必读，先于一切）
- **NSFC（2026 通告原文，可追责）**："不得使用由生成式人工智能直接生成的申请书，不得使用未经核实的生成内容"；借助 AI 整理文献须人工核实并**如实声明、按《人工智能生成合成内容标识办法》标识**。
- **NIH（NOT-OD-25-132，2025-09 起）**：实质由 AI 生成的申请不视为 original idea（NIH 用检测技术识别）；每 PI 每财年 ≤6 份。
- **本技能的产出定位是"供申请人实质性重写的草稿框架与思路"，不是可直接提交的成稿；申请人须对全部内容负责、亲自改写。生成时主动向用户重申这一点**（NSFC 渠道还须提醒标识义务）。

## 定标模式（grant 流水线第 0 步：查标的要求并让用户确认，不起草）

主控在完整 grant 流水线里**最先**派本模式；用户单独说"帮我查 XX 基金今年的申报要求 / 看看该按哪份文件写"也走它。**产出只有一份 `requirement_card.md`，落盘即停**——选题、锻打、起草都在后面的步骤，别顺手往下做。

1. **定渠道**：工作台表单已带渠道（`funder`）就直接用；没有 → 照第 1 步的表列编号选项问，**问完本轮结束**。
2. **扫用户材料**：用户已上传申报通知/模板/指南（或表单"撰写要求"栏填了内容）→ 按第 2 步摄入，**视同已确认**，直接跳到第 5 小步落卡。
3. **没有材料 → 联网查当年文件（内置渠道也要查）**：内置卡管的是结构骨架，**当年通知才管得住改版、限项变化、指南方向**。用 WebSearch/WebFetch 检索"<渠道> <当年> 申报通知/项目指南/申请书模板"，来源优先级照第 1.5 步②（主办机构官网/申报平台 > 依托单位科研处转载 > 商业平台二手）。联网不可用 → 如实说明，按内置卡落卡并显著标注"未经当年通知核实"。
4. **确认闸（查到了必须让用户拍板，绝不自行认定）**：把查到的候选文件编号列出，每条给「文件名 / 发布机构 / 年份 / URL / 一句它是什么」，推荐项放 1：如 "**1)** 《XX 省 2026 年度省自然科学基金项目申报通知》（XX 省科技厅官网，2026-02，推荐：年份与渠道都对上）　**2)** 《…》　**3)** 都不是，我自己上传文件　**4)** 先按内置卡走，不等通知"。**问完本轮结束等用户回数字**。查到的年份对不上/只有去年的 → 如实说，把"去年版"作为候选之一并标明风险。**无人值守（AUTO）时不等确认**：选最可信的官方来源落卡，卡头显著标注"自动选定、未经用户确认，正式申报前须核对"。
5. **落 `requirement_card.md`**（全流水线公共输入，五节）：①渠道与类别、文体家族；②结构提纲（内置渠道写"指针 → references/<卡>.md"+当年通知的增量差异，表外渠道照第 1.5 步③的临时卡结构写全）；③字数/页数硬限与格式硬规定；④**评审评价维 + 指南方向/考核指标**（供 research-scan 限定范围、topic-selection 打 funder-fit、idea-forge 定议程权重与指南对表）；⑤弃标硬闸结论（资格/限项/截止，照第 1.8 步硬闸扫一遍）+ 口径年份与来源 URL + 经用户确认与否。
6. **收尾**：报告卡已落盘、列待补事实（Minor），指路下一步（编号选项）："**1)** 进 research-scan 扫方向（推荐，从零开始）　**2)** 已有大致想法，直接进 idea-forge 锻立意　**3)** 课题已明确，直接起草"。

## 工作流程（五步，均按要求卡驱动）

> 以下五步是**起草模式**（从课题到成稿）。用户**已有成稿、只想评审**现有标书时，走文末「评审模式」——只判该渠道评审会怎么看、给改进意见，不重写。**当前目录已有 `requirement_card.md`（定标模式落的）→ 第 1 步不再问渠道、以卡为准直接往下**；第 2/3 步照跑（用户后补的官方文件仍以文件为准；定标时已核实过当年口径的，动态核实闸标注"已于定标时核实"即可不重查）。
>
> ⚠️ **别把这条流程读成"合规检查表"**：第 1–3 步解决"写给谁、写多长、什么格式"，**第 3.5 步才解决"写什么"**。
> 格式全对、字数全合、形审全过，但立项依据是文献罗列、创新点没有对照物——这样的稿子照样出局，而且是最常见的出局方式。
> **第 3.5 步与第 5 步的空洞度闸不许跳过**，它们和字数硬限一样是硬要求。

### 第 1 步 · 定渠道，加载要求卡
按编号选项问清申请渠道与类别，**问完本轮就结束、等用户回答**；拿到答复后的下一轮再 **Read 对应要求卡**（本技能目录 `references/` 下）：

| **NSFC 医学类（申请代码 H）** | 上面的 NSFC 卡 **＋ `references/nsfc-medical-h.md`**（代码表 H01–H35、分流规则、伦理硬附件、人遗资源、当年临床专项） | 科学问题驱动 |

**三张公共卡（不是渠道卡，叠加读）**：
- **每份标书都读** → `references/rationale-and-innovation.md`：**立项依据论证骨架 + 创新点构造卡**。渠道卡决定"写成什么样子"，这张卡决定"写出什么内容"。**空洞、罗列文献、创新点站不住，根因都在这张卡没落实**——第 3.5 步整步就是执行它。
- **涉及人（含已有样本/数据的回顾性研究）** → `references/ethics-review.md`：法定送审材料 11 项、知情同意 12 要素、免除审查四情形，以及各渠道申报阶段要什么伦理件。**NSFC 医学/生命科学部缺伦理审核证明直接不予资助**，起草时就要提醒用户倒排送审时间（院内预审窗口常早于基金截止一个月）。
- **临床研究（干预性或观察性）** → `references/clinical-registration.md`：ChiCTR / ClinicalTrials.gov / ICMJE 三种注册时机口径不同（别混写），以及方案按 SPIRIT 2025（34 项）/ PRISMA-P 2015（17 项）写。

同时问清（能枚举的列编号选项）：拟申请经费强度与年限、学部与申请代码（NSFC）、课题方向与核心假设、前期工作/预实验/代表作（事实性，开放式要）。

### 第 1.5 步 · 未内置渠道：先把要求查清，再动笔（**不许凭常识硬写**）
渠道不在上表、或用户申请的类别本卡未覆盖时，**先补齐要求，不要直接起草**——各渠道的结构提纲、字数硬限、匿名/在线生成等硬规矩差异极大，凭通识写出来的稿子往往整篇作废。按下列优先级取要求：

**① 先问用户要官方文件**（最可靠、最省事）：一句话问"手上有本渠道当年的申报通知/申请书模板吗（Word/PDF 都行）"。有 → 直接走第 2 步指南摄入，**不必联网调研**。

**② 用户没有 → 联网调研。先判运行时能力，再定并行/串行**（同 `deep-research` §编排决策）：
- 当前环境**有子代理/任务派发类工具**（Task / spawn / 子代理）→ 派 **1 个**调研子代理；若该渠道还牵涉伦理审查、临床注册等独立议题，最多派 **2–3 个**分头查，各给明确边界。
- **没有该类工具、或拿不准** → **一律串行**，主流程自己用 web 搜索/抓取（或 `.venv` 的 requests/beautifulsoup4）顺序查完。**"能并发调工具"≠"能开子代理"。**
- 联网也不可用 → 跳到 ③。

**给调研子代理的任务书必须写清**（别只说"查 X 基金的要求"）：
- **要什么**：① 申请书结构提纲（**章节标题原文**）② 字数/页数硬限（逐节）③ 格式规定（字体字号行距边距、是否系统在线生成）④ 形式审查/附件清单（伦理件、限项、盖章、代表作数量）⑤ 申报截止与平台入口 ⑥ 评审要点或打分权重（若公开）。
- **来源优先级**：主办机构官网/申报平台公告 > 依托单位（高校/医院）科研处转载的模板与通知 > 商业平台（LetPub、募格等）二手汇总。**结构提纲必须来自官方或转载原文，不接受博客式概括**。
- **交付格式**：每条给 文档名 / 发布机构 / 年份 / URL / 关键条目摘要；标注一手 vs 二手；**找不到的明确写"未找到官方来源"，不许用常识补**。

**③ 调研结果落成"临时要求卡"**，写到当前工作目录（裸文件名，如 `要求卡-XX基金.md`），**按内置卡同一五节结构**：结构提纲原文｜字数/页数硬限｜格式硬规定｜形式审查清单｜动态核实项（附 URL 与年份）。卡头必须写明 **"网络调研生成，未经官方模板校验；提交前须以申报系统内当年模板为准"**，并列出哪几项没查到（写"未找到官方来源"，起草时对应部分标 `[待补充]`，别自己发挥）。
- 关键硬限（字数/页数/截止/限项）**至少 1 个官方来源或 2 个独立二手来源**才写进卡；只有单一二手来源的标"待核实"。
- 什么都没查到 → 用**最近似文体家族**的内置卡起草（见上表家族列），并在产出顶部显著声明"结构按 XX 卡类推，非本渠道官方要求，提交前必须按官方模板重排"。

**④ 沉淀**：临时卡只存在于本次会话产物目录；**容器内 `/app` 下的技能目录重建即失效，别往那写**。若卡质量不错，交付时提示用户"可把这张卡交给维护者内置到 `references/`，下次免调研"。

### 第 1.8 步 · 起草前弃标闸（go/no-go，先判该不该投再动笔）
选定渠道 ≠ 该投。动笔前过一遍匹配度，把"写完才发现资格不符/严重不匹配"挡在前面。**两段式**：
1. **硬闸（任一不过 = 直接劝退换渠道，不进打分）**：截止时间来得及？资格门槛（年龄/职称/学位/单位性质）符合？限项不冲突？研究方向属该渠道受理范围（NSFC 代码分流、中医药十处准入等）？——多数能从卡的形审/限项节直接判。
2. **funder-fit 七维快评（硬闸过了才打，粗评即可，别搞成繁琐问卷）**：topic 方向｜mechanism 资助的工作类型（基础/转化/临床）｜stage 研究阶段｜geographic 地域限制｜team 团队资质匹配｜budget 经费档位｜competitive 中标率，每维 0（不符）/1（勉强）/2（契合），满分 14。
   - 判定（照 AGENTS.md §六 给编号选项）：**≥11 → 直接起草**；**≤5 → 建议换渠道**并列 1–2 个更匹配候选；**6–10 → 停下**告知"哪几维弱、能否补强或换渠道"，用户回数字定夺。
- competitive 等需渠道数据的维，缺则第 3 步动态核实时取、或按 1 计。**闸只出信号、不替用户拍板**——投不投是用户的方向性决策，闸只把不匹配提前摆上台面。用户已铁心要投且资格明显无碍 → 硬闸扫一眼即可、七维可略。

### 第 2 步 · 指南摄入（用户有官方文件时，其优先级高于要求卡）
很多渠道的模板锁在申报平台内（省基金/卫健委尤甚），**主动请用户提供当年官方模板、申报通知或指南文件**（Word/PDF 皆可）。拿到后：
1. 通读提取：结构提纲（章节标题原文）、字数/页数硬限、格式规定、形式审查/附件要求、截止时间。
2. 与内置要求卡 **diff**：有出入处一律**以用户文件为准**，并把差异点列给用户看（这也是发现"今年又改版了"的机会）。
3. 据此生成本次起草用的"对照清单"（结构 + 硬限 + 自查项），后续各步都对着它写。
用户没有文件时：用内置卡，并在产出显著位置标注"结构按 20XX 年口径要求卡，提交前请以当年官方模板核对"。

### 第 3 步 · 动态核实闸
每张卡末节列有"动态核实项"（限项、截止期、提纲是否改版、salary cap、FORMS 版本等每年会变的数字）。**联网可用时逐项 WebFetch 卡内官方 URL 核实**，有变化就按新口径写并告知用户；联网不可用时不猜——按卡内口径写，逐项标注"基于 20XX 年口径，请核对当年规定"。**不要把可能过期的数字当铁律写进标书。**

### 第 3.5 步 · 论证内核（**动笔前必做，别跳**）

前三步解决的是"写给谁、写多长、什么格式"；**这一步解决"写什么"**。跳过它，立项依据必然退化成
"A 报道了…B 发现了…然而机制尚不清楚，亟待进一步阐明"——每句都没错，评审读完却不知道
**哪一步卡住、为什么至今没解决、你凭什么能解决**。这是标书最常见的死法，也是本技能一度最弱的一环。

**⓪ 先看有没有现成的设计定案**：扫当前工作目录有无 `design_brief.md`（idea-forge 立意锻打对话的出件，标书变体含立意卡/创新点五要素/方案骨架/证据台账，通常还伴随 `closest_work.md`）——**有就直接映射成本步四件套，跳过下面 1–4 的自行推导**（用户与 idea-forge 逐节确认过的结论，别再翻案；只补映射时发现的明显缺口）。**没有**且用户在线 → 照 §六 给编号选项："**1)** 先进 `idea-forge` 用多轮对话把立意/创新点/方案锻硬再写（推荐，标书空洞的根因就是这步没做过）　**2)** 快速通道：我按下面 1–4 自行检索推导（快，但吃不到你的临床观察与未写出的前期思考）"。用户回 2、或无人值守场景，才走下面四个动作。

**先 Read `references/rationale-and-innovation.md`**，然后按它跑完四个动作，**产出物齐了才进第 4 步**：

1. **读上游产物**（该卡 §1）：扫当前工作目录有无 `novelty_verdict*.md`（novelty-check）、`research_scan.md`（research-scan）、`topic_selection*.md`、`evidence_table.csv`（多轮检索时另有 `evidence_table__<标签>.csv`）/ 综述稿——有就直接映射，别重做泛综述。**一个都没有**（用户直呼本技能、跳过了上游）→ 用 `literature-review` 的 `search.py` 或 `search-lit` 做**针对性检索**，目标只有一个：找出与本课题**最接近的 3–5 项工作**并读到能说清其失效条件（必要时 `fulltext-retrieval` 取全文）。检索式围绕**你的科学问题**构造，不是围绕疾病名——查疾病名只会捞回一万篇背景。
2. **建「最接近工作对照表」**（该卡 §2）→ 写 `closest_work.md`，≤5 行：`最接近工作(引文) | 它回答了什么 | 具体局限 | 本课题的增量 | 该增量为何以前做不到`。局限要按**八类失配**（人群/终点/时间尺度/机制层次/测量/设计/规模/一致性）具体到设计参数，**不接受"研究较少""不够深入"**。**没有这张表不许写创新点。**
3. **gap 归因四选一**（该卡 §3）：这个空白**为什么至今还在**——技术不可及 / 数据不可得 / 概念未提出 / 做过但证据互斥。这一问就是用户说的"深入分析"之所在，且**归因直接决定创新点类型与可行性怎么论**。答不出来 = 空白要么是假的、要么不值得做。归因①而拿不出技术可及性证据（前期数据/平台）→ 按 §六 给编号选项停下问用户，别硬写。
4. **锁一句可证伪的关键科学问题**（该卡 §4）：从上面的局限 + 归因**收敛**出来，单句、可证伪、能追溯到对照表的某一行。放哪按渠道分（2026 新格式写进「研究内容」开头 + 摘要；classic 类别单列进「拟解决的关键科学问题」栏；NIH 放 Specific Aims 首段；指标驱动渠道换成"关键技术瓶颈 + 考核指标"）。

**缺用户输入时**（该卡 §8）：深入分析吃两样用户独有的东西——真实临床观察与前期数据。**能枚举的用编号选项问**（如"你觉得这个空白至今还在，主因是哪一类？1) 缺测量手段 2) 缺样本数据 3) 没人这么设想过 4) 结论互相打架"），比"请介绍研究背景"有用得多；纯事实项开放式要，缺则标 `[待补充]`——照 AGENTS.md §五 判级铁律，**这属 Minor，不阻断交付、不触发返工**。**绝不用编造填补**（编前期数据、编"最接近工作"、编检索结论都踩不虚构红线）。

### 第 4 步 · 按卡起草
- **结构**：严格按卡（或摄入的对照清单）的章节标题与顺序写，NSFC 类"勿删改提纲标题及括号文字"。
- **硬限**：逐节字数/页数按卡执行（博后 500–2000 字/节、浙江省 ≤8000 字、NIH Aims 1 页等）。**写完必须逐节实际数一遍**（写个小脚本切分统计，别目测）。**留余量**：用户后续填入真实细节（刊名卷期、批号、纳排细则）字数会涨，起草时写到硬限的 70–85% 为宜。
- **⚠️ 中文字数计数口径（最易错，实测栽过）**：算 **字符数**——**汉字、数字、英文字母、全角/半角标点全都算 1 个**；只排除空白与 Markdown 标记。**不要只数汉字**：一段含 `2019–2024`、`386 例`、`18.3% vs 7.9%`、`P=0.008` 的摘要，只数汉字会比真实字符数少 30–60 字，看着"353/400 有余量"实则已 411 超限。规范写法：
  ```python
  # 只剥 Markdown 语法符与空白；**别剥连字符 '-'**——正文里的连接号/范围号(如 2019-2024)是内容、算 1 字，
  # 剥掉会低估字数、造成"看着有余量实则超限"。故字符集不含 '-'。
  import re; n = len(re.sub(r'[\s*#>`|\[\]]', '', text))   # 这就是要与限额比的数
  ```
- **缺材料的字段一律标 `[待补充]`**：卡里说"某节允许出现某信息"（如博后研究基础节允许写单位/导师）不等于要求你填——用户没给的事实（单位全称、导师姓名、伦理批号、刊名卷期）**只占位、不编造、不起化名**，并在交付时列成"需你补的事实项"清单。
- **特殊开关**：博后基金正文匿名化（除研究基础节外零身份信息）；重点研发的考核指标表（立项/中期/完成三栏）；学会临床基金调 `clinical-stats` 做样本量。
- **立项依据按五段骨架落笔**（详见 `references/rationale-and-innovation.md` §5，第 3.5 步的产物直接喂进来）。括号里是**立项依据内部**的字数占比：
  1. **痛点事实（10–15%）**——具体决策点卡在哪、只能采取什么次优做法、代价是什么（可量化）。**不写**"发病率逐年上升，严重威胁人类健康"（对任何疾病都成立 = 零信息量）。引用 ≤3 条。
  2. **现有解法的失效分析（35–40%，主体）**——`closest_work.md` 逐行展开：每项工作"做了什么"+"在什么条件下失效、为什么"，段末给出 gap 归因。**全文 ≥60% 的引用集中在这一段**。
  3. **关键科学问题（≤5%）**——第 3.5 步锁的那句，单独成段。
  4. **切入点与假说（25–30%）**——假说是什么、**为什么它能绕开第 2 段的失效点**（机制上的理由）、可推出哪些可观测预测。**技术本身不是切入点**：NSFC 医学部原话"避免无创新性思想而盲目追求使用高新技术和跟踪热点问题"，写高新技术必须说明它使能了什么此前不可及的观测。
  5. **价值锚（10%）**——若成立会把**哪个具体决策/认知**从什么状态变成什么状态。**不写**"具有重要的科学意义和应用价值""为临床提供理论依据""造福广大患者"。
  > 不设笔墨预算时，第 2 段会缩成 5% 的"然而尚不清楚"、背景铺陈膨胀到 60%——这就是空洞的字面成因。写完用第 5 步的脚本 `--sections` 核对实际分布。
- **创新点按五要素写**（该卡 §6）：`断言 + 对照物(别人的工作+引文) + 增量类型(方法/人群/机制层次/尺度/裁决，单选) + 为何以前做不到(对应 gap 归因) + 可证伪的检验 + 若成立的后果`。**无对照物时禁用**"首次/填补空白/创新性地采用/国际领先/突破性"——离开对照物它们是不可证伪的断言，评审一眼看穿。只找得到自己团队的工作作对照 = **new to me 不是 new to field**，降级写成"本团队首次将…"并如实说明领域内已有 X。条数 **2–3 条为宜**，列 5 条以上通常意味着每条都不够硬；每条都要能追溯到 `closest_work.md` 的某一行。
  ⚠️ **凝练 ≠ 把没做的写成已做**：命题与创新点本身可以斩钉截铁，但支撑它的未核实前提（如"病理分期在两组间无差异"这类尚未做统计检验的断言）仍须标 `[待补充]`，新颖性断言仍带"据本次检索"等 hedge——别为了句子利落就把没做的统计写成已证实、把个人首次说成领域首创，那踩"不虚构"红线。
- **写作要点（跨渠道通用）**：逻辑链闭环（问题→假说→目标→内容→方案一一对应）；可行性用用户给的真实前期数据支撑；关键论断引真实文献（配合 `search-lit` / `fulltext-retrieval`）。**反模式对照表见该卡 §7**（八种最常见的空洞句式 → 该改成什么），落笔前扫一眼。
- **按卡的"评审评价维"分配笔墨**：起草不是均匀铺开——把重心压到本渠道评审最看重的维度（见卡内"评审在乎什么"节）：NSFC 面上重**科学问题凝练 + 创新性**、重点研发重**可考核指标**、学会临床基金重**方案可落地**。是写给这个渠道评审的心智模型，不是写一份"通用好标书"。卡未列评价维时，回落到"科学问题是否值得做 + 与现有工作比新在哪 + 可行性是否有前期数据撑住"。
- **正文只写面向评审的正式内容（正文洁净度，起草时就守住）**：绝不在正文出现技能名/工具名（`search-lit`/`reference-check`/`data-analysis` 等）；绝不把方括号编辑批注、或"解释自己写得好"的元评论（如"这是具体可衡量而非泛化造福患者的表述""这也是本渠道优选特征"）混进面向评审的叙述句——这类提示一律放到正文之外的"[待补充]清单"或给用户的说明里。评审读到会当成没清理干净的草稿而扣分。
- **预算**：按卡内该渠道的科目与规则编制（NSFC 三大科目或包干、NIH modular/detailed、重点研发分单位），每条挂到具体研究内容/Aim、写测算依据（单价×数量、人月×费率），别只给总额。
- 草稿写 `proposal.md`（当前工作目录，裸文件名）。

### 第 5 步 · 按卡自查 + 空洞度闸 + 排版衔接
- **① 空洞度闸（起草完必跑，形式审查之前）**——形式合规不等于内容不空，旧版本正是只查前者才让空洞稿一路通关：
  ```bash
  "${REPO_ROOT:-/app}/.venv/bin/python" <本技能目录>/scripts/hollowness_check.py proposal.md --sections
  ```
  查五项：**空话词密度｜引文承载率（最硬的一条：引用是否落在失效点语境）｜段落落点率｜创新点对照率｜无引用强断言**，`--sections` 附章节字数占比用于核对笔墨预算；只体检某一节用 `--section 立项依据`。
  **signal not verdict**：脚本查的是论证的**形状**不是对错，命中项要回读原文确认（正常背景引用也可能被点名）。不达标 → **回 `references/rationale-and-innovation.md` 对应节重写论证**，别只替换词面——把"亟待阐明"换成"尚需探索"过不了引文承载率这一关。**同一项连续两轮仍不过 → 停下找用户**（多半是缺真实前期数据或临床观察，照 §六 给编号选项要），别无限自我返工。
- **② 交付前自评审（一轮，起草模式也要做）**——用文末「评审模式」的评价维把自己的稿子过一遍，重点三问：科学问题是否收敛成 1 个可检验命题？创新是否写清了**相对别人的增量**？意义是否**具体可衡量**？发现硬伤自行返工一次，并把自评结论随稿附给用户（写成"若送到该渠道函评，最可能被质疑的是…"）。
- **③ 自查清单不用通用版**——用所选卡的"形式审查/自查清单"节 + 摄入文件的要求生成本次专属清单，逐条勾给用户看；再叠加下方"跨渠道通用自查"。
- **格式硬规定下传排版层**：常见渠道已固化成预设，出 Word 时直接 `render-docx --journal most-key-rd`（重点研发：标题黑体四号/正文宋体小四/1.5 倍行距）/ `municipal-sci`（市科局）/ `nih-forms-i`（NIH 11pt Arial+0.5" 边距）/ `hospital-fund`（院内），标题/正文双字体双字号由预设的 `PRESET_HEADING_CJKFONT/FONTSIZE` 落盘（也可手传 `--heading-cjk-font 黑体 --heading-fontsize 14`）；有渠道官方 Word 模板则 `--ref` 更权威。预设外的渠道按其 reference 手传页面参数。注意：标题双字体仅 docx 侧生效，`render-pdf-doc` 忽略之；博后/NSFC 等"系统在线生成"渠道则产出各节文字供用户粘贴，说明白**不出最终申请书文件**。
- 引用真实性：稿中**含具体文献引用**（作者/期刊/DOI）时定稿前跑 `reference-check`；正文只有泛化表述、未落具体引用时**跳过并说明**"本稿未含可查引用，后续补引用后需补跑"——别为了走流程凭空补引用。

## 跨渠道通用自查（叠加在卡清单之后）
- [ ] **`closest_work.md` 存在且 ≤5 行**，每行的"具体局限"落到设计参数（人群构成/终点/样本量/测量精度/机制层次），不是"研究较少""不够深入"。
- [ ] **gap 归因已写出**（技术不可及/数据不可得/概念未提出/证据互斥），且创新点类型与它对得上。
- [ ] **空洞度闸五项已跑**，未达标项已重写论证（不是换词），或已如实说明为何保留。
- [ ] **立项依据笔墨分布**大致落在 15/40/5/30/10，失效分析是主体而非背景铺陈。
- [ ] 逻辑闭环：问题→假说→目标→内容→方案一一对应，无断裂。
- [ ] 创新点每条五要素齐（断言+对照物+增量类型+为何以前做不到+可证伪检验+后果），且分清**"领域没做过"而非"我没做过"**（new to field ≠ new to me）——别把个人首次当领域首创。
- [ ] **失效点已回流成自己的风险清单**：`closest_work.md`「具体局限」那一列**逐条**都回答了"我怎么不栽在同一处"（结构上避开 / 写成风险并给缓解）。**盲评实测的高频失分点**——指出了别人的多中心设备差异，自己却零应对，可行性一维当场被扣。
- [ ] **主动写了风险与缓解**（立项依据/可行性/研究方案里）——评审知道研究一定有风险，回避风险反而显得天真、不成熟。
- [ ] **预测模型 / 诊断准确性 / 干预类研究给了样本量或事件数依据**（调 `clinical-stats`），并识别了本设计特有的偏倚（如金标准只在部分人群取得 = 部分验证偏倚）。骨架把注意力拉向论证时，这类"设计必答项"最容易整块蒸发。
- [ ] **指标驱动渠道（重点研发 / 四大慢病）另加两查**：① 考核指标**逐条**点名应答，一条不漏（含"操作人员培训时长""现场例数"这类容易被无视的软指标）；② **分解数字相加要对得上指标线**——各分项成本/耗时之和不得越过总指标（实测出现过分项 85+50=135 元、指标线却是 ≤120 元的自相矛盾）。
- [ ] 可行性有前期数据/预实验/团队条件支撑（真实材料）。
- [ ] 限项/在研冲突已提示用户核对；伦理与合规件（涉人/动物/人遗）已提示。
- [ ] 政策类硬数字均已核实当年口径或标注口径年份。
- [ ] **无虚构**：预实验数据、发表记录、合作单位、预算报价均真实或标"待补充"。
- [ ] AI 合规已向用户重申（见顶部红线；NSFC 另提标识义务）。
- [ ] **正文洁净**：无技能名/工具名、无混入正式句的方括号批注或自夸式元评论（这些一律放正文之外）。
- [ ] **关键数字全文一致**：摘要与正文的样本量、率、P 值、时间窗口等统计量前后不打架（如"6 个月内"与"2 年内"、18.3%/7.9% 全文统一）。

## 评审模式（用户已有标书、只求评审、不要起草时）

用户拿来一份**已写好的标书**求评审（挑毛病 / 能不能中 / 模拟评审打分 / 投前自评），**不要重写它**。走本模式：
1. **判渠道 → 加载对应要求卡**（尤其"评审在乎什么"评价维节）；渠道不确定就按 §六 编号选项问。
2. **先跑空洞度闸拿客观信号**（比人肉扫读稳）：
   ```bash
   "${REPO_ROOT:-/app}/.venv/bin/python" <本技能目录>/scripts/hollowness_check.py 用户的稿.md --sections
   ```
   引文承载率低 = 文献被当背景板堆着；创新点对照率为 0 = 创新点是不可证伪的断言；章节占比里失效分析远不足 35% = 立项依据写成了综述。**把这几个数字连同原句一起摆给用户看**，比"感觉有点空"有说服力得多。改法指向 `references/rationale-and-innovation.md` 的对应节。
3. **对着评价维 + 评审心理 + funder-fit 七维，逐维审这份稿**：
   - 科学问题是否凝练成 **1 个可检验命题**（还是散在论述里 / 宽泛愿景）？
   - **现有工作的失效点是否具体**（八类失配对得上号），还是"然而机制尚不清楚"式的甩锅？**这个空白为什么至今还在**，稿子答了没有？
