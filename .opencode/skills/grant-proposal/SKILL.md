# 基金标书技能

> **决策规约（照 AGENTS.md §六）**：本技能任何要用户拍板的抉择——渠道 / 类别 / 方案 / 下一步等——一律**在正文里列 2–4 个编号候选**（推荐项放第 1 个并写明"推荐 X，因为……"），让用户**回一个数字即推进**；**别用开放式提问逼用户打字，也别弹交互选项卡（如 AskUserQuestion）**。只有无法枚举的纯事实（手上的数据文件、伦理批号、代表作清单等）才开放式问。

帮用户把课题写成有说服力、结构完整的标书。**内容基于用户提供的真实课题与前期工作，不编造数据、成果或报价。**

## 定位（本技能在套件中的位置）
顶层主控判意图、定范围、派发；派到本技能就**直接做，别回绕**。本技能是 grant 流水线的正文起草环节；单独直呼（已有明确课题+前期工作、只要起草/润色）也直接做。产物直接写**当前工作目录**、用裸文件名（如 `proposal.md`），别拼 `outputs/…` 前缀，也别写仓库根。

## ⚠️ AI 使用合规红线（必读，先于一切）
- **NSFC（2026 通告原文，可追责）**："不得使用由生成式人工智能直接生成的申请书，不得使用未经核实的生成内容"；借助 AI 整理文献须人工核实并**如实声明、按《人工智能生成合成内容标识办法》标识**。
- **NIH（NOT-OD-25-132，2025-09 起）**：实质由 AI 生成的申请不视为 original idea（NIH 用检测技术识别）；每 PI 每财年 ≤6 份。
- **本技能的产出定位是"供申请人实质性重写的草稿框架与思路"，不是可直接提交的成稿；申请人须对全部内容负责、亲自改写。生成时主动向用户重申这一点**（NSFC 渠道还须提醒标识义务）。

## 工作流程（五步，均按要求卡驱动）

> 以下五步是**起草模式**（从课题到成稿）。用户**已有成稿、只想评审**现有标书时，走文末「评审模式」——只判该渠道评审会怎么看、给改进意见，不重写。

### 第 1 步 · 定渠道，加载要求卡
按编号选项问清申请渠道与类别，然后 **Read 对应要求卡**（本技能目录 `references/` 下）：

| 渠道/类别 | 要求卡 | 文体家族 |
|---|---|---|
| NSFC 面上、青年C类 | `references/nsfc-2026.md`（2026 新三段式提纲） | 科学问题驱动 |
| NSFC 重点、青年A/B 等未改版类别 | `references/nsfc-classic.md`（经典提纲；先核当年模板是否仍适用） | 科学问题驱动 |
| **NSFC 医学类（申请代码 H）** | 上面的 NSFC 卡 **＋ `references/nsfc-medical-h.md`**（代码表 H01–H35、分流规则、伦理硬附件、人遗资源、当年临床专项） | 科学问题驱动 |
| 中医药项目（国家局/省级/NSFC 十处） | `references/tcm-projects.md` | 三条路结构各异，卡内分流 |
| NIH（R01/R21/R03/K/F…） | `references/nih-forms-i.md` | 科学问题驱动 |
| 国家重点研发计划 | `references/most-key-rd.md` | **任务指标驱动**（勿套 NSFC 骨架） |

| 省自然科学基金 | `references/provincial-nsf.md` | 科学问题驱动（篇幅大减） |
| 省/市卫健委科研课题 | `references/health-commission.md` | 小额表格化 |
| 市级科技计划（北京市基金、上海关键技术研发、广州卫健、深圳医学专项） | `references/municipal-sci.md` | 科学问题驱动 / 指标驱动混合 |

| 表外渠道（无内置卡） | **走第 1.5 步：先调研要求，再动笔** | 调研后判定 |

**两张公共卡（不是渠道卡，按课题性质叠加读）**：
- **涉及人（含已有样本/数据的回顾性研究）** → `references/ethics-review.md`：法定送审材料 11 项、知情同意 12 要素、免除审查四情形，以及各渠道申报阶段要什么伦理件。**NSFC 医学/生命科学部缺伦理审核证明直接不予资助**，起草时就要提醒用户倒排送审时间（院内预审窗口常早于基金截止一个月）。
- **临床研究（干预性或观察性）** → `references/clinical-registration.md`：ChiCTR / ClinicalTrials.gov / ICMJE 三种注册时机口径不同（别混写），以及方案按 SPIRIT 2025（34 项）/ PRISMA-P 2015（17 项）写。

同时问清（能枚举的列编号选项）：拟申请经费强度与年限、学部与申请代码（NSFC）、课题方向与核心假设、前期工作/预实验/代表作（事实性，开放式要）。

### 第 1.5 步 · 未内置渠道：先把要求查清，再动笔（**不许凭常识硬写**）
渠道不在上表、或用户申请的类别本卡未覆盖时，**先补齐要求，不要直接起草**——各渠道的结构提纲、字数硬限、匿名/在线生成等硬规矩差异极大，凭通识写出来的稿子往往整篇作废。按下列优先级取要求：

**① 先问用户要官方文件**（最可靠、最省事）：一句话问"手上有本渠道当年的申报通知/申请书模板吗（Word/PDF 都行）"。有 → 直接走第 2 步指南摄入，**不必联网调研**。

**② 用户没有 → 联网调研。先判运行时能力，再定并行/串行**（同 `deep-research` §编排决策）：
- 当前环境**有子代理/任务派发类工具**（Task / spawn / 子代理）→ 派 **1 个**调研子代理；若该渠道还牵涉伦理审查、临床注册等独立议题，最多派 **2–3 个**分头查，各给明确边界。
- **没有该类工具、或拿不准** → **一律串行**，主流程自己用 web 搜索/抓取（或 `.venv` 的 requests/beautifulsoup4）顺序查完。**"能并发调工具"≠"能开子代理"。**
- 联网也不可用 → 跳到 ③。

**给调研子代理的任务书必须写清**（别只说"查 X 基金的要求"）：
- **要什么**：① 申请书结构提纲（**章节标题原文**）② 字数/页数硬限（逐节）③ 格式规定（字体字号行距边距、是否系统在线生成）④ 形式审查/附件清单（伦理件、限项、盖章、代表作数量）⑤ 申报截止与平台入口 ⑥ 评审要点或打分权重（若公开）。
- **来源优先级**：主办机构官网/申报平台公告 > 依托单位（高校/医院）科研处转载的模板与通知 > 商业平台（LetPub、募格等）二手汇总。**结构提纲必须来自官方或转载原文，不接受博客式概括**。
- **交付格式**：每条给 文档名 / 发布机构 / 年份 / URL / 关键条目摘要；标注一手 vs 二手；**找不到的明确写"未找到官方来源"，不许用常识补**。

**③ 调研结果落成"临时要求卡"**，写到当前工作目录（裸文件名，如 `要求卡-XX基金.md`），**按内置卡同一五节结构**：结构提纲原文｜字数/页数硬限｜格式硬规定｜形式审查清单｜动态核实项（附 URL 与年份）。卡头必须写明 **"网络调研生成，未经官方模板校验；提交前须以申报系统内当年模板为准"**，并列出哪几项没查到（写"未找到官方来源"，起草时对应部分标 `[待补充]`，别自己发挥）。
- 关键硬限（字数/页数/截止/限项）**至少 1 个官方来源或 2 个独立二手来源**才写进卡；只有单一二手来源的标"待核实"。
- 什么都没查到 → 用**最近似文体家族**的内置卡起草（见上表家族列），并在产出顶部显著声明"结构按 XX 卡类推，非本渠道官方要求，提交前必须按官方模板重排"。

**④ 沉淀**：临时卡只存在于本次会话产物目录；**容器内 `/app` 下的技能目录重建即失效，别往那写**。若卡质量不错，交付时提示用户"可把这张卡交给维护者内置到 `references/`，下次免调研"。

### 第 1.8 步 · 起草前弃标闸（go/no-go，先判该不该投再动笔）
选定渠道 ≠ 该投。动笔前过一遍匹配度，把"写完才发现资格不符/严重不匹配"挡在前面。**两段式**：
1. **硬闸（任一不过 = 直接劝退换渠道，不进打分）**：截止时间来得及？资格门槛（年龄/职称/学位/单位性质）符合？限项不冲突？研究方向属该渠道受理范围（NSFC 代码分流、中医药十处准入等）？——多数能从卡的形审/限项节直接判。
2. **funder-fit 七维快评（硬闸过了才打，粗评即可，别搞成繁琐问卷）**：topic 方向｜mechanism 资助的工作类型（基础/转化/临床）｜stage 研究阶段｜geographic 地域限制｜team 团队资质匹配｜budget 经费档位｜competitive 中标率，每维 0（不符）/1（勉强）/2（契合），满分 14。
   - 判定（照 AGENTS.md §六 给编号选项）：**≥11 → 直接起草**；**≤5 → 建议换渠道**并列 1–2 个更匹配候选；**6–10 → 停下**告知"哪几维弱、能否补强或换渠道"，用户回数字定夺。
- competitive 等需渠道数据的维，缺则第 3 步动态核实时取、或按 1 计。**闸只出信号、不替用户拍板**——投不投是用户的方向性决策，闸只把不匹配提前摆上台面。用户已铁心要投且资格明显无碍 → 硬闸扫一眼即可、七维可略。

### 第 2 步 · 指南摄入（用户有官方文件时，其优先级高于要求卡）
很多渠道的模板锁在申报平台内（省基金/卫健委尤甚），**主动请用户提供当年官方模板、申报通知或指南文件**（Word/PDF 皆可）。拿到后：
1. 通读提取：结构提纲（章节标题原文）、字数/页数硬限、格式规定、形式审查/附件要求、截止时间。
2. 与内置要求卡 **diff**：有出入处一律**以用户文件为准**，并把差异点列给用户看（这也是发现"今年又改版了"的机会）。
3. 据此生成本次起草用的"对照清单"（结构 + 硬限 + 自查项），后续各步都对着它写。
用户没有文件时：用内置卡，并在产出显著位置标注"结构按 20XX 年口径要求卡，提交前请以当年官方模板核对"。

### 第 3 步 · 动态核实闸
每张卡末节列有"动态核实项"（限项、截止期、提纲是否改版、salary cap、FORMS 版本等每年会变的数字）。**联网可用时逐项 WebFetch 卡内官方 URL 核实**，有变化就按新口径写并告知用户；联网不可用时不猜——按卡内口径写，逐项标注"基于 20XX 年口径，请核对当年规定"。**不要把可能过期的数字当铁律写进标书。**

### 第 4 步 · 按卡起草
- **结构**：严格按卡（或摄入的对照清单）的章节标题与顺序写，NSFC 类"勿删改提纲标题及括号文字"。
- **硬限**：逐节字数/页数按卡执行（博后 500–2000 字/节、浙江省 ≤8000 字、NIH Aims 1 页等）。**写完必须逐节实际数一遍**（写个小脚本切分统计，别目测）。**留余量**：用户后续填入真实细节（刊名卷期、批号、纳排细则）字数会涨，起草时写到硬限的 70–85% 为宜。
- **⚠️ 中文字数计数口径（最易错，实测栽过）**：算 **字符数**——**汉字、数字、英文字母、全角/半角标点全都算 1 个**；只排除空白与 Markdown 标记。**不要只数汉字**：一段含 `2019–2024`、`386 例`、`18.3% vs 7.9%`、`P=0.008` 的摘要，只数汉字会比真实字符数少 30–60 字，看着"353/400 有余量"实则已 411 超限。规范写法：
  ```python
  # 只剥 Markdown 语法符与空白；**别剥连字符 '-'**——正文里的连接号/范围号(如 2019-2024)是内容、算 1 字，
  # 剥掉会低估字数、造成"看着有余量实则超限"。故字符集不含 '-'。
  import re; n = len(re.sub(r'[\s*#>`|\[\]]', '', text))   # 这就是要与限额比的数
  ```
- **缺材料的字段一律标 `[待补充]`**：卡里说"某节允许出现某信息"（如博后研究基础节允许写单位/导师）不等于要求你填——用户没给的事实（单位全称、导师姓名、伦理批号、刊名卷期）**只占位、不编造、不起化名**，并在交付时列成"需你补的事实项"清单。
- **特殊开关**：博后基金正文匿名化（除研究基础节外零身份信息）；重点研发的考核指标表（立项/中期/完成三栏）；学会临床基金调 `clinical-stats` 做样本量。
- **起草前先锁定"一句话关键科学问题"（立意锁，轻量）**：把中心假说凝练成 **1 个单独成句、可检验（可证伪）的科学问题命题**——这是评审第一眼找的锚点。**放哪：2026 新格式（面上/青年C）无独立栏，该命题写进「研究内容」开头并在摘要里显著提出；classic 类别（重点/青年A/B 等）才有独立「拟解决的关键科学问题」栏，单列进去。**别把它散在立项依据论述里，别写成"明确 X / 鉴定 Y / 评估 Z"的并列分句，也别写成"探索某机制"式宽泛愿景。可先过七问自查确保选题想透：①一句话目标（外行能懂）②现状与局限 ③新意+为何会成 ④谁在乎/成功后的差别 ⑤风险与应对 ⑥经费与周期 ⑦成功的检验标准——任一答不出 = 选题未想清，先按 §六 问用户补。**本步只帮你想清 + 凝练问题，不规定正文其他段落的结构写法。**
  ⚠️ **凝练 ≠ 把没做的写成已做**：命题本身可以斩钉截铁，但支撑它的未核实前提（如"病理分期在两组间无差异"这类尚未做统计检验的断言）仍须标 `[待补充]`，创新点仍带"据本次检索"等 hedge——别为了命题利落就把没做的统计写成已证实、把个人首次说成领域首创，那踩"不虚构"红线。
- **写作要点（跨渠道通用）**：逻辑链闭环（问题→假说→目标→内容→方案一一对应）；创新点写"与现有工作比新在哪"；可行性用用户给的真实前期数据支撑；关键论断引真实文献（配合 `search-lit` / `fulltext-retrieval`）。
- **按卡的"评审评价维"分配笔墨**：起草不是均匀铺开——把重心压到本渠道评审最看重的维度（见卡内"评审在乎什么"节）：NSFC 面上重**科学问题凝练 + 创新性**、重点研发重**可考核指标**、学会临床基金重**方案可落地**。是写给这个渠道评审的心智模型，不是写一份"通用好标书"。卡未列评价维时，回落到"科学问题是否值得做 + 与现有工作比新在哪 + 可行性是否有前期数据撑住"。
- **正文只写面向评审的正式内容（正文洁净度，起草时就守住）**：绝不在正文出现技能名/工具名（`search-lit`/`reference-check`/`data-analysis` 等）；绝不把方括号编辑批注、或"解释自己写得好"的元评论（如"这是具体可衡量而非泛化造福患者的表述""这也是本渠道优选特征"）混进面向评审的叙述句——这类提示一律放到正文之外的"[待补充]清单"或给用户的说明里。评审读到会当成没清理干净的草稿而扣分。
- **预算**：按卡内该渠道的科目与规则编制（NSFC 三大科目或包干、NIH modular/detailed、重点研发分单位），每条挂到具体研究内容/Aim、写测算依据（单价×数量、人月×费率），别只给总额。
- 草稿写 `proposal.md`（当前工作目录，裸文件名）。

### 第 5 步 · 按卡自查 + 排版衔接
- **自查清单不用通用版**——用所选卡的"形式审查/自查清单"节 + 摄入文件的要求生成本次专属清单，逐条勾给用户看；再叠加下方"跨渠道通用自查"。
- **格式硬规定下传排版层**：常见渠道已固化成预设，出 Word 时直接 `render-docx --journal most-key-rd`（重点研发：标题黑体四号/正文宋体小四/1.5 倍行距）/ `municipal-sci`（市科局）/ `nih-forms-i`（NIH 11pt Arial+0.5" 边距）/ `hospital-fund`（院内），标题/正文双字体双字号由预设的 `PRESET_HEADING_CJKFONT/FONTSIZE` 落盘（也可手传 `--heading-cjk-font 黑体 --heading-fontsize 14`）；有渠道官方 Word 模板则 `--ref` 更权威。预设外的渠道按其 reference 手传页面参数。注意：标题双字体仅 docx 侧生效，`render-pdf-doc` 忽略之；博后/NSFC 等"系统在线生成"渠道则产出各节文字供用户粘贴，说明白**不出最终申请书文件**。
- 引用真实性：稿中**含具体文献引用**（作者/期刊/DOI）时定稿前跑 `reference-check`；正文只有泛化表述、未落具体引用时**跳过并说明**"本稿未含可查引用，后续补引用后需补跑"——别为了走流程凭空补引用。

## 跨渠道通用自查（叠加在卡清单之后）
- [ ] 逻辑闭环：问题→假说→目标→内容→方案一一对应，无断裂。
- [ ] 创新点写清"与现有工作比新在哪"，且分清**"领域没做过"而非"我没做过"**（new to field ≠ new to me）——别把个人首次当领域首创。
- [ ] **主动写了风险与缓解**（立项依据/可行性/研究方案里）——评审知道研究一定有风险，回避风险反而显得天真、不成熟。
- [ ] 可行性有前期数据/预实验/团队条件支撑（真实材料）。
- [ ] 限项/在研冲突已提示用户核对；伦理与合规件（涉人/动物/人遗）已提示。
- [ ] 政策类硬数字均已核实当年口径或标注口径年份。
- [ ] **无虚构**：预实验数据、发表记录、合作单位、预算报价均真实或标"待补充"。
- [ ] AI 合规已向用户重申（见顶部红线；NSFC 另提标识义务）。
- [ ] **正文洁净**：无技能名/工具名、无混入正式句的方括号批注或自夸式元评论（这些一律放正文之外）。
- [ ] **关键数字全文一致**：摘要与正文的样本量、率、P 值、时间窗口等统计量前后不打架（如"6 个月内"与"2 年内"、18.3%/7.9% 全文统一）。

## 评审模式（用户已有标书、只求评审、不要起草时）

用户拿来一份**已写好的标书**求评审（挑毛病 / 能不能中 / 模拟评审打分 / 投前自评），**不要重写它**。走本模式：
1. **判渠道 → 加载对应要求卡**（尤其"评审在乎什么"评价维节）；渠道不确定就按 §六 编号选项问。
2. **对着评价维 + 评审心理 + funder-fit 七维，逐维审这份稿**：
   - 科学问题是否凝练成 **1 个可检验命题**（还是散在论述里 / 宽泛愿景）？
   - 创新是否写清"与现有工作比的**增量**"，有没有把"我没做过"当"领域首创"？
   - 可行性是否有**真实前期数据**撑住（还是空口）？
   - 临床价值 / 意义是否**具体可衡量**（还是"造福患者"式空话）？
   - 是否**主动谈了风险与应对**（回避风险显得天真）？
   - 笔墨是否压在**本渠道评审最看重**的维度上（见卡评价维）？
   - **硬门槛**：格式 / 字数硬限 / 伦理件 / 限项等形式审查是否达标（按卡形审清单）？
   - **正文洁净**：有没有技能名 / 方括号批注 / 自夸式元评论混进正式叙述、关键数字前后是否打架？
   - 顺带可跑起草前弃标闸七维（第 1.8 步），给"该不该投这个渠道"的匹配度判断。
3. **输出评审意见**：分维度指强 / 弱 → 按渠道评审语言给总判（NIH 用三因子打分；国自然用"优先资助 / 可资助 / 不予资助"档 + 分维度评语）→ **每条弱点定位到段落、给具体改法**。
4. **边界（别重复 `peer-review`）**：方法学 / 统计 / 报告规范的深度红队（样本量、CONSORT/PRISMA、图像完整性）交 `peer-review` 技能；本模式聚焦"**作为一份标书，评审会怎么看、能不能中**"。发现疑似假引用 / DOI 存疑 → 提示跑 `reference-check`。
5. **只评不改**；用户要按意见改稿时，转起草模式第 4 步做定向修订（改完再按第 5 步自查）。
