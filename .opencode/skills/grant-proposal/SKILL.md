# 基金标书技能

> **决策规约（照 AGENTS.md §六）**：本技能任何要用户拍板的抉择——渠道 / 类别 / 方案 / 下一步等——一律**在正文里列 2–4 个编号候选**（推荐项放第 1 个并写明"推荐 X，因为……"），让用户**回一个数字即推进**；**别用开放式提问逼用户打字，也别弹交互选项卡（如 AskUserQuestion）**。只有无法枚举的纯事实（手上的数据文件、伦理批号、代表作清单等）才开放式问。

帮用户把课题写成有说服力、结构完整的标书。**内容基于用户提供的真实课题与前期工作，不编造数据、成果或报价。**

> 本文件只留定位、红线、各模式/各步的输入·输出·停下问用户的点与硬闸；细则按指针**进入该步时**再 Read `references/` 下对应文件，别一次全读。

## 定位（本技能在套件中的位置）
顶层主控判意图、定范围、派发；派到本技能就**直接做，别回绕**。本技能是 grant 流水线的正文起草环节；单独直呼（已有明确课题+前期工作、只要起草/润色）也直接做。产物直接写**当前工作目录**、用裸文件名（如 `proposal.md`），别拼 `outputs/…` 前缀，也别写仓库根。

## ⚠️ AI 使用合规红线（必读，先于一切）
- **NSFC（2026 通告原文，可追责）**："不得使用由生成式人工智能直接生成的申请书，不得使用未经核实的生成内容"；借助 AI 整理文献须人工核实并**如实声明、按《人工智能生成合成内容标识办法》标识**。
- **NIH（NOT-OD-25-132，2025-09 起）**：实质由 AI 生成的申请不视为 original idea（NIH 用检测技术识别）；每 PI 每财年 ≤6 份。
- **本技能的产出定位是"供申请人实质性重写的草稿框架与思路"，不是可直接提交的成稿；申请人须对全部内容负责、亲自改写。生成时主动向用户重申这一点**（NSFC 渠道还须提醒标识义务）。

## 定标模式（grant 流水线第 0 步：查标的要求并让用户确认，不起草）
主控在完整 grant 流水线里**最先**派本模式；用户单独说"帮我查 XX 基金今年的申报要求"也走它。**产出只有一份 `requirement_card.md`（五节：渠道与文体家族｜结构提纲｜硬限与格式｜评审评价维+指南方向/考核指标｜弃标硬闸结论+口径年份与来源 URL+经用户确认与否），落盘即停**——选题、锻打、起草都在后面，别顺手往下做。
- 输入：表单渠道 `funder` / 用户上传的通知、模板、指南（按第 2 步摄入，**视同已确认**）；都没有 → 联网查当年文件（**内置渠道也要查**，当年通知才管得住改版与限项）；联网不可用 → 按内置卡落卡并显著标"未经当年通知核实"。
- **停下问用户两处**：没渠道 → 编号选项问，问完本轮结束；查到候选文件 → 编号列出（文件名/机构/年份/URL/一句它是什么，推荐放 1，附"我自己上传"和"先按内置卡走"）让用户拍板，**绝不自行认定**；年份对不上如实说。**AUTO 不等确认**：选最可信官方来源，卡头标"自动选定、未经用户确认"。
- 收尾：报告卡已落盘、列待补事实（Minor），编号指路 research-scan / idea-forge / 直接起草。
详见 `references/targeting-mode.md`（进入定标模式时读）。

## 工作流程（五步，均按要求卡驱动）

> 以下五步是**起草模式**。用户**已有成稿、只想评审** → 走文末「评审模式」，只评不改。**当前目录已有 `requirement_card.md`（定标模式落的）→ 第 1 步不再问渠道、以卡为准直接往下**；第 2/3 步照跑（用户后补的官方文件仍以文件为准；定标时已核实过当年口径的，动态核实闸标注"已于定标时核实"即可不重查）。
> ⚠️ **别把流程读成"合规检查表"**：第 1–3 步解决"写给谁、写多长、什么格式"，**第 3.5 步才解决"写什么"**。**第 3.5 步与第 5 步的空洞度闸不许跳过**，和字数硬限一样是硬要求。

### 第 1 步 · 定渠道，加载要求卡
按编号选项问清渠道与类别，**问完本轮就结束、等用户回答**；下一轮再 Read `references/` 下对应要求卡——渠道→卡与文体家族的映射表（NSFC 2026/经典/医学 H、中医药、NIH、重点研发、四大慢病、省自然、卫健委、市级、院级、学会临床、IIT）见 `references/channel-cards.md`（第 1 步读）。**三张公共卡叠加读**：每份标书都读 `references/rationale-and-innovation.md`（论证骨架+创新点构造，第 3.5 步整步就是执行它）；涉人 → `references/ethics-review.md`（**NSFC 医学/生命科学部缺伦理审核证明直接不予资助**，提醒倒排送审时间）；临床研究 → `references/clinical-registration.md`。同时问清经费强度与年限、学部与申请代码、课题方向与核心假设（编号选项）、前期工作/代表作（事实性，开放式要）。表外渠道 → 第 1.5 步。

### 第 1.5 步 · 未内置渠道：先把要求查清，再动笔（**不许凭常识硬写**）
按优先级取要求：**①** 先问用户要当年申报通知/模板（有 → 直接第 2 步，不联网）；**②** 没有 → 联网调研：有子代理工具才派 1 个（牵涉伦理/注册等独立议题最多 2–3 个），没有或拿不准一律串行；来源 官方 > 科研处转载 > 商业二手，结构提纲必须来自原文，找不到写"未找到官方来源"、**不许用常识补**；**③** 结果落"临时要求卡"到当前目录（同内置卡五节结构，卡头标"网络调研生成，未经官方模板校验"；硬限至少 1 官方或 2 独立二手来源才入卡）；什么都没查到 → 用最近似文体家族卡并显著声明；**④** 临时卡别写进容器 `/app` 技能目录。子代理任务书要求与细则见 `references/unlisted-funder-research.md`（遇表外渠道时读）。

### 第 1.8 步 · 起草前弃标闸（go/no-go，先判该不该投再动笔）
两段式：**硬闸**（截止/资格门槛/限项/受理范围，任一不过 = 直接劝退换渠道）→ **funder-fit 七维快评**（topic｜mechanism｜stage｜geographic｜team｜budget｜competitive，各 0/1/2，满分 14）：**≥11 直接起草；≤5 建议换渠道并列 1–2 个候选；6–10 停下**告知弱在哪几维，用户回数字定夺。闸只出信号、不替用户拍板；用户铁心要投且资格无碍 → 硬闸扫一眼即可。详见 `references/go-no-go-gate.md`（第 1.8 步读）。

### 第 2 步 · 指南摄入（用户有官方文件时，其优先级高于要求卡）
很多渠道的模板锁在申报平台内（省基金/卫健委尤甚），**主动请用户提供当年官方模板、申报通知或指南文件**（Word/PDF 皆可）。拿到后：①通读提取结构提纲（章节标题原文）、字数/页数硬限、格式规定、形式审查/附件要求、截止时间；②与内置要求卡 **diff**，有出入处一律**以用户文件为准**，并把差异点列给用户看；③据此生成本次起草用的"对照清单"（结构 + 硬限 + 自查项），后续各步都对着它写。用户没有文件时：用内置卡，并在产出显著位置标注"结构按 20XX 年口径要求卡，提交前请以当年官方模板核对"。

### 第 3 步 · 动态核实闸
每张卡末节列有"动态核实项"（限项、截止期、提纲是否改版、salary cap、FORMS 版本等每年会变的数字）。**联网可用时逐项 WebFetch 卡内官方 URL 核实**，有变化就按新口径写并告知用户；联网不可用时不猜——按卡内口径写，逐项标注"基于 20XX 年口径，请核对当年规定"。**不要把可能过期的数字当铁律写进标书。**

### 第 3.5 步 · 论证内核（**动笔前必做，别跳**）
这一步解决"写什么"；跳过它，立项依据必然退化成"A 报道了…然而机制尚不清楚"的文献罗列。**先 Read `references/rationale-and-innovation.md`**，四件套齐了才进第 4 步：
- **⓪** 扫当前目录有无 `design_brief.md`（idea-forge 出件，常伴 `closest_work.md`）——有就直接映射，别翻案；**没有且用户在线 → 停下给编号选项**：1) 先进 idea-forge 锻硬再写（推荐）2) 用户直说立意与创新点，我只做**最小核实**（"首次/没人做过"必查、点名的最接近工作只核那几篇、其余采信）3) 快速通道自行推导。用户回 3 或无人值守才走 1–4。
- **1** 读上游产物（`research_scan.md` / `topic_selection*.md` / `evidence_table*.csv` / 综述稿），有就映射不重做泛综述；**一个都没有 → 先问用户"谁的工作最接近"**（1) 我知道 2) 你去查），点名只核实那几篇，空手才围绕科学问题做针对性检索找最接近 3–5 项。
- **2** 写 `closest_work.md`（≤5 行五列；局限按八类失配落到设计参数，不接受"研究较少"）。**没有这张表不许写创新点。**
- **3** gap 归因四选一（技术不可及/数据不可得/概念未提出/证据互斥）；归因①拿不出可及性证据 → 编号选项停下问用户。
- **4** 锁一句可证伪的关键科学问题，按渠道放位。
缺用户输入：能枚举的编号问，纯事实开放式要，缺则 `[待补充]`（Minor，不阻断交付）；**绝不用编造填补**。完整流程见 `references/argument-core-workflow.md`（进入第 3.5 步时读）。

### 第 4 步 · 按卡起草
- 结构严格按卡章节标题与顺序；硬限逐节按卡，**写完逐节用脚本实际数一遍**，写到硬限 70–85% 留余量；中文字数口径算**字符数**（汉字/数字/字母/标点全算 1，只剥空白与 Markdown 标记，别剥连字符）。
- 缺材料字段一律 `[待补充]`，只占位、不编造、不起化名，交付时列"需你补的事实项"。
- 立项依据按五段骨架（痛点 10–15% / 失效分析 35–40% 主体 / 关键科学问题 ≤5% / 切入点与假说 25–30% / 价值锚 10%）；创新点按五要素、2–3 条、每条追溯到 `closest_work.md`，**无对照物禁用"首次/填补空白/国际领先"**，new to me ≠ new to field；凝练 ≠ 把没做的写成已做。
- 按卡的评审评价维分配笔墨；正文洁净（无技能名/工具名、方括号批注、自夸元评论）；预算每条挂到研究内容并写测算依据。草稿写 `proposal.md`。
计数脚本、五段骨架与五要素细则、特殊开关（博后匿名化/重点研发指标表/学会临床基金调 clinical-stats）见 `references/drafting-details.md`（第 4 步读）。

### 第 5 步 · 按卡自查 + 空洞度闸 + 排版衔接
- **① 空洞度闸（起草完必跑，形式审查之前）**：
  ```bash
  "${REPO_ROOT:-/app}/.venv/bin/python" <本技能目录>/scripts/hollowness_check.py proposal.md --sections
  ```
  五项：空话词密度｜引文承载率｜段落落点率｜创新点对照率｜无引用强断言。**signal not verdict**，命中项回读原文；不达标回 `rationale-and-innovation.md` 重写论证而非换词；**同一项连续两轮仍不过 → 停下找用户**（编号选项要真实前期数据/临床观察）。
- **②** 交付前自评审一轮（用「评审模式」评价维三问：命题收敛？相对别人的增量清楚？意义可衡量？），自评结论随稿附给用户。
- **③** 自查清单用所选卡的形审节 + 摄入文件生成专属清单逐条勾给用户，再叠加**跨渠道通用自查**（closest_work ≤5 行、gap 归因、闸五项、笔墨分布 15/40/5/30/10、失效点回流成风险清单、样本量依据、指标驱动渠道逐条应答且分项相加不越线、无虚构、AI 合规重申、正文洁净、关键数字全文一致等）。
- 排版：`render-docx --journal most-key-rd / municipal-sci / nih-forms-i / hospital-fund`，有官方 Word 模板 `--ref` 更权威；在线生成渠道只出各节文字。含具体引用时定稿前跑 `reference-check`，无引用则跳过并说明。
详见 `references/self-check-and-delivery.md`（第 5 步读，含完整通用自查清单与排版参数）。

## 评审模式（用户已有标书、只求评审、不要起草时）
**只评不改、不重写。** 判渠道加载卡（不确定则编号问）→ 先跑空洞度闸，把数字连同原句摆给用户 → 对着评价维 + 评审心理 + funder-fit 七维逐维审（命题收敛、失效点具体、增量绑定**别人的**对照、真实前期数据、意义可衡量、风险应对、笔墨落点、硬门槛形审、正文洁净）→ 输出分维强弱 + 渠道评审语言总判（NIH 三因子 / 国自然三档）+ 每条弱点定位到段落给具体改法。边界：方法学/统计深度红队交 `peer-review`；疑似假引用提示 `reference-check`。用户要改稿 → 转起草模式，**先补第 3.5 步的对照表与 gap 归因**。详见 `references/review-mode.md`（进入评审模式时读）。

## 约定
- **绝不虚构预实验数据、发表记录、合作单位、预算报价/单价/薪资费率**——缺的向用户要、标"待补充"，别自己编数字凑总额。
- 要求卡本身也会过期：发现卡内口径与当年官方文件冲突时，以官方文件为准，并提醒维护者更新卡（卡都注明了口径年份与官方 URL）。
