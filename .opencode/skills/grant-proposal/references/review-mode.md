## 评审模式（用户已有标书、只求评审、不要起草时）

用户拿来一份**已写好的标书**求评审（挑毛病 / 能不能中 / 模拟评审打分 / 投前自评），**不要重写它**。走本模式：
1. **判渠道 → 加载对应要求卡**（尤其"评审在乎什么"评价维节）；渠道不确定就按 §六 编号选项问。
2. **先跑空洞度闸拿客观信号**（比人肉扫读稳）：
   ```bash
   "${REPO_ROOT:-/app}/.venv/bin/python" <本技能目录>/scripts/hollowness_check.py 用户的稿.md --sections
   ```
   引文承载率低 = 文献被当背景板堆着；创新点对照率为 0 = 创新点是不可证伪的断言；章节占比里失效分析远不足 35% = 立项依据写成了综述。**把这几个数字连同原句一起摆给用户看**，比"感觉有点空"有说服力得多。改法指向 `references/rationale-and-innovation.md` 的对应节。
3. **对着评价维 + 评审心理 + funder-fit 七维，逐维审这份稿**：
   - 科学问题是否凝练成 **1 个可检验命题**（还是散在论述里 / 宽泛愿景）？
   - **现有工作的失效点是否具体**（八类失配对得上号），还是"然而机制尚不清楚"式的甩锅？**这个空白为什么至今还在**，稿子答了没有？
   - 创新是否写清"与现有工作比的**增量**"、每条是否绑定了**别人的**对照工作，有没有把"我没做过"当"领域首创"？
   - 可行性是否有**真实前期数据**撑住（还是空口）？
   - 临床价值 / 意义是否**具体可衡量**（还是"造福患者"式空话）？
   - 是否**主动谈了风险与应对**（回避风险显得天真）？
   - 笔墨是否压在**本渠道评审最看重**的维度上（见卡评价维）？
   - **硬门槛**：格式 / 字数硬限 / 伦理件 / 限项等形式审查是否达标（按卡形审清单）？
   - **正文洁净**：有没有技能名 / 方括号批注 / 自夸式元评论混进正式叙述、关键数字前后是否打架？
   - 顺带可跑起草前弃标闸七维（第 1.8 步），给"该不该投这个渠道"的匹配度判断。
4. **输出评审意见**：分维度指强 / 弱 → 按渠道评审语言给总判（NIH 用三因子打分；国自然用"优先资助 / 可资助 / 不予资助"档 + 分维度评语）→ **每条弱点定位到段落、给具体改法**（改法引 `rationale-and-innovation.md` §7 反模式对照表：原句 → 改成什么）。
5. **边界（别重复 `peer-review`）**：方法学 / 统计 / 报告规范的深度红队（样本量、CONSORT/PRISMA、图像完整性）交 `peer-review` 技能；本模式聚焦"**作为一份标书，评审会怎么看、能不能中**"。发现疑似假引用 / DOI 存疑 → 提示跑 `reference-check`。
6. **只评不改**；用户要按意见改稿时，转起草模式——**先补第 3.5 步的对照表与 gap 归因**（稿子空洞多半是这两样从没做过），再按第 4 步定向重写、第 5 步跑闸。
