### 第 5 步 · 按卡自查 + 空洞度闸 + 排版衔接
- **① 空洞度闸（起草完必跑，形式审查之前）**——形式合规不等于内容不空，旧版本正是只查前者才让空洞稿一路通关：
  ```bash
  "${REPO_ROOT:-/app}/.venv/bin/python" <本技能目录>/scripts/hollowness_check.py proposal.md --sections
  ```
  查五项：**空话词密度｜引文承载率（最硬的一条：引用是否落在失效点语境）｜段落落点率｜创新点对照率｜无引用强断言**，`--sections` 附章节字数占比用于核对笔墨预算；只体检某一节用 `--section 立项依据`。
  **signal not verdict**：脚本查的是论证的**形状**不是对错，命中项要回读原文确认（正常背景引用也可能被点名）。不达标 → **回 `references/rationale-and-innovation.md` 对应节重写论证**，别只替换词面——把"亟待阐明"换成"尚需探索"过不了引文承载率这一关。**同一项连续两轮仍不过 → 停下找用户**（多半是缺真实前期数据或临床观察，照 §六 给编号选项要），别无限自我返工。
- **② 交付前自评审（一轮，起草模式也要做）**——用文末「评审模式」的评价维把自己的稿子过一遍，重点三问：科学问题是否收敛成 1 个可检验命题？创新是否写清了**相对别人的增量**？意义是否**具体可衡量**？发现硬伤自行返工一次，并把自评结论随稿附给用户（写成"若送到该渠道函评，最可能被质疑的是…"）。
- **③ 自查清单不用通用版**——用所选卡的"形式审查/自查清单"节 + 摄入文件的要求生成本次专属清单，逐条勾给用户看；再叠加下方"跨渠道通用自查"。
- **格式硬规定下传排版层**：常见渠道已固化成预设，出 Word 时直接 `render-docx --journal most-key-rd`（重点研发：标题黑体四号/正文宋体小四/1.5 倍行距）/ `municipal-sci`（市科局）/ `nih-forms-i`（NIH 11pt Arial+0.5" 边距）/ `hospital-fund`（院内），标题/正文双字体双字号由预设的 `PRESET_HEADING_CJKFONT/FONTSIZE` 落盘（也可手传 `--heading-cjk-font 黑体 --heading-fontsize 14`）；有渠道官方 Word 模板则 `--ref` 更权威。预设外的渠道按其 reference 手传页面参数。注意：标题双字体仅 docx 侧生效，`render-pdf-doc` 忽略之；博后/NSFC 等"系统在线生成"渠道则产出各节文字供用户粘贴，说明白**不出最终申请书文件**。
- 引用真实性：稿中**含具体文献引用**（作者/期刊/DOI）时定稿前跑 `reference-check`；正文只有泛化表述、未落具体引用时**跳过并说明**"本稿未含可查引用，后续补引用后需补跑"——别为了走流程凭空补引用。

## 跨渠道通用自查（叠加在卡清单之后）
- [ ] **`closest_work.md` 存在且 ≤5 行**，每行的"具体局限"落到设计参数（人群构成/终点/样本量/测量精度/机制层次），不是"研究较少""不够深入"。
- [ ] **gap 归因已写出**（技术不可及/数据不可得/概念未提出/证据互斥），且创新点类型与它对得上。
- [ ] **空洞度闸五项已跑**，未达标项已重写论证（不是换词），或已如实说明为何保留。
- [ ] **立项依据笔墨分布**大致落在 15/40/5/30/10，失效分析是主体而非背景铺陈。
- [ ] 逻辑闭环：问题→假说→目标→内容→方案一一对应，无断裂。
- [ ] 创新点每条五要素齐（断言+对照物+增量类型+为何以前做不到+可证伪检验+后果），且分清**"领域没做过"而非"我没做过"**（new to field ≠ new to me）——别把个人首次当领域首创。
- [ ] **失效点已回流成自己的风险清单**：`closest_work.md`「具体局限」那一列**逐条**都回答了"我怎么不栽在同一处"（结构上避开 / 写成风险并给缓解）。**盲评实测的高频失分点**——指出了别人的多中心设备差异，自己却零应对，可行性一维当场被扣。
- [ ] **主动写了风险与缓解**（立项依据/可行性/研究方案里）——评审知道研究一定有风险，回避风险反而显得天真、不成熟。
- [ ] **预测模型 / 诊断准确性 / 干预类研究给了样本量或事件数依据**（调 `clinical-stats`），并识别了本设计特有的偏倚（如金标准只在部分人群取得 = 部分验证偏倚）。骨架把注意力拉向论证时，这类"设计必答项"最容易整块蒸发。
- [ ] **指标驱动渠道（重点研发 / 四大慢病）另加两查**：① 考核指标**逐条**点名应答，一条不漏（含"操作人员培训时长""现场例数"这类容易被无视的软指标）；② **分解数字相加要对得上指标线**——各分项成本/耗时之和不得越过总指标（实测出现过分项 85+50=135 元、指标线却是 ≤120 元的自相矛盾）。
- [ ] 可行性有前期数据/预实验/团队条件支撑（真实材料）。
- [ ] 限项/在研冲突已提示用户核对；伦理与合规件（涉人/动物/人遗）已提示。
- [ ] 政策类硬数字均已核实当年口径或标注口径年份。
- [ ] **无虚构**：预实验数据、发表记录、合作单位、预算报价均真实或标"待补充"。
- [ ] AI 合规已向用户重申（见顶部红线；NSFC 另提标识义务）。
- [ ] **正文洁净**：无技能名/工具名、无混入正式句的方括号批注或自夸式元评论（这些一律放正文之外）。
- [ ] **关键数字全文一致**：摘要与正文的样本量、率、P 值、时间窗口等统计量前后不打架（如"6 个月内"与"2 年内"、18.3%/7.9% 全文统一）。
