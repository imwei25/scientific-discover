## 定标模式（grant 流水线第 0 步：查标的要求并让用户确认，不起草）

主控在完整 grant 流水线里**最先**派本模式；用户单独说"帮我查 XX 基金今年的申报要求 / 看看该按哪份文件写"也走它。**产出只有一份 `requirement_card.md`，落盘即停**——选题、锻打、起草都在后面的步骤，别顺手往下做。

1. **定渠道**：工作台表单已带渠道（`funder`）就直接用；没有 → 照第 1 步的表列编号选项问，**问完本轮结束**。
2. **扫用户材料**：用户已上传申报通知/模板/指南（或表单"撰写要求"栏填了内容）→ 按第 2 步摄入，**视同已确认**，直接跳到第 5 小步落卡。
3. **没有材料 → 联网查当年文件（内置渠道也要查）**：内置卡管的是结构骨架，**当年通知才管得住改版、限项变化、指南方向**。用 WebSearch/WebFetch 检索"<渠道> <当年> 申报通知/项目指南/申请书模板"，来源优先级照第 1.5 步②（主办机构官网/申报平台 > 依托单位科研处转载 > 商业平台二手）。联网不可用 → 如实说明，按内置卡落卡并显著标注"未经当年通知核实"。
4. **确认闸（查到了必须让用户拍板，绝不自行认定）**：把查到的候选文件编号列出，每条给「文件名 / 发布机构 / 年份 / URL / 一句它是什么」，推荐项放 1：如 "**1)** 《XX 省 2026 年度省自然科学基金项目申报通知》（XX 省科技厅官网，2026-02，推荐：年份与渠道都对上）　**2)** 《…》　**3)** 都不是，我自己上传文件　**4)** 先按内置卡走，不等通知"。**问完本轮结束等用户回数字**。查到的年份对不上/只有去年的 → 如实说，把"去年版"作为候选之一并标明风险。**无人值守（AUTO）时不等确认**：选最可信的官方来源落卡，卡头显著标注"自动选定、未经用户确认，正式申报前须核对"。
5. **落 `requirement_card.md`**（全流水线公共输入，五节）：①渠道与类别、文体家族；②结构提纲（内置渠道写"指针 → references/<卡>.md"+当年通知的增量差异，表外渠道照第 1.5 步③的临时卡结构写全）；③字数/页数硬限与格式硬规定；④**评审评价维 + 指南方向/考核指标**（供 research-scan 限定范围、topic-selection 打 funder-fit、idea-forge 定议程权重与指南对表）；⑤弃标硬闸结论（资格/限项/截止，照第 1.8 步硬闸扫一遍）+ 口径年份与来源 URL + 经用户确认与否。
6. **收尾**：报告卡已落盘、列待补事实（Minor），指路下一步（编号选项）："**1)** 进 research-scan 扫方向（推荐，从零开始）　**2)** 已有大致想法，直接进 idea-forge 锻立意　**3)** 课题已明确，直接起草"。
