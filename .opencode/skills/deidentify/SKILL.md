# 临床数据脱敏技能

医学用户把**真实患者数据**上传给 AI 分析/作图/写论文，是隐私与伦理的高风险动作。本技能在数据进入分析前，先检测并替换可识别信息，把风险降到可控。**核心原则：宁可多标（疑似的也标出来让人确认），不可漏标真 PII。**

> ⚠️ **仍需人工复核（先读）**：本技能现已覆盖自由文本里的**中文姓名（靠"患者/家属/主治医师+姓名"称谓触发+百家姓）与住址**，但仍非万无一失——**无称谓前缀的孤立人名**（如叙述中直接出现的名字）规则可能漏。因此：① 处理病历文本后**务必人工通读复核**（脚本结尾会打印醒目复核提示；当作合规闸时加 `--require-review`，脚本以非 0 退出码强制上游停下）；② CSV 里的姓名/标识/住址列，优先用 `--name-cols`/`--id-cols`/`--addr-cols` **显式指定**（表头含"医生/医师/家属/联系人"等强人名特征的列会自动脱敏并提示）；③ 正式脱敏前可先 `--scan-only` 看一遍。

## 定位（本技能在套件中的位置）
顶层主控（AGENTS.md 常驻指令）负责判意图、定范围、派发；派到本技能就**直接做，别回绕**。产物直接写**当前工作目录**——网关已把本会话的 cwd 指到该会话的产物目录，用裸文件名即可（如 `table1.csv`），别再拼 `outputs/…` 前缀，也别写到仓库根。

## 覆盖的可识别信息
身份证号（18 位**校验位核验**；15 位加**出生日期结构校验**，把纯 15 位研究流水号挡在外）、手机号（容忍 `+86`/`86` 前缀与 `-`/空格；**后接计量单位的检验值如"血糖13800138000 mmol/L"不误脱**）、住院号/病案号/门诊号/**床号（含"内科3床"自然写法）**等（"标签+号码"识别）、银行卡号（**Luhn 校验**）、座机、Email、车牌、**医保/社保号、护照号、军官证**、**住址**（省市区+路/号/楼/室，贪婪吃全串）、**中文姓名**（自由文本"称谓+百家姓名"触发；CSV 按 `--name-cols` 或强人名特征列自动）、**高龄 ≥90 岁**（HIPAA 建议归并，正常年龄如 60 岁不动）、（可选 `--dates`）具体日期。

## 误脱/漏检的取舍（宁可多脱，不可漏检）
- **本质歧义按 PII 处理**：15 位数字若出生日期结构可信、16–19 位数字若过 Luhn、11 位数字若 `1[3-9]` 开头且不接单位——与真身份证/银行卡/手机无法区分，一律脱（可能误伤同形态的科研编号，属可接受代价）。介意时先 `--scan-only` 核对。
- **姓名**：靠称谓触发（患者/家属/主治医师…+ 百家姓开头的 2–3 字名），避免误伤"月经周期/周围神经"等以姓氏字开头的术语；无称谓前缀的孤立人名可能漏，靠人工复核兜底。

## ⚠️ 仍需人工核查的类型
IP 与设备序列号、生物特征描述、面部照片、港澳台通行证、无称谓的孤立人名、罕见地址写法——务必人工核对。

## 用法
脚本在 `/app/.opencode/skills/deidentify/scripts/`（容器内的实际路径；命令行里写 `${REPO_ROOT:-/app}/...` 由 shell 展开，但**散文里的路径要能直接拿去 Read/ls**，所以这里写实路径）：
```bash
# 先扫描看看有哪些 PII、不改数据
${REPO_ROOT:-/app}/.venv/bin/python ${REPO_ROOT:-/app}/.opencode/skills/deidentify/scripts/deidentify.py --input uploads/patients.csv --scan-only

# CSV 脱敏：自动扫每个单元格；姓名列、标识号列显式指定按列假名化
${REPO_ROOT:-/app}/.venv/bin/python ${REPO_ROOT:-/app}/.opencode/skills/deidentify/scripts/deidentify.py \
  --input uploads/patients.csv --out patients_deid.csv \
  --name-cols 姓名,患者姓名 --id-cols 住院号,身份证号

# 病历/自由文本
${REPO_ROOT:-/app}/.venv/bin/python ${REPO_ROOT:-/app}/.opencode/skills/deidentify/scripts/deidentify.py --input uploads/notes.txt --out notes_deid.txt

# 同时脱敏具体日期（默认不脱，因日期常是分析变量）
${REPO_ROOT:-/app}/.venv/bin/python ${REPO_ROOT:-/app}/.opencode/skills/deidentify/scripts/deidentify.py --input uploads/notes.txt --out notes_deid.txt --dates
```
> Excel(.xlsx)：先用 `data-analysis` 把工作表另存成 CSV 再脱敏，或在脚本里用 pandas 读入后按列处理。

## 关键设计
- **一致性假名化**：同一个原值在整份数据里替换成同一个假名（`[ID0001]`、`[TEL0001]`、姓名 `[P0001]`……）。这样**既保护身份、又保留可分析性**——能按患者聚合、能追同一手机的多次就诊，但拿不到真实身份。
- **映射表单独存**：脱敏输出**不含**原始 PII；原值↔假名的映射另存 **`.private/<名>_mapping.csv`**（点号目录）。⚠️ 该映射表含真实 PII，**必须单独妥善保管或用后销毁，绝不能随脱敏数据一起外发**。
  - **点号目录不是随手写的**：界面的"产出"侧栏会把产物目录整个列出来。实测踩过——`patients_deid.csv`
    与 `patients_deid_mapping.csv` 并排出现、都能一键下载，而后者第一列就是真实姓名、住院号、
    身份证号、手机号。模型嘴上说着"映射表单独存放勿外发"，用户看到的却是两个挨着的下载按钮，
    一次误点或误转发就是一起真实的信息泄露。放进 `.private/` 后侧栏不再收录它。
  - **不要把它复制回产物目录**，也**不要把里面的内容贴进对话**（对话可以被导出、分享）。
    告诉用户时只说"映射表已单独存放、不在下载列表里，需要时可以取"。
- **默认不脱日期**：日期常是研究变量（随访时间、发病日期），默认保留；需要时加 `--dates`。若要做日期偏移（保留时间间隔但隐藏真实日期），在分析阶段统一平移。

## 何时用
- `data-analysis` / `nature-figure` / `write-paper` 处理**患者级原始数据**前，先跑本技能。
- 投稿的补充材料、公开的数据集，发布前必须脱敏。

## 硬约束与诚实边界
- **本技能是辅助、不是保证**：正则能可靠抓结构化标识（身份证/手机/住院号），但中文姓名与自由文本隐性标识穷尽不了——**脱敏后务必人工复核再对外共享**。
- **假名化 ≠ 匿名化（重要法律区别）**：本技能保留"原值↔假名"映射表，属**可复原的去标识化**。按《个人信息保护法》，只要映射存在、能复原，脱敏后的数据**仍是"个人信息"**，仍受个保法全部约束；这不同于第 73 条"匿名化"（要求不可复原、不再是个人信息）。**因此：不能仅凭跑过本工具就公开发布或随意再利用数据**；对外共享/发表前仍需本机构伦理审查与法务合规确认。
- **映射表安全 + 链接攻击风险**：`*_mapping.csv` 含真实 PII，必须单独妥善保管或用后销毁，绝不随脱敏数据外发。此外，一致性假名本身是稳定准标识符——同一患者群体多次/多数据集发布时，配合年龄/性别/罕见病等准标识仍可能被重识别；这种场景建议不同批次用不同映射，别全局固定。
- 不改动非 PII 的临床数值（检验值、诊断、用药、血压/血糖/剂量）——那是分析要用的。
