# 原创研究论文写作技能（IMRaD）

> **决策规约（照 AGENTS.md §六）**：本技能任何要用户拍板的抉择——方向 / 方案 / 目标刊 / 作图后端 / 纳排标准 / 下一步等——一律**在正文里列 2–4 个编号候选**（推荐项放第 1 个并写明“推荐 X，因为……”），让用户**回一个数字即推进**；**别用开放式提问逼用户打字，也别弹交互选项卡（如 AskUserQuestion）**。只有无法枚举的纯事实（手上的数据文件、伦理批号、代表作清单等）才开放式问。

把用户**真实的**研究数据、方法与结果，写成一篇逻辑闭环、可投稿的研究型论文。**绝不虚构数据、结果、样本量、统计数字或参考文献**——缺的向用户要、标"待补充"。本技能是本套件"写作本体"，负责把前面各环节的产物组织成成稿。

## Python 环境（可选，用于配套脚本/排版）
> **报「找不到 `.venv` / 缺 Python」先查命令里的引号**：安装目录含空格（`.../Niuma Science/bundle/app`），路径不加引号会被 bash 从空格处切断、报 `No such file or directory`——**那不是缺环境**。Python 环境随安装包/镜像装好，**不要重建 `.venv`、也不要重装依赖**（白烧十几分钟还可能弄坏包版本）；确认解释器真的不存在时，才在仓库根跑 `install.ps1`（Windows）/ `install.sh`。
```
"${REPO_ROOT:-/app}/.venv/bin/python"
```

## 定位（本技能在套件中的位置）
顶层主控（AGENTS.md 常驻指令）判意图、定范围、派发；派到本技能就**直接做，别回绕**。本技能是 paper 流水线的成稿环节（deidentify→clinical-stats+data-analysis→novelty-check(可选,数据已备时的新颖性裁定)→nature-figure→literature-review(成文综述)→**本技能**→reference-check→humanize-academic→peer-review→render-docx）；**本技能应基于上一步 `literature-review` 产出的成文综述**来写引言背景与讨论的文献对比（综述不足就回退补做，见 AGENTS.md §二）。单独直呼（统计与图已就绪、只要组织成稿，或只写投稿信/回复审稿）也直接做。产物写主控注入的**当前工作目录**（即本会话专属产物目录），**勿写仓库根固定名**——同一用户的多个会话共用一个 outputs 卷，写固定名会**跨会话互相覆盖**，而且不会出现在界面的"产出"侧栏里（侧栏只列会话目录）。

> 注：`<会话id>` 是**占位符**，执行前替换成主控给出的实际会话 id（原样复制进 shell 会因 `<` `>` 是重定向符而报错）。

## 先问清楚（写之前必须对齐）
- **研究类型**：RCT / 队列 / 病例对照 / 横断面 / 诊断试验 / 动物实验 / 病例报告 / 系统综述+Meta……（决定该套哪个报告规范，见下）。
- **目标期刊**：有没有目标刊？（决定字数、结构、摘要格式、参考文献风格与上限、是否结构式摘要）。**定了刊就去查该刊稿约、没定就走默认送审格式**——见下方「排版交付格式」，别把格式问题留到最后问用户。没定可先用 `research-scan` 帮**辅助判断**候选，但**最终仍需用户拍板确认目标刊后才动笔**（因为结构与格式强依赖具体刊）。
  - **选刊别拍脑袋**：按加权评分（契合度权重最高）+ 三档梯队（reach / target / safety）定刊，照 AGENTS.md §六 编号让用户拍板，并核查掠夺性期刊——细则见 [references/journal-selection.md](references/journal-selection.md)。
- **手上材料**：数据文件、已跑的统计结果、图表、前期文献。缺统计就先用 `data-analysis`，缺图就用 `nature-figure`，缺文献就用 `search-lit`/`literature-review`。
- **语言**：中文核心 / 英文 SCI（决定语域与引用格式；中文刊多用 GB/T 7714）。
- **故事线定了没有**：先扫当前目录有无 `design_brief.md`（idea-forge 故事线对话的出件：核心主张+主张梯度、与最接近论文的差异、目标刊三梯队、局限与反驳预演）——有就照它写引言末段/讨论定位/选刊，别再另起炉灶。没有且出现以下任一情形 → 照 §六 给编号选项 offer：用户说不清这批数据要讲什么故事/投哪；核心主张明显超出设计能撑的级别（回顾性数据说 improves/causes）——"**1)** 先进 `idea-forge` 用几轮对话把故事线和主张级别锻定再动笔（推荐，返工最少）　**2)** 直接写，主张按我判断的保守级别落笔"。故事线清晰时不 offer，直接写。

## 全自动编排（何时自动往下、何时停下问）
**自动往下走**（确定性步骤，只汇报不打断）：从已有数据算统计→建证据/结果表→按结构成文→写完自动跑 `reference-check` 查引用（标红项按 §6 的**自修复循环**处理：能可靠改就改+只复验改动项，改不动才标注上浮）→（英文/中文按需）跑 `humanize-academic` 去 AI 味→排版。
**必须停下问用户**：核心结论与主张（不能替作者拔高）、目标期刊未定、涉及未提供的数据、作者/单位/基金号等真实信息、终稿定稿前。**凡让用户拍方向（如目标期刊未定），照 AGENTS.md §六 给编号选项、用户回一个数字即推进。**
**失败即上浮**：某步（如检索）失败先按降级路径换道，换道再失败才问用户。

## IMRaD 写作流程

### 起草顺序（框架：从最客观到最主观，别从标题顺写到底）
下面 1–8 是**成稿的呈现顺序**，但**动笔顺序**建议反过来、从数据侧往解释侧写——数字与主张天然一致、少返工：
1. **先写 方法 + 结果（配对写）**：最客观；每个方法都要有对应结果，一一对应。**子节级配对**——每写完一个 Methods 子节，立即起草它对应的 Results 子节，防止"方法写了没结果 / 结果冒出没交代的分析"。
2. **再写 引言末段(研究目的) + 结论（配对写）**：让"目的"与"结论"互相照应、用词对齐（最常见硬伤就是结论答非所问）。
3. **写 讨论**：每条主张都靠 结果数据 + 文献 支撑。
4. **回填 引言开头两段**（背景 → 缺口）。
5. **写 摘要（最后写）**：逐一核对每个数字与正文/表/图三处一致。
6. **拟标题（最后定）**。
**跨节边界自查**（写完逐条查，这些是审稿人一眼就抓的硬伤）：方法里别写结果；结果里别下解释、别引文献；讨论里别塞新结果、别整段复述结果原文；结论别跑出引言写的研究目的之外；结果里出现的每个分析在方法里都要有对应描述。
**时态**：陈述本研究做了什么/发现了什么用**过去时**（方法、结果、及引用某项具体研究时）；陈述公认事实/既有知识用**现在时**（引言背景、讨论里的普遍规律）。

### 1. 标题 + 摘要
- **标题**：准确、含关键变量与研究类型，不夸大。
- **摘要**：按目标刊要求选结构式（Background/Methods/Results/Conclusions）或非结构式；**摘要里的每个数字必须与正文、与统计结果一致**；给关键效应量+置信区间，不只写"有显著差异"。**摘要要能脱离全文独立读懂**（很多读者/审稿人只看摘要）；除公认缩写外，缩写首次出现要展开；**摘要的结论句要与正文结论一致**，别一处保守一处拔高。
  - ⚠️ 各刊摘要"标题体系"不同（JAMA / Lancet / Annals / NEJM / Nature Medicine 各异），用错是 desk-reject 常见原因——按目标刊套，对照表见 [references/abstract-heading-systems.md](references/abstract-heading-systems.md)；拿不准就查目标刊 author instructions。

### 2. 引言（Introduction）——倒三角
- 背景与临床/科学意义 → 已知什么（引真实文献）→ 缺口是什么 → 本研究的问题与假设/目的。**最后一段明确研究目的**，不要写成综述。

### 3. 方法（Methods）——以"能被复现"为标准
- 研究设计、时间地点、伦理批准与知情同意（有则写批号）、注册号（试验必填，ClinicalTrials.gov/ChiCTR）。
- 对象：纳入/排除标准、抽样、分组。
- 变量与测量、干预/暴露与对照、结局定义（主要/次要）。
- **样本量/把握度依据**：优先给**研究开展前的先验**估算依据（缺就让用户补，或用 `clinical-stats` 技能算）。⚠️ 研究已完成时**不要用观察到的效应量倒推做"事后功效分析(post-hoc power)"**——方法学上被认为无意义甚至误导；无先验依据就如实说明本研究为探索性/受条件限制。
- **基线特征表 Table 1**：用 `clinical-stats` 技能生成（按变量类型自动选检验）。⚠️ **诊断准确性 / 方法比对 / 纯实验室验证类研究常无人口学基线协变量——此时省略 Table 1，别把检测值 / 生存时间硬塞成"基线表"制造误导（这类研究的样本描述放正文即可）。**
- **统计方法**：逐一说明每个分析用什么检验、软件及版本、显著性水平、缺失值处理、多重比较校正——**方法与"结果"里出现的每个分析一一对应**（统计选择见 `data-analysis` 的护栏）。

### 4. 结果（Results）——只陈述、不解释
- 先描述样本（可配 Table 1 基线特征表）。
- 按主要→次要结局顺序报**效应量 + 95%CI + 精确 p 值 + n**，别只写 p<0.05。**统计报告格式逐条对照 `data-analysis` 的 [统计报告清单](../data-analysis/references/stat-reporting-checklist.md)**（数字格式、观察性研究未校正+校正双报、诊断试验全指标、多重比较校正等）。
- 图表：出版级图交 `nature-figure`（森林图/KM/火山图等）生成到**本会话的产物目录**（主控注入的 当前工作目录；与 nature-figure / data-analysis 的落盘位置一致）。**正文数字、表内数字、图中数字三处必须一致**。
- 不在结果里下结论或讨论。

**图表如何落进论文（画完必须做，否则图会变"孤儿"）**：真嵌入 `![图1. 图注……](xxx.png)`（路径用主控给的会话产物目录前缀，写错 pandoc 会静默丢图）→ 正文点名 → 写图注 → 按首次出现顺序编号 → 交排版前自查无孤儿图、三处数字一致。五步细则见 [references/figures-and-tables.md](references/figures-and-tables.md)「图表如何落进论文」。

**表格排版铁律**：列名用标准缩写、单位与统计量形式放表注；单元格只放值；列数 >8 就转置或拆表；表题 `**表n. ……**` 置上、表注置下；**表题与表格之间、表格与正文之间必须空一行**（贴着写 pandoc 会把整张表摊平成普通文字且不报错）。六条全文见 [references/figures-and-tables.md](references/figures-and-tables.md)「表格排版铁律」。

**上下标与特殊字符铁律**：上下标一律用 pandoc 语法（`FT~3~`、`10^9^/L`、`m^2^`），禁止 Unicode 上下标字符与平排写法；负号用 ASCII `-`、别用 U+2212 `−`（宋体无字形、Word 兜底换字体）。理由与全文见 [references/figures-and-tables.md](references/figures-and-tables.md)「上下标与特殊字符铁律」。

### 5. 讨论（Discussion）
- 首段用一句话回答研究问题（呼应目的）。
- 主要发现的解释与机制、与既往研究的异同（引文献）、临床/科学意义。与既往比对用**"你的结果 → 与谁一致 → 与谁不同 → 差异可能因人群/方法/定义不同"**的模式，别只堆"某某也做过"。
- ⚠️ **引用内容失真是讨论里最危险的幻觉**：`reference-check` 只能确认"这篇文献真实存在、标题吻合"，**不能保证你对它的转述准确**。"与既往研究异同"里每处对某文献的具体说法，主代理都要**回读该文献摘要（必要时用 `fulltext-retrieval` 读全文）确认**，别把真实文献张冠李戴地引申。
  - 可机械化：把"论断→DOI/PMID"整理成 CSV 交 `literature-review` 的 `ground_claim.py` 逐条捞支撑句，WEAK 的回原文核——做法见 [references/reference-self-repair.md](references/reference-self-repair.md)「讨论转述的机械化核对」。
- **局限性**诚实交代——按四类想全，别只写一句"本研究存在一些局限"：①**设计**(回顾性/单中心/横断面/无对照) ②**样本**(样本量小/选择偏倚/人群同质/失访) ③**数据测量**(自报数据/缺失值/未验证量表/未测混杂) ④**分析**(多重比较/事后检验/残余混杂)。每条按**三段式**写：具体是什么局限 → **偏倚方向**(会高估还是低估结果) → 做了什么缓解或如何解读。**别把优点伪装成局限，也别过度自贬削弱结论**。系统综述要分两层写局限：纳入证据本身的质量 + 综述过程的局限。
- 结论**不超出数据能支撑的范围**。

### 6. 参考文献
- 每条都来自真实检索（`search-lit`/`literature-review`），**绝不凭记忆造引用**。
- 成稿后**必须**把参考文献交 `reference-check` 技能核查真实性（揪 AI 常编的假引用）。
- 中文刊多用 GB/T 7714，英文刊按目标刊风格。

**查出问题后：自修复 → 只复验改动项 → 改不动才上浮**。对 `reference-check` 标红项（`ID_FAKE`/`FABRICATED`/`MISMATCH`/`NOT_FOUND`）与转述失真逐条分诊：能可靠修复（找到真实文献 + 回读摘要确认支持论断）就改、并只把改动项传 `verify_refs.py` 复验；改不动就地标注 `【待核实：…】`、汇总进 `reference_check.md` 上浮；每条最多自修复 2 次，绝不为消灭标红换成没核实的文献。分诊规则与护栏全文见 [references/reference-self-repair.md](references/reference-self-repair.md)。

### 7. 报告规范自检（按研究类型对照，投稿前必做）
按研究类型对照规范（RCT→CONSORT 2025、系统综述/Meta→PRISMA 2020、观察性→STROBE、诊断准确性→STARD 2015、预测模型/临床 AI→TRIPOD(+AI)、动物→ARRIVE 2.0、病例报告→CARE、卫生经济→CHEERS 2022），逐条核对、缺项补齐；**RCT 的 CONSORT 流程图、系统综述的 PRISMA 流程图是硬性产出**（交 `nature-figure`）。版本注意事项与方案层规范（SPIRIT / PRISMA-P）见 [references/reporting-guidelines.md](references/reporting-guidelines.md)。

### 8. 投稿必备声明（几乎每个期刊投稿系统的必填项，缺一项就问用户要）
作者贡献（ICMJE + CRediT）、利益冲突、资助来源、数据/代码可用性、伦理与知情同意、ORCID / 通讯作者 / 补充材料清单——逐项清单见 [references/submission-declarations.md](references/submission-declarations.md)。

## 病例报告写作分支（CARE，非 IMRaD——写病例报告时改走这一节）
病例报告**不套 IMRaD**：段序按 CARE 六域、引言最后写且核心是"为何值得报告"、CARE 式三段摘要须写明最终诊断；**合规门禁**（发表知情同意书 + 影像发表授权 + 去标识，三者不可互替、缺任一项投稿前阻断）。结构规则与门禁全文见 [references/case-report-care.md](references/case-report-care.md)；其余环节复用本技能主线。

## 附属产出（按需）
投稿信 / 审稿意见回复 / 改投适配的写法要点见 [references/ancillary-outputs.md](references/ancillary-outputs.md)。

## 数字来源核对（防"顺手编数字"，写完必做）
AI 写论文最危险的是**悄悄编一个 p 值/样本数/效应量**。成稿后做一次机械核对：
- 列一张**数字来源表**：摘要、正文、每张表、每张图里出现的每个关键数字 → 对应到 `data-analysis`/统计脚本的**原始输出文件的哪一行**。凡在原始输出里找不到出处的数字，一律标红、回去核实或删除，**不允许"看起来对"就放过**。
- **样本量与统计量逐一对照统计输出文件，不得凭记忆复述**：总例数与各组例数必须与统计脚本的打印输出（`df.shape`、`groupby().size()`）及 Table 1 的"样本量 n"行完全对上，**不得按数据文件行数推断**（行数含表头会多算 1 例）；对不上以统计输出为准，回上游重跑核对再落笔。
- **三处一致**：同一个数（如主要结局效应量）在摘要、正文、表、图里必须完全一致。
- 改写/润色后再跑一遍 `humanize-academic` 的 `scripts/check_invariants.py`（比对改写前后数字/引用无变化）。

## 投稿前自查（收尾，最后一道闸）
范围契合、字数/结构/摘要/引用符合目标刊、图表达标、流程图与声明（§8）齐全、完稿后走 `peer-review` 的"投稿前自查模式"；**Desk-reject 红线七条**（范围不匹配、新颖性未显式陈述、伦理/注册缺失、超限、报告规范清单未附、格式硬伤、相似度）投前逐条过，任一不过先补齐再投。完整清单见 [references/pre-submission-checklist.md](references/pre-submission-checklist.md)。

## 查重工具推荐（交付成稿时主动附给用户）
成稿交付时**主动**附查重建议（**仅论文 / 投稿稿件适用**；均为网页端、需用户**自行上传**，本技能不代查）：中文免费初查 PaperPass / PaperYY、定稿知网（万方 / 维普可过渡）；英文免费初查 Scribbr 免费版 / Plagly、定稿 iThenticate。随附两条提醒：上传选**不入库**选项、免费工具只做初筛。工具表与网址见 [references/plagiarism-check-tools.md](references/plagiarism-check-tools.md)。

## 排版交付格式（定稿出件时按这条走，别每次问用户要什么格式）
判一件事：**用户指定目标期刊了没有**。**A. 没指定** → 直接 `render_docx.sh -i manuscript.md --journal generic-submission`（PDF 同参数给 `render-pdf-doc`），一个参数落齐默认送审格式（Times New Roman 12pt、1.5 倍行距、不加行号、三线表拉满版心等），别追问格式细节。**B. 指定了** → 先 `--journal list` 看有无预设，没有就 WebFetch 该刊 Instructions for Authors 摘出要求再落参数；查不到如实说明、退回 generic-submission，**不凭印象编该刊格式**。默认参数表、B 路四步、以及排版脚本做不到的两项（参考文献期刊全称 / et al. 规则、图表位置——写作阶段就得写对）见 [references/submission-format.md](references/submission-format.md)。

## 产出与交付
- 稿件写 `manuscript.md`；cover letter 写 `cover_letter.md`；回复写 `response_to_reviewers.md`。
- **出投稿版**：按上一节「排版交付格式」选默认预设还是查稿约。Word 稿交 `render-docx` 技能（医学期刊多要 .docx；该技能用 pandoc）。**若 pandoc 未安装或 render-docx 不可用**，退回用 `render-pdf-doc` 出 PDF，并如实告知用户"可用 Word/WPS 打开 Markdown 自行另存为 .docx"，**不要静默失败或臆造转换步骤**。
- **去 AI 味**：定稿前把正文交 `humanize-academic`（中英文都支持），并跑其不变量校验确保数字/引用未被改动。

## 硬约束
- **绝不虚构**数据、结果、数字、样本量、统计量、参考文献、伦理批号、注册号、基金号、作者单位——缺的标"待补充"向用户要。
- 结论不超出数据；不替作者夸大主张。
- **AI 使用合规**：多数期刊要求披露 AI 辅助写作，且不接受实质由 AI 生成、无人负责的稿件。**AI 不满足作者资格、不得列为作者或共同作者**（ICMJE）；披露时说明用了什么工具/版本、用于哪个环节（如仅语言润色 vs 起草内容）。**本技能产出为草稿，作者须实质性审阅、修改并对全部内容负责。**
- 涉及人/动物研究，提醒补伦理与合规内容。
