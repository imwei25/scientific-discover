# 图表落稿、表格排版与上下标写法铁律

> 本文件从 SKILL.md「4. 结果」节（图表如何落进论文 / 表格排版铁律 / 上下标与特殊字符铁律）搬出，由 SKILL.md 在把图表写进 manuscript.md 与交排版前自查时引用。

**图表如何落进论文（画完必须做，否则图会变"孤儿"——文件躺在 `outputs/` 里但正文既没嵌入也没图注，渲染出来就是"提了图却没图"）**：
1. **真正嵌入图片（不是只在文字里提"见图1"）**：每张要进正文的图生成后，在 manuscript.md 结果对应处写 `![图1. 图注……](xxx.png)`。⚠️ **路径必须指向图的真实位置**——渲染脚本从**仓库根**跑，而图在**本会话的产物目录**里，所以要用主控注入的那个路径（形如 `xxx.png`，主控在每轮开头已给出确切前缀，照抄即可）；写成 `figures/…`、裸文件名、或写死成仓库根的 `outputs/xxx.png`（少了会话段），pandoc 都会找不到而**静默丢图**——这正是"正文提了图却没插进来"的头号原因。按目标刊惯例可把图与图注单列在正文之后，正文处留点名，但**图本身仍要真嵌入**（放文末图表区）。
2. **正文点名**：在讲到该结果处点名 `(图1)` / `(Figure 1)`，别让图和正文脱节——但点名**不能替代**上一步的真正嵌入。
3. **写图注 (legend)**：说清图表达什么、样本量 n、误差条/箱线含义、统计方法与显著性标记（`*p<0.05` 等）、坐标单位/比例尺；缩写在图注里首次展开。
4. **统一编号**：图、表各自**按正文首次出现顺序**编号，维护一份图/表清单；引用编号与 `outputs/` 文件一一对应。
5. **交排版前自查**：凡正文点了名的图，会话产物目录里都有对应文件、且已用 `![...](xxx.png)` 真嵌入、有图注、无"孤儿图"、图号连续；三处数字一致。⚠️ `render-docx`/`render-pdf-doc` 嵌入的图题只是普通文字、**不是 Word 自动编号域**，增删图后编号需手工复核。

**表格排版铁律（进正文的每张表都适用；列名写太长是渲染后表格丑的头号原因）**：
1. **列名用标准缩写，单位与全称放表注**：写 `SBP` 不写 `收缩压(mmHg)均值±标准差`；统计量形式（mean±SD、n(%)、M(IQR)）在表注统一交代一次，别塞进列名或重复在每格。表注里缩写逐一展开——这本来就是期刊要求，顺带治了排版。
2. **单元格只放值**：数值列统一小数位；长说明文字进表注或正文，不进单元格。
3. **列数 >8 或列名实在缩不动** → 转置（变量做行、组别做列）或拆成 表na/表nb；别硬挤一页。
4. **分隔行 `|---|` 不用手调宽度**：`render-docx`/`render-pdf-doc` 渲染时会按内容自动推断列宽并套三线表——但那只是兜底，**源头列名短才是治本**；渲染时若报"表格过宽"警告，回来按第 1/3 条改表。
5. 每表有表题（`**表n. ……**` 独立一行置表上方）与表注（置表下方）；表内不放图片、不嵌套表。
6. **表题与表格之间、表格与下方正文之间必须空一行**。贴着写的话 pandoc 会把表题当段落开头、把每一行表格当作它的"懒续行"，**整张表摊平成一段普通文字，docx 里一个表都没有，而且不报任何错**——稿子看着有内容、表却没了，最容易漏检。标题行、列表贴着正文写同理会被吞。

**上下标与特殊字符铁律（源头写对，别指望渲染器兜底）**：
1. **上下标一律用 pandoc 语法**：`FT~3~`、`10^9^/L`、`m^2^`、`p = 6.6×10^-26^`。
   - **禁止 Unicode 上下标字符**（`FT₃`、`10⁻⁴`、`10⁹`）：那不是格式、是普通字符，渲染全看字体里有没有这个字形。宋体/等线**只有 ² ³ ¹，缺 ⁻ ⁴ ⁵ ⁹ 和全部下标 ₀-₉**（微软雅黑也缺 ⁻ ⁹ ₃ ₄），缺字形时 Word 临时换字体去顶，于是「10」是宋体、「⁻⁴」是另一套字体，字重/大小/基线全对不上。这就是「`m²` 正常、`10⁹` 就坏」的原因——**症状时有时无，最难排查**。
   - **也别平排写**成 `FT3`、`10^9/L`、`m2`：那连上下标都没有，渲染器无从修正（`FT3` 也可能是变量名，自动改有误伤风险）。
2. **负号用 ASCII 连字符 `-`，别用 U+2212 数学减号 `−`**：宋体没有这个字形，而它按 UAX#11 属"东亚歧义宽度"，Word 在中文稿里倾向按东亚字体取字 → 落到宋体 → 兜底换字。**满屏负数的结果表尤其明显**（实测一份稿件里 72 处负号全部受影响）。
> 以上三条 `render-docx` 在渲染前会自动兜底修正（`normalize_md.py`），但**兜底不等于免责**：源头写对，PDF/HTML 等其它出口才一并正确，也省得每次都靠渲染器打补丁。
