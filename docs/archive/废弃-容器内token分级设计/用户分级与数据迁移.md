# 用户分级 + 每日额度 + 一键数据迁移

面向本套「每用户一个容器」的多用户部署，补齐三件事：**用户分级、每日 token 额度、一键导出迁移**。

---

## 一、用户分级与每日 token 额度

### 制度长什么样
全部规则集中在一份文件：`deploy/state/users.json`（所有用户容器只读挂载它，改完**即时生效、无需重启**）。

```jsonc
{
  "tiers": {                                   // 档位定义
    "free":  { "label": "普通",   "dailyTokens": 500000 },   // 50 万 token/天
    "plus":  { "label": "高级",   "dailyTokens": 2000000 },  // 200 万 token/天
    "admin": { "label": "管理员", "dailyTokens": 0 }         // 0 = 不限
  },
  "defaultTier": "free",                       // 没登记的用户走这个档
  "users": {                                   // 用户 → 档位
    "alice": { "tier": "admin" },
    "bob":   { "tier": "free" }
  }
}
```

- **额度单位** = 当日消耗的 token 合计（输入 + 输出 + 推理，即 DeepSeek 实际计费口径）。`dailyTokens: 0` 表示不限。
- **每天 0 点（北京时间 UTC+8）自动重置**。用量按天记在 `deploy/state/usage/<用户名>.json`，保留最近 90 天供审计/导出。
- 首次启动若无 `users.json`，程序按 `deploy/state/users.example.json` 生成一份（预设 alice=管理员、bob=普通）。

### 用户端体验
- 每个用户页面右上角有**今日额度徽章**：`今日 128k/500k ▓▓▓░░`，接近上限变黄、用尽变红。
- 额度用尽后再发消息，会立即收到提示「今日 token 额度已用完（档位「普通」：已用 … / 上限 …），北京时间每日 0 点自动重置」，**该轮不会真的发起、不消耗任何 token**。

### 管理员怎么改分级
两种方式，任选：

1. **网页管理台**（推荐）：管理员（compose 里 `IS_ADMIN: "1"` 的用户，缺省是 alice）访问 `http://服务器/alice/admin`：
   - 看所有用户的今日用量、剩余额度、进度条；
   - 下拉改任一用户的档位，点保存即生效；
   - 改档位的每日额度、或新增档位（如 `vip`）。
2. **直接编辑** `deploy/state/users.json`：改完即时生效，无需重启容器。

> 谁是管理员由容器的 `IS_ADMIN` 环境变量决定（与档位无关）。非管理员容器访问 `/admin` 一律 404，不暴露入口。

### 给某用户单独设档
在管理台下拉里改，或在 `users.json` 的 `users` 里加一行 `"carol": { "tier": "plus" }`。新用户首次访问后会自动按缺省档出现在管理台，再改即可。

## 二、一键导出（换服务器 / 备份）

所有需要迁移的数据分布在两处：**每用户 3 个 Docker 卷** + **共享目录 `deploy/state`**（外加账号/路由配置）。一个脚本全部打包。

| 数据 | 位置 |
|---|---|
| 上传的数据文件 | 卷 `<user>-uploads` |
| 产物（图/表/文档） | 卷 `<user>-outputs` |
| **会话历史 + 会话元数据 + 所选模型** | 卷 `<user>-data`（OpenCode 存储经 `XDG_DATA_HOME` 落此卷） |
| 分级制度 + 每日用量 | `deploy/state/`（users.json、usage/） |
| 账号 / 路由 / 密钥 | `htpasswd`、`.env`、`nginx.conf`、`docker-compose.yml` |

### 导出（旧服务器）
```bash
cd ~/sci-agent/deploy
bash export-all.sh                       # 产物：backups/sci-agent-backup-<时间>.tar.gz
# 想要严格一致的快照，可先 docker compose stop 再导出，导完再 up -d
```

### 导入（新服务器）
```bash
# 先把代码拉下来、装好 docker（见主部署文档阶段 A/B），然后：
cd ~/sci-agent/deploy
scp 你的机器:.../sci-agent-backup-<时间>.tar.gz .     # 或用别的方式把包拷进来
bash import-all.sh sci-agent-backup-<时间>.tar.gz     # 恢复卷 + state + 账号/路由
docker compose build && docker compose up -d
```

导入会把每个卷灌回本机对应卷（不存在则自动建），并恢复 `state/` 与账号/路由文件（原有同名文件先备份成 `*.bak-<时间>`）。脚本用短卷名迁移、导入时套用本机项目前缀，**换了服务器或改了目录名也不影响**。

> 若你的 compose 项目名不是缺省的 `deploy`（目录名），导出/导入前设 `export COMPOSE_PROJECT_NAME=你的项目名` 即可。

## 三、涉及的文件（改了什么）

- `web/quota.mjs`（新）— 分级 / 额度 / 用量计量核心。
- `web/server.mjs` — 计量每轮 token、发起前查额度拦截、`/api/quota`、`/admin` 与 `/api/admin/*`；持久化目录改走 `DATA_DIR`。
- `web/admin.html`（新）— 管理台页面。
- `web/index.html` — 右上角今日额度徽章 + 管理台入口。
- `deploy/docker-compose.yml` — 每用户加 `-data` 卷、共享 `./state` 挂载、`USER_NAME/IS_ADMIN/DATA_DIR/STATE_DIR/XDG_DATA_HOME` 环境变量。
- `deploy/entrypoint.sh` — 建持久化目录。
- `deploy/state/users.example.json`（新）— 分级制度范例/种子。
- `deploy/export-all.sh` / `deploy/import-all.sh`（新）— 一键导出 / 导入。
