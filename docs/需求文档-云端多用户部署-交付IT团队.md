# 需求文档：科研医学 Agent 云端多用户部署版（交付 IT 团队）

> 版本：v1.0（2026-07-28）｜需求方：AI 团队｜实施方：公司 IT 团队
>
> 本文档只描述**需求与验收标准**，不限定技术路线：服务器形态、隔离手段、编排方式、
> 中间件选型均由 IT 团队自主决策，以 §4 验收标准为准。
> 与《需求文档：桌面本地部署版》为并行的两种产品形态，共用同一份应用本体与技能目录。

---

## 0. 一句话目标

把科研医学 Agent 部署为**多用户云端服务**：用户用浏览器（电脑/手机）访问，注册登录后
即可使用全部功能；每个用户拥有隔离的工作环境与数据；平台按用户计量 token、分档位管控额度。

## 1. 背景与现状（供理解，非需求）

- **应用本体已成熟可运行**（AI 团队维护，不在 IT 改造范围内）：
  web 界面网关（node, `web/server.mjs`）→ opencode agent 引擎 → 23 个技能
  （SKILL.md 提示词 + Python/Bash 脚本，Python 栈钉版于 `deploy/requirements.txt`）。
  应用本体按"一份实例服务一个用户"的模型工作，自带会话管理、文件上传、产物侧栏、
  局域网/本机登录门禁。
- **云端平台是空白画布**：如何把 N 份用户实例托管起来（隔离、调度、路由、伸缩）、
  以及注册登录/计量/后台这些平台能力，由 IT 团队从零设计。
- 一次完整科研流水线（标书/论文/系统综述）单轮可运行十几分钟到更久，且过程中会执行
  统计计算、文档转换等本地进程——这是平台设计必须适配的核心负载特征。

## 2. 角色与职责边界

| 角色 | 负责 | 不负责 |
|---|---|---|
| **AI 团队（需求方）** | 应用本体（网关+引擎+技能）、`.opencode/skills/` 全部技能内容、`AGENTS.md` 主控指令、`deploy/requirements.txt` Python 依赖钉版 | 平台架构、部署、运维 |
| **IT 团队** | 云端平台（多用户托管/隔离/路由/伸缩）、注册登录、计量计费、运营后台、发布运维、安全合规基础设施 | 应用本体与技能内容 |

**接口约定**：应用本体代码 + 技能目录 + AGENTS.md + requirements.txt 是双方的全部接口。
AI 团队更新这些 → IT 的发布管道自动吸收；IT 不修改应用本体与技能内容；
应用本体对运行环境的要求以 §3.6 环境契约为准，新增依赖须双方协商。

## 3. 需求清单

优先级标注：【必须】v1 上线前提；【应当】v1 尽量、v1.x 必须；【可选】有条件再做。

### 3.1 用户访问与体验

- 【必须】浏览器直达：HTTPS + 正式域名，电脑与手机浏览器均可正常使用（应用界面已自适应）。
- 【必须】长任务不掉线：单轮任务可持续 30 分钟以上；用户**关闭页面/断网后任务继续跑**，
  重新打开能看到进行中状态与最终结果。
- 【必须】数据持久：会话历史、上传文件、产物跨登录持久保存；用户删除会话即删除对应数据。
- 【必须】就绪时间：用户打开页面到可对话 ≤60 秒（含冷启动场景）；热状态 ≤5 秒。
- 【应当】容量声明：初期支持 ≥50 注册用户、≥10 并发活跃用户；扩容路径清晰（加资源即可，
  无需改架构）。

### 3.2 注册登录与用户管理

- 【必须】注册/登录方式：**手机号 + 短信验证码**（一期）；**微信扫码**（二期，需公司主体的
  微信开放平台资质，请提前评估办理周期）。
- 【必须】云端用户档案：身份（手机号/openid）、**档位（分级）**、状态（正常/停用）、用量。
- 【必须】免登录期：登录态保持 N 天（可配置），期内重访免登录；
  停用账号后现有登录态在下一次请求即失效。
- 【必须】防滥用：验证码有频控与图形验证兜底；同一账号并发会话数可限制。

### 3.3 多用户隔离与资源管控

- 【必须】强隔离：用户之间**数据不可互访、执行环境不可互扰**。注意：agent 引擎具备执行
  任意 shell 命令的能力（这是产品功能，不是漏洞），因此隔离必须是**执行环境级**的，
  仅靠应用层权限校验不满足本条。隔离的具体技术手段由 IT 选型。
- 【必须】资源限额：单用户的 CPU/内存/磁盘有上限，任何用户的重负载（如大文件统计、
  文档转换）不得拖垮其他用户或平台本身；超限行为有可预期的失败表现而非平台崩溃。
- 【必须】闲置回收与按需分配：用户不活跃时其占用的计算资源可回收，再次访问时自动恢复
  （数据不丢）；平台总资源按并发活跃数配置而非注册数。
- 【必须】引擎不对外暴露：agent 引擎无鉴权，其服务端口绝不可被用户浏览器或公网直接访问；
  所有流量必须经过带鉴权的入口层。

### 3.4 token 计量与额度

- 【必须】按用户计量：每个用户的 LLM token 消耗可查（日/月/累计），作为计费与额度依据；
  被用户中途终止的请求也必须计入（上游按全额计费）。
- 【必须】额度控制：按档位设额度（建议含"每日额度"维度），超限拒绝并给用户明确提示；
  额度策略运营可调，无需发版。
- 【必须】分级管理：档位决定可用模型与额度；后台调档对用户即时或次轮生效。
- 【必须】上游模型通道管理：多渠道调度/故障切换/换模型对用户透明。
- 【应当】用量异常告警：单账号用量突刺提醒运营。

### 3.5 运营后台

- 【必须】最小后台能力：用户列表（搜索）、改档位、停用/启用、看用量、看在线/资源占用状态。
  操作不得要求登录服务器敲命令。
- 【应当】数据看板：活跃用户、总用量趋势、资源水位。

### 3.6 应用本体环境契约（每个用户实例的运行环境必须满足）

无论 IT 采用什么托管方案，分配给每个用户实例的执行环境必须成立以下契约
（这是技能正常运行的前提，验收 A5 逐项覆盖）：

1. 应用根存在 `.venv`，`.venv/bin/python` 可执行并加载钉版科研 Python 栈
   （`deploy/requirements.txt`）；
2. 命令行环境提供：`bash`（heredoc/管道/source）、`git`、`pandoc`、裸 `python3`；
3. **完整文档能力**（云端版不降级）：出版级 PDF 排版（xelatex + 中文宏包 + 全套字体）、
   docx/pptx 生成与在线预览（LibreOffice）可用；
4. matplotlib 中文图不出豆腐块（含逐字形回退）；
5. 每个会话有独立工作目录，agent 写裸文件名即落对应会话的产物目录（应用本体自带机制）；
6. 应用本体以环境变量接收平台注入的配置（LLM 接入、额度参数、路径前缀等，
   具体清单交接时由 AI 团队提供）。

AI 团队承诺：技能只依赖以上契约；新增系统级依赖提前协商。

### 3.7 可用性与运维

- 【必须】数据备份：用户数据（会话/文件/产物/用户档案）定期备份，有恢复预案且演练过。
- 【必须】监控告警：平台存活、资源水位、上游 LLM 通道可用性有监控与告警。
- 【必须】日志：平台侧与用户实例侧日志可查，排障不依赖复现。
- 【应当】技能热更新：技能内容更新走管道直达所有用户实例，与平台发版解耦。

### 3.8 安全与合规

- 【必须】全链路 HTTPS；用户内容数据存储于平台，须有访问控制与备份保护；
  运营后台不提供查看用户内容数据的功能（只见元数据与用量）。
- 【必须】平台自身安全：入口层防暴力破解（频控/封禁）、验证码、依赖组件的安全更新机制。

### 3.9 明确的非目标（不做）

- 不做团队/组织账号体系（一人一账号；机构合作另立需求）。
- 不做用户内容数据的跨用户共享/协作功能。
- 不承诺 LLM 上游的 SLA（上游故障时平台如实提示并自动切换通道）。

## 4. 验收标准

| # | 场景 | 通过标准 |
|---|---|---|
| A1 | 新用户注册 | 手机号+验证码完成注册并进入主界面；全程 HTTPS |
| A2 | 免登录 | 同设备 N 天内重访免登录；后台停用后下一次请求即拒 |
| A3 | 冷/热启动 | 冷启动 ≤60s 可对话，热状态 ≤5s |
| A4 | 长任务 | 发起 ≥30 分钟的流水线任务，中途关浏览器，重开后看到进行中/完成结果 |
| A5 | 环境契约 | 在任一用户实例内逐项验证 §3.6 六条契约（统计出中文图、md→PDF 出版排版、pptx 生成+在线预览） |
| A6 | 隔离-数据 | 用户 A 无法以任何方式（含构造 URL、让 agent 执行命令）读到用户 B 的文件与会话 |
| A7 | 隔离-资源 | 用户 A 跑满自身资源上限时，用户 B 的使用不受影响；A 超限得到明确失败提示 |
| A8 | 引擎不暴露 | 从公网与用户浏览器侧均无法直连 agent 引擎端口 |
| A9 | 计量 | 后台可见某用户本轮 token 消耗；中途终止的轮次也计入 |
| A10 | 额度/档位 | 超额被拒且提示明确；后台调档后模型与额度随之变化 |
| A11 | 闲置回收 | 用户闲置后资源被回收；再访问数据完好、自动恢复可用 |
| A12 | 备份恢复 | 按预案完成一次真实恢复演练，用户数据完整 |
| A13 | 发布 | 完成一次应用本体+技能的更新发布：运行中任务不中断，失败可回滚 |
| A14 | 后台 | 搜用户、调档、停用、看用量 |

## 5. 交接与协作方式

- AI 团队移交：应用本体代码、技能目录、AGENTS.md、requirements.txt、环境变量配置清单；
  并保留对上述内容的维护权（建议以 CODEOWNERS/评审规则固化）。
- 技术选型（托管/隔离/编排/网关/短信服务商/上游通道管理等）IT 自主决策，以验收标准为准。
- 建议里程碑：M1 单用户云端可用（A3/A4/A5/A8）→ M2 多用户隔离与回收（A6/A7/A11）
  → M3 注册登录与计量档位（A1/A2/A9/A10/A14）→ M4 运维成熟度（A12/A13）。
- 与桌面版的关系：两形态共用应用本体与技能；云端版的登录/计量/后台能力建议设计时
  预留复用给桌面版（桌面版需求文档 §3.2–§3.4 与本文档高度同构）。
