# 设计方案：模块 = 结构化工作流（不再是"进去就是自由对话"）

日期：2026-08-04　范围：`web/server.mjs` 模块层 + `web/index.html` 前端 + `.opencode/skills/` 契约
决策前提：**系统综述 / Meta 不做模块，只走「自由对话」**（本次已定，见 §7）。

---

## 0. 现状与目标

**现状**：`MODULE_DEFS`（[web/server.mjs:507](../web/server.mjs)）给每个模块绑一组技能，`skillGate`
（server.mjs:1345）强制只能调这组技能。但用户点进模块后看到的**仍是一个空白输入框** —— 边界是硬的，
流程是软的：走哪几步、每步要什么、产出长什么样，全靠模型自己发挥和用户自己打字。

**目标**：模块 = **技能白名单（硬边界）+ 步骤链（剧本）+ 每步的结构化输入输出（表单与渲染）**。
用户进模块先填一张卡，之后每一步的输入是勾选而非打字、输出是渲染的表/卡/图而非一坨文本。

**一条贯穿全篇的取舍**：结构化**只灌初值、只做观察与呈现，不做硬状态机**。agent 会合并步骤、
会跳步、会根据实际情况回退（AGENTS.md §二 本来就要求它这么做）。服务端若强行卡"必须按序"，
会与 agent 的自主推进正面打架，产生"它已经做完了但界面卡在第 3 步"的死结。所以：
**表单 → 灌进消息；产物 → 反推进度；闸不过 → 给返工按钮。全程不阻断 agent。**

## 1. 架构：三件套

### 1.1 工作流定义（服务端唯一事实来源）→ 新文件 `web/workflows.mjs`

```js
// 每个模块一条 steps[]；模块的技能白名单由它展开，不再手写数组
export const WORKFLOWS = {
  paper: {
    intake: [ /* 首屏立项卡字段，见 §3.1 */ ],
    steps: [
      { id:"deid",     name:"数据脱敏",   skill:"deidentify",
        when:"hasRawData && !deidDone",              // 条件步：立项卡决定要不要
        form:[…], emits:["deid_*.csv","deid_report.md"], render:"deid" },
      { id:"stats",    name:"统计分析",   skill:"data-analysis",
        form:[…], emits:["data_profile.md","stats_*.csv"], render:"table" },
      { id:"refcheck", name:"引用核查",   skill:"reference-check", gate:true,
        emits:["refcheck_report.md"], render:"refcheck", onFail:"write" },
      …
    ],
  },
  …
}
// 模块技能白名单 = steps 的 skill 去重（∪ extra），一份定义两用
export const skillsOf = (mod) =>
  [...new Set([...(WORKFLOWS[mod]?.steps || []).map(s => s.skill), ...(EXTRA[mod] || [])])]
```

要点：

- **`MODULE_DEFS.skills` 改为由 `skillsOf()` 展开**，与上一轮设计的"pipeline 闭包"合流 ——
  流程表和技能白名单是同一份事实，不会再漂。
- **`modPrimarySkill` 改读显式 `primary` 字段**，不再取 `skills[0]`。技能集自动展开后数组顺序
  不可靠，而它决定模块是否可用（server.mjs:535），会静默错判。**这是必须一起改的既存隐患。**
- 启动自检：每个 `skill` 必须在 `SKILL_IDS`（真实技能目录）里存在，否则响亮告警。

### 1.2 输入结构化：表单 → 任务卡 → 拼进消息

**沿用已验证的机制**：`zScopePrefix()`（index.html:2895）已经在把 UI 状态拼成 `【…】` 前缀塞进
消息里，实测有效。表单走同一条路，零 opencode 改动：

```
【任务卡 · SCI 论文 / 立项确认】
研究类型：回顾性队列
稿件类型：Original Article
已有材料：原始数据表（uploads/cohort.xlsx，含患者姓名与住院号 → 未脱敏）
目标期刊：target 主投；筛选条件 IF 3–6、中科院 3 区及以上、非掠夺性、PubMed 收录
输出语言：英文
【以上为用户通过表单提交的结构化输入，视同用户明确指令。未填项标"待补充"并向用户索要，不要臆测。】
```

- 首屏表单填完点「开始」= 发出第一条消息。**之后输入框照常可用**，可自由追问（仍受技能白名单约束）。
- 后续步骤若有 `form`，在**对话流内联渲染一张卡**（不是弹窗），提交即作为下一条消息发出。
- **schema 由服务端下发**（`GET /api/modules/:id/workflow`），前端只是渲染器 —— 改流程不用重发
  桌面安装包，走已有的"界面包"热更新即可。

### 1.3 输出结构化：产物契约 → 渲染器

**不要求 agent 输出 JSON**（模型格式会漂，脆）。改为**认产物文件**——技能本来就产这些文件：

| 渲染器 | 认领的产物 | 呈现 |
|---|---|---|
| `evidence` | `evidence_table.csv` / `evidence.md` | **文献卡片列表**：标题/期刊/年/DOI/被引/OA/期刊影响力；可排序筛选；每条带「下全文」「推 Zotero」「排除」 |
| `retrieval` | `retrieval_report.json` / `manual_needed.txt` | 成功 / 失败分栏（把"诚实汇报"那条铁律 UI 化） |
| `table` | `table1.csv` / `stats_*.csv` / 任意 csv | 三线表预览，可复制 |
| `figure` | `fig*.png/pdf/svg` | 图卡（复用已有预览） |
| `refcheck` | reference-check 报告 | 红/黄/绿逐条 + 「回退改引用」按钮 |
| `review` | `review_report.md` | 按严重度五元组分组，逐条可标"已修/忽略" |
| `integrity` | `integrity_report.md` | 待核信号列表（措辞守"signal not verdict"） |
| `deid` | `deid_report.md` | 脱敏前后对照 + 命中规则计数 |
| `diff` | `manuscript_humanized.md` vs 原文 | **对照 diff**（润色模块的核心，现在纯文本完全看不出改了啥） |
| `doc` | `*.docx/*.pdf` | 下载卡 + 查重工具推荐（§五 硬规矩） |

- **agent 侧只加一条约束**：产物用契约文件名。写进 `modulePreamble`，成本近乎零（技能已在用这些名）。
- **兜底**：认不出的产物照常进普通产出侧栏，绝不因为"没匹配上渲染器"就藏起来。

### 1.4 步骤状态：`_workflow.json`（服务端写，agent 只读）

```json
{ "module":"paper", "cur":"write",
  "done":["intake","deid","stats","figure","litreview"],
  "form":{ "studyType":"retrospective", "journalTier":"target", "ifMin":3, "ifMax":6, … },
  "gates":{ "refcheck":{"status":"fail","note":"2 条 DOI 对不上"} } }
```

- 放会话产物目录，下划线前缀 → 侧栏过滤不展示。
- **完成判据 = `emits` 的文件出现了**（服务端在已有的 `/api/files` 扫描上加一层匹配），
  不依赖 agent 自觉，也不给它篡改进度的机会。
- 作用：刷新/切会话能回到当前步；**表单值跨步继承**（立项卡填的目标期刊，第 7 步检索筛选、
  第 12 步排版预设直接复用，不用重填）。

## 2. 期刊指标（影响因子 / 分区）：先解决数据源

**现状核实**：仓库内无任何期刊指标数据；PubMed / Europe PMC 检索结果不含 IF、分区、JCR。
所以"勾选影响因子筛选"**目前物理上做不出来**。三条路：

- **官方 JCR IF 与中科院分区是授权数据，不能内置分发。** 直接排除。
- **A（推荐，默认档）：OpenAlex `sources` API** —— 免费、可批量、按 ISSN-L 关联，给
  `summary_stats.2yr_mean_citedness`（两年篇均被引，JIF 式指标）、`h_index`、`is_oa`、`is_in_doaj`。
  `enhanced_search.py` 已经在调 OpenAlex，扩一个 sources 查询 + 本地缓存即可。
  **UI 必须标注"期刊影响力（OpenAlex 两年篇均被引，非官方 JIF）"**，用四分位替代"分区"字样 ——
  否则等于凭空造一个 IF 数值，违反 §五 不虚构。
- **B（精确档）：用户上传本机构的 JCR / 中科院分区表**（xlsx，多数单位都有），按 ISSN 映射，
  UI 显示"依据你上传的 `<文件名>`"。合规且精确。

**建议 A + B**：默认用 A 作近似分级，用户传了 B 就切到 B 并标明来源。表单里的"影响因子区间 /
分区"控件在无 B 时显示为"期刊影响力区间（近似）"，别用"IF"这个词。

## 3. 各模块完整方案

### 3.1 SCI 论文（paper）— 最复杂，作样板

**首屏「立项卡」**

| 字段 | 类型 | 影响 |
|---|---|---|
| 研究类型 | 单选：回顾性队列/前瞻性队列/RCT/诊断准确性/病例对照/横断面/病例系列/体外·动物 | 前瞻·RCT → `novelty-check` **前置**做预注册锁；诊断准确性 → **跳过 `clinical-stats`**（AGENTS.md §三 表下注已写死此规则） |
| 稿件类型 | 单选：Original / Brief Report / Case Report / Letter | 章节模板与字数 |
| 已有材料 | 多选 + 上传：原始数据表 / 初稿 / 已有图表 / 伦理批号 / 注册号 / 参考文献库 | 勾了原始数据且未声明已脱敏 → **强制插入 deidentify 步**（§五 硬规矩） |
| 目标期刊 | 梯队三选一（reach / **target 推荐** / safety）+ 可填具体刊名 | 填了刊名 → 排版查该刊稿约；否则 `--journal generic-submission` |
| 期刊筛选 | 影响力区间 / 分区 / OA / APC 上限 / PubMed 收录 | 见 §2 |
| 输出语言 | 中文 / 英文 | 全程 |

**步骤链**（按研究类型裁剪）

| # | 步骤 | 技能 | 结构化输入 | 产物 | 渲染 |
|---|---|---|---|---|---|
| 1 | 立项确认 | — | 立项卡 | `_workflow.json` | 摘要卡 |
| 2 | 数据脱敏（条件） | deidentify | 文件选择 + 标识列勾选 | `deid_*.csv` `deid_report.md` | `deid` |
| 3 | 数据体检 + 分析 | data-analysis | **从真实表头下拉**选分组列/结局列/时间列/事件列/协变量 | `data_profile.md` `cleaning_log.md` `stats_*.csv` | `table` |
| 3b | 基线表（条件） | clinical-stats | 连续/分类变量勾选 | `table1.csv` | `table` |
| 4 | 完整性自查（闸·可选） | data-integrity | — | `integrity_report.md` | `integrity` |
| 5 | 出版级图 | nature-figure | 图类型勾选（森林/KM/火山/ROC）+ 期刊尺寸/DPI | `fig*.png/pdf` | `figure` |
| 6 | 新颖性 / 预注册 | novelty-check | 假设 + 主分析计划 | `novelty_report.md` / `preregistration.md` | 裁定卡 |
| 7 | 文献综述 | literature-review | 检索式 + 筛选条件（继承立项卡） | `evidence_table.csv` `evidence.md` | **`evidence`** |
| 8 | 撰写 | write-paper | 章节勾选 + 目标刊 | `manuscript.md` | 分章节稿件视图 |
| 9 | 引用核查（闸） | reference-check | — | `refcheck_report.md` | `refcheck` |
| 10 | 润色 | humanize-academic | 强度 + 是否保护引用文字 | `manuscript_humanized.md` | **`diff`** |
| 11 | 投稿前自审（闸） | peer-review | 角色勾选（方法学/统计/临床） | `review_report.md` | `review` |
| 12 | 排版出件 | render-docx | 期刊预设 | `manuscript.docx` | `doc` + 查重推荐 |

**回退**（对齐 AGENTS.md §二）：9 不过 → 回 8；11 不过 → 回对应上游；7 单薄 → 回 7；
10 动了引用文字 → 自动重跑 9。闸的渲染卡上直接给「返工」按钮，点击后自动把闸报告作为下一步输入。
同一闸连续失败 ≥2 次 → 停下问用户（§二 已定）。

### 3.2 综述撰写（review）

**首屏「选题卡」**：主题 / PICO、时间范围、语种、纳入研究设计（多选）、期刊筛选（见 §2）、
目标长度、输出语言、是否要 PRISMA-lite 计数。
**卡片底部固定一行提示**：需要双人筛选 / PRISMA / RoB / GRADE 强度 → 请到「自由对话」（见 §7）。

**步骤**：检索 → **证据表（渲染重点：文献卡片列表，逐条纳入/排除勾选，勾完回传为下一步输入）**
→ 全文获取（可选，`retrieval` 成功失败分栏）→ 成文 → 引用核查（闸）→ 润色 → 排版。

### 3.3 基金申报（grant）

**首屏「标书卡」**：资助渠道（国自然面上/青年/地区/省市/院级）、学部代码、**申请人身份**
（在读/博后/讲师/副高/正高 → 驱动 `topic-selection` 的申请人分流）、研究方向、已有工作基础
（上传代表作/预实验数据）、截止日期、各章字数上限。

**步骤**：领域扫描 → **选题（渲染重点：候选选题卡片 + 评分维度对比，用户选一个）** →
新颖性裁定 + 预注册 → 标书成文（立项依据/研究内容/技术路线/研究基础/工作条件，**分章节渲染 +
字数进度条**，`grant-proposal` 已有字数正则）→ 自审闸 → 排版。

### 3.4 文献研读（litread）

**首屏「研读卡」**：模式（快速扫描 / 深度研究 / 建小库问答）、主题、时间范围、来源多选
（Europe PMC / PubMed / 预印本 / Semantic Scholar / OpenAlex）、筛选条件、数量上限、
是否下全文、是否推 Zotero。

**步骤**：检索 → **证据表渲染** → 全文获取（**诚实分栏**：下到的入小库、没下到的列原因）→
小库 RAG 问答 或 综述成文 → 出件（本模块需补 `render-pdf-doc`/`render-docx`，见 §5）。

> 这是"输出的文献要渲染"收益最直接的模块。

### 3.5 数据统计与分析（stats）

**首屏「数据卡」**：上传数据 → **服务端读表头** → 勾分析类型（描述统计 / 组间比较 / 相关回归 /
生存分析 / ROC 诊断效能 / 方法比对 Bland-Altman·Passing-Bablok / 重复测量）→ **按勾选动态展开
变量映射，全部从真实表头下拉**。

> 变量映射用真实表头下拉是这个模块最大的单点收益：**"列名猜错/写错"是当前最高频的失败模式**，
> 用下拉从根上消灭。

**步骤**：数据体检 → 脱敏（条件触发）→ 分析 → 出图 → 完整性自查（可选）。
渲染：体检报告（缺失/异常/重复 ID 高亮）、结果表、图卡。

### 3.6 文稿核查与审校（refcheck）

**首屏「核查卡」**：上传稿件 + 勾核查项（假引用 / DOI / 撤稿 / 统计陷阱 / 数据完整性 / 格式）+ 严格度。
**步骤**：引用核查 → 同行评审自查 → 数据完整性（仅当附了数值表）。
渲染：三份报告合并成**一张问题清单**，按严重度五元组分组，逐条可标"已修 / 忽略"，导出核查报告。

### 3.7 文章润色（humanize）

**首屏「润色卡」**：上传稿件 + 目标（去 AI 味 / 语言润色 / 期刊风格对齐）+ 强度（保守/标准/激进）
+ 是否保护引用文字 + 输出格式。
**步骤**：润色 →（动了引用文字则自动触发 `reference-check` 兜底，§二 已写死）→ 排版。
渲染：**`diff` 对照视图是本模块核心**。

### 3.8 自由对话（chat）

不加表单，保持现状。新增一个角色：**系统综述 / Meta 的唯一入口** —— 欢迎页 chip 增加一条
"做系统综述 / Meta 分析"，并在综述模块的表单底部指路过来。

## 5. 与上一轮"技能白名单"方案的合流

本方案的 `steps[].skill` 展开即技能白名单，所以上一轮那几件事在这里一并落地：

- **补齐缺口**：paper 补 deidentify / clinical-stats / data-analysis / data-integrity /
  novelty-check / nature-figure；review 补 humanize-academic；litread 补 render-*。
- **`primary` 显式化**（§1.1）。
- **L4 bash 闸**：在 [server.mjs:1541](../web/server.mjs) 同处扫 `p.tool === "bash"` 的命令文本，
  命中 `.opencode/skills/<非白名单>` 即 abort。堵"顺手跑隔壁模块脚本"这条真实路径。
  口径与既有注释一致：**产品分权闸，不是对抗边界**。
- **`modulePreamble` 升级**：技能白名单 + **步骤链剧本 + 质量闸 + 产物契约文件名**。
  技能集变大后模块间区分度靠剧本而非白名单来维持。

## 6. 落地顺序

| 批次 | 内容 | 是否动 agent |
|---|---|---|
| M1 骨架 | `workflows.mjs` + `/api/modules/:id/workflow` + 首屏表单卡 + 任务卡拼接 + `_workflow.json` | 否 |
| M2 渲染器 | `evidence`（价值最高）→ `table`/`figure` → `retrieval` → `refcheck`/`review` → `diff`/`doc` | 否 |
| M3 期刊指标 | OpenAlex sources 抓取 + 缓存 + 用户上传分区表映射 | 技能侧小改 |
| M4 步骤机 | 逐步内联表单、产物反推进度、闸的返工按钮、表单值跨步继承、表头下拉 | 否 |
| M5 收口 | 白名单从 workflow 展开 + `primary` + L4 bash 闸 + 启动自检 + 测试 | preamble |

M1+M2 就能让"进模块先填卡、文献结果渲染成卡片"这两件用户最直观的事落地，且全程不动 agent。

## 7. 已定与未定

**已定**：系统综述 / Meta **不做模块**，只走自由对话。代价是用户点「综述撰写」永远拿不到
PRISMA/RoB 强度 —— 用 §3.2 表单底部的固定指路提示来兜，别让它成为哑失败。

**已按推荐实现**（分支 `feat/module-workflows`，worktree `D:\projects\sci-workflow-wt`）：

**实机联调抓到并修掉的 4 个真问题**（都是实现细节，设计没动）：
1. 综述模块脚注拼在结束标记之后 → `stripPreamble` 剥不掉，用户回看历史会看到自己"说"了一句没说过的话。
2. 「已脱敏」开关未填时是 `undefined`，条件写 `eq:false` 判不成立 → **脱敏步被整个剔掉**，
   而这恰是最该脱敏的情形。改成 `truthy:false`，方向 fail-safe。
3. `wfSyncDone` 在轮次收尾整体写回旧快照，会抹掉用户同一时刻提交的表单值。
4. 结构化产物渲染调的 `follow()` 是流式回调链的局部函数，作用域外调用会 ReferenceError。

**两轮 agent 审查（对抗性代码审查 + 扮演临床医生的界面走查）后又修的 16 处**，其中 3 个会让功能静默失效：
1. **上传先于对话 → 模块绑定丢失**。`/api/upload` 无 sid 时会现建会话且不带任何绑定，而
   stats / refcheck / humanize 的规定流程（先传文件再填表）必然走这条路 → 服务端判成自由对话，
   模块前言 / 技能闸 / 表单值 / 步骤条全部失效而 AI 照常回答。**哑失败，界面上完全看不出来。**
2. **全文获取卡把下到的全判成没下到**。真实状态是 `oa/pmc/arxiv/skip/fail/institutional`，
   而判据写成了关键词匹配 → 走 OA 渠道（默认、国内唯一路径）下成功的每一篇都进"未获取"栏，
   正好把「如实区分哪些下到了」那条铁律做反。
3. **报告红黄绿基本不可信**。子串匹配把"未发现严重问题"判成红、"the majority matched"判成红，
   真问题反而是灰；而这个计数在界面上当结论读，还会弹「返工」按钮把人推去返工没问题的稿子。

把英文稿翻译掉**；**只算样本量却被"数据文件必填"卡死**（唯一彻底走不通的功能）。
