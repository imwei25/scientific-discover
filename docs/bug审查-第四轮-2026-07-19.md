## 先厘清一个事实（影响所有严重度判断）

`render-compose.sh` 给每个用户挂的是**独占的** `<name>-uploads / -outputs / -ocdata` 三个卷，
所以**跨用户串数据在架构上不可能**。下面 A 组问题的真实影响一律是：
**同一用户跨会话互相覆盖 + 产物在"产出"侧栏消失 + 幽灵文件占配额**。

多处 SKILL.md 把威胁写成"多用户共享会 clobber"，措辞夸大了，容易让后续维护者误判严重度——已在改到的地方顺手改成"跨会话"。

### ①.10 补：systemd drop-in 的优先级坑（顺手搜残留时发现，同属我 D3 改动的余波）

`sci-manager.service` 的 `Environment=`（与 ①.5 同病，已改）。更要紧的是
`服务器架构.md:65` 记载：**生产机的 `ADMIN_PASSWORD`/`ONEAPI_URL`/`ONEAPI_TOKEN` 是放在
systemd drop-in `/etc/systemd/system/sci-manager.service.d/admin.conf` 里的**。

而 **drop-in 在主单元【之后】解析** → drop-in 的 `Environment=` 会**反过来盖住**我 D3 加的
`EnvironmentFile=-/etc/sci-manager.env`。后果分两面：
- **好的一面**：生产机现有的管理密码不会被我的改动弄丢，仍然生效。
- **坑的一面**：文档现在让人"编辑 `/etc/sci-manager.env`"，但在有 drop-in 的机器上**改了完全没效果、也不报错**——
  正是 ①.5 那个失败模式的翻版。

已做：
- `README-multiuser.md` 与 `DEPLOY.md` 都写清优先级（drop-in > env 文件 > 主单元 `Environment=`），
  并给出 `systemctl show sci-manager -p Environment` 查最终生效值的办法；
- `setup.sh` 增加检测：装的时候若发现 drop-in 里有 `Environment=`，**打印出来并说明它会覆盖 env 文件**，
  提示要么删 drop-in 对应行、要么继续在 drop-in 里改。**输出时把 `ADMIN_PASSWORD=` 的值遮成 `***`**
  （已实测遮蔽生效）——部署日志里不该出现明文管理密码。

## ②' 已按你的方案实现（2026-07-19 追加）—— 8 个脚本改为"默认写当前会话目录"

你提的方向对，但有个硬约束先说清楚：**脚本自己没法"猜"出当前是哪个会话**。
实测确认 `spawnOc()` 只调一次、**一个 opencode 进程服务所有会话**且 cwd 固定 `/app`，
`jobs` 按 sid 存、同容器可并发多会话；`opencode` 也**不注入任何会话相关的环境变量**。
所以会话目录只能由**主控从上面传下来**。据此实现成一条优先级链：

**`--outdir/--out` 显式参数 > `SCI_OUTPUT_DIR` 环境变量 > 当前工作目录（若已在 `outputs/<会话id>/` 内） > 报错中止**

- **关键改变：不再有"静默写共享 `outputs/` 根"这个兜底。** 四条线索都没有就**报错并给出三种可操作写法**，
  失败响亮且可恢复，而不是把产物悄悄写到一个用户看不见、还会跨会话覆盖的地方。
- **让它"默认就对"的那一环**：网关每轮注入的 preamble 里加了一行，直接告诉 agent
  `SCI_OUTPUT_DIR=outputs/<本会话id> python3 <脚本> ...`。于是 agent 不需要逐个脚本记 `--outdir`，
  加个前缀就全覆盖了——这就是你要的"为空时默认落到当前对话对应的目录"。
- 8 个 SKILL.md 里的 11 处命令示例也都加了该前缀；`CLAUDE.md`/`AGENTS.md` §五 补了全局规则，
  并写明 **PowerShell 不认 `VAR=x cmd` 前缀**（要先 `$env:SCI_OUTPUT_DIR=...`，或直接用 `--outdir`）。

**验证**（这次是真跑，不是静态看）：
- 8 个脚本全部 `py_compile` 通过；
- 从**真实源码**里抠出解析器做单测：显式参数 / 环境变量 / 显式压过环境变量 / cwd 在会话目录内 /
  无线索时中止 / `--out` 文件名拼接 / 显式 `--out` 原样——**7 项全过**；
- `table1.py` 端到端实跑两次：**不给线索 → 非零退出并打印可操作提示、共享根未被写入**；
  **给 `SCI_OUTPUT_DIR` → 退出码 0，产物落在 `outputs/ses_TESTSESSION/table1.csv`**，共享根依旧干净。

**过程中的一次教训**（记下来免得重犯）：第一版补丁我用 shell heredoc + JS 拼 Python 代码，
`\n` 在多层转义里被还原成真实换行，**把 8 个脚本的字符串字面量全写坏了**（`py_compile` 立刻报
unterminated string literal）。已 `git checkout` 全部还原后改用：补丁脚本落成文件（不经 shell 转义）、
且错误信息用 `chr(10)` 拼行、**完全不含反斜杠转义**。教训是——**多层转义拼代码不可靠，
要么落文件要么绕开转义**。

## ② 未修，理由充分（列给你判断）

**为什么这轮没动**：我核过文档里的实际调用——`table1.py`、`snowball.py`、`ground_claim.py`、`search.py`、
`verify_refs.py`、`enhanced_search.py` 的调用示例**都不传** `--out/--outdir`。所以把默认值改成"必填"会
**当场打断这些技能的文档化用法**；而要改对就得同时改 8 个脚本 + 约 20 处文档调用点，
且本机没有 opencode、**无法端到端验证技能真的还能跑**。
本会话已经三次因为"大范围改自己验证不了的东西"而引入新 bug（构建失败、容器 OOM、keep-alive 卡死），
这次不再赌。

**推荐方案（要我做就说一声）**：8 个脚本的默认值改为**必填**，同步更新约 20 处文档调用点，
让 agent 漏传时**当场报错**而不是静默写进共享根——失败响亮且可恢复，符合本项目一贯取向。

## ③ 需要你拍板（设计/产品取舍）

1. **要不要实现存储自动清理**：现在**唯一**的回收路径是用户手动删会话，即存储只增不减，
   free 档 1024MB 撞上限只是时间问题。但静默删用户的科研产物风险更大。
   选项：**(a)** 什么都不做，只在 UI 上把"存储快满"提示做醒目（当前已有 90% 提示）；
   **(b)** 实现 N 天未访问自动清理 + 提前告知；**(c)** 只自动清 `.preview` 等派生物（已做）而永不动用户产物。
   我倾向 **(c)+(a)**：派生物自动清，用户产物永不自动删，只提示。
2. **`outputs/` 根现存的 69 个散落文件**：它们是你的真实历史产物，**我没有删**。
   要不要归档到某个 `outputs/_legacy/` 下（既不占会话侧栏、也不丢数据）？
3. **fail2ban 会把整个出口 IP 封一小时**：`maxretry=5` 作用在 `/api/login` 的 401 上，
   而 manager 的**图形验证码错误也回 401** → 用户连看错 5 次验证码，全诊所被封 1 小时。
   这与第二轮已认定的"诊所几十人共用出口 IP"是同一群体（当时冷启动限流为此改成了两级桶，fail2ban 这层没跟上）。
   建议把验证码失败改回 400（不计入 jail），只让密码错误进 401。
4. **`ppt-master` 的 SVG 编辑器 workflow** 指示 agent 起 `http://localhost:5050` 并把 URL 报给用户，
   但容器只发布了 3000 端口 → 这个 URL 用户永远打不开。建议在多用户镜像里禁掉该 workflow，或标注"仅本地开发可用"。
5. **`monitor.sh` 的 OOM 检测几乎必然漏报**：`docker inspect .State.OOMKilled` 只在容器**当前处于被 OOM 杀死的停止态**
   时为真，而 manager 通常几秒到几分钟内就把它拉起来、标志被重置 → 5 分钟一次的 cron 大概率错过窗口。
   这正好盖住第三轮认定的最高危场景（LibreOffice 转换峰值打爆内存、连 opencode 一起带走）。
   建议改用 `docker events --filter event=oom` 落盘，或在 manager 的 `ensureUp` 里探到上次退出码 137 就上报。
   （属 plausible：本机无 docker，是按 docker 语义推断的。）
