# AGENTS.md 规则的来龙去脉（维护者备忘，不进模型提示）

2026-09-08 起，AGENTS.md 只留"规则本身"，每轮都进系统提示；"为什么这么定"的实验记录、日期、用户原话迁到这里。改规则前先看这里，别把已经用实验否掉的方案改回去。

## 判级铁律：需要用户补充的项一律 Minor
- 这类项不是稿件或分析本身的缺陷，只是信息还没到位。返工重做一遍也改不掉"用户还没给"，只会把交付卡死：§五 明令不许编造伦理批号，AI 协助的稿子几乎必然以"待补充"收尾，判成 Major 会让稿子永远出不了件。
- 「待补充」要分"一般待补"与"承重待补"两级：把"回顾队列里够不够主结局事件数"和"缺伦理批号"并列成一句"待你补充"，等于把一颗雷说成一粒灰。2026-08-24 实测用户原话："我倒希望它逼我一下"。

## 选题不由 AI 遴选（2026-08-18 定的产品立场）
用户给了研究问题 / 痛点时，AI 只做细化变体，候选 1 固定"按你写的原样推进"，选哪条由用户拍板。AI 自拟课题只在用户什么都没给时兜底。

## 为什么 idea-forge 在前、novelty-check 在后（2026-08 A/B 实验，别改回去）
- 先裁定臂：75 分钟扫描后方向一转，最终设计对 n=1050 的在研竞争试验全盲。
- 先锻打臂：25 分钟收敛，裁定对定稿问题做，当场抓到该试验。
- 结论：锻打内嵌快筛负责早杀与定向；novelty-check 对定稿科学问题做严格裁定 + 预注册锁——预注册锁本来就必须在问题冻结后做。

## novelty-check → grant-proposal 为什么是硬接口
立项依据的主体段与创新点都从 novelty-check 的《新颖性裁定记录》长出来（原固定文件名 novelty_verdict.md 已于 2026-09 取消，现落 novelty_assessment.md）。跳过它，立项依据必然写成文献罗列（"A 报道了…然而机制尚不清楚"），这是标书最常见的死法。用户直呼 grant-proposal 时该技能会自己补一轮针对性检索，但成本更高、覆盖更窄。

## Python 路径必须加引号
桌面版装在 `.../Niuma Science/bundle/app`，目录名里有空格；不加引号 bash 会从空格处把路径切成两半，报 `.../Local/Niuma: No such file or directory`。模型常把这个报错误判成"没装 Python / 没有 .venv"然后重建环境，白烧十几分钟还可能弄坏包版本——环境是随安装包 / 镜像装好的。自建部署 / 开发机首次初始化走仓库根的 `install.ps1` / `install.sh`。

## 产物为什么写裸文件名
网关建会话时把 opencode 的 `directory` 定到 `outputs/<会话id>/`，所以当前工作目录就是产物目录。拼 `outputs/` 前缀会写成 `outputs/<会话id>/outputs/...`；界面"产出"侧栏曾只列顶层文件不递归，用户看不到任何东西。脚本已对这种写法响亮报错并给出正确写法。
现在侧栏按目录折叠展示、多深都列得出来、能一键打包下载，所以"文件在更深的子目录里所以看不到"已不是事实；只剩一条要守：别把交付物埋在无谓的深层目录里。

## 问完就停下（§六 第 5 条）
用户没答之前你不知道他要哪个；替他选了再往下，等于把一个本该由他拍的方向变成既成事实，而返工的成本全落在他身上。技能文档里"按编号选项问清 X，然后做 Y"这类连写措辞曾多次被模型读成一步，所以主控里明写"读作两步"。

## question 工具为什么在配置层禁用
opencode 的 `question` 工具会弹交互式提问卡片，web 网关没有应答它的 UI，模型一旦调用整轮卡死（实测卡在"确认方向选择"那步）。提示词要求"用编号文本"模型仍会无视，故 server.mjs 的 enforceOcTools 全局 `tools.question=false`。

## 技能位置与分发
`.opencode/skills/` 是唯一源头，桌面安装包由 `desktop/bundle.ps1` 直接打包它，不再维护副本。AGENTS.md 由 `scripts/install_router.py` 镜像成项目根 `CLAUDE.md` 的受管块（供 Claude Code 读），不碰机器全局 `~/.claude/CLAUDE.md`，以免在无关项目触发路由。
