# 机构通道代测说明（请在学校 / 医院网络里的同事帮忙跑一次）

目的：确认软件能不能借用**你所在机构已订购的权限**，下载付费期刊的全文。
全程约 5 分钟。软件不会接触你的账号密码，需要登录时由你自己在浏览器窗口里完成。

---

## 一、开始前确认三件事

1. **人在机构网络里**：用单位的有线网或单位 WiFi（不要用访客 WiFi），**关掉个人 VPN / 加速器 / 代理**。
   这一条最容易出错：连着 VPN 时，出版商看到的不是单位的 IP，订阅权限不会生效。
2. **软件已更新**到开发者告诉你的版本（本次测试用到的功能是新加的）。
3. **准备 2–3 篇你确定能下的付费文章的 DOI**。这是这次测试最关键的一步，要求是：
   - 是**付费**期刊的文章：文章页上**没有** "Open Access" / "Free" 标记；
   - 你**刚刚在这台电脑、这张网上，亲手点开过它的 PDF**，确认能下；
   - 最好来自不同出版商（比如一篇 Elsevier / ScienceDirect、一篇 Wiley、一篇 Springer）。

   DOI 在文章页标题附近，形如 `10.1016/j.xxxx.2023.01.005`，只要 `10.` 开头的这一串，不要带 `https://doi.org/`。

## 二、在软件里发这句话

把下面的 DOI 换成你准备好的，发给软件：

> 运行全文下载技能的机构网络自检（--diagnose），追加这几篇我确定能下的文章做探针：
> 10.xxxx/aaaa、10.xxxx/bbbb、10.xxxx/cccc

## 三、运行过程中

- 会弹出一个**新的浏览器窗口**。它和你平时用的 Chrome 是分开的，没有你的书签，这是正常的。
- **如果你的单位要登录才能下文献**（CARSI、图书馆账号、WebVPN）：在这个新窗口里打开你平时用的图书馆 / WebVPN 地址，登录一次，然后回软件里再发一遍上面那句话。
- 如果窗口里出现"请验证你是真人"之类的勾选框，**请手动点一下**。软件不会自动过验证。
- 跑的过程中别关这个窗口。跑完后软件会自动把它关掉。

## 四、把结果发回来

跑完后，会话的产出栏里有两个文件：

- `机构网络自检报告.md`（给人看的）
- `机构网络自检报告.json`（详细记录）

**两个都发回来。** 请注意：报告里含有这台电脑的**出口 IP 和网络归属**（例如"某某大学"），
这是用来判断你是否真的在单位网络里的。介意的话，发之前可以先打开看一眼。

另外请顺手告诉我们：**你们单位平时是怎么下文献的**——在单位里直接就能下 / 要登录图书馆账号 / 用 WebVPN。

## 附：开发者如何读结果

先看报告第三节"逐篇探针结果"里 **「代测人提供（已知能下）」** 这几行：

| 结果 | 结论 |
|---|---|
| 这几行 ✅ | 机构通道**确实能下付费全文**，验证通过 |
| ❌，判定是「人机验证」 | 出版商的反爬拦截；让代测人在窗口里点一次验证后重跑 |
| ❌，判定是「要登录」 | 该单位不是 IP 授权；让代测人在窗口里登录后重跑。若 OA 对照组也是「要登录」且报告里列着 WebVPN 网关，说明本机记忆的旧网关串了，加 `--no-webvpn` 重跑 |
| ❌，判定是「网络层就不通」 | 网络问题，与权限无关 |
| ❌，判定是「页面挂着购买入口」或「找到了链接但下载失败」 | **本工具的问题**（代测人明明能下）。看 json 里该篇的 `landed_url` 和 `attempts`（逐次状态码 / 类型 / 字节数）定位 |

OA 对照组（PLoS）也失败 → 先解决网络问题，其余各行都不用看。
6 家固定探针只核实过"不是 OA"，核实不了对方单位订没订，它们全败**说明不了问题**。
