# sci-auth 部署与运维（服务器只做鉴权 + 网关）

> 配套：[改造方案](改造方案-服务器只做鉴权与网关-2026-07-28.md)
> 代码：`server/`（应用）、`ops/`（迁移与自检）、`deploy-auth/`（部署模板）

---

## 0. 这台服务器现在做什么

```
桌面客户端 ──HTTPS──> Caddy :443 ──> sci-auth 127.0.0.1:8090 ──> one-api / 上游模型
                                        │
                                        └── /var/lib/sci-auth/sci.db（唯一状态）
```

**只有三件事**：认人（账号与 key）、放行（LLM 转发 + 计量 + 额度）、管人（`/admin`）。
用户的会话、文件、产物全在客户端本机，**不进服务器**。

## 1. 全新安装

```bash
git clone <仓库> /root/sci-agent && cd /root/sci-agent
git checkout <发布 tag>
DOMAIN=your.duckdns.org sudo -E deploy-auth/setup.sh
```

`setup.sh` 会：装 Node 24（`node:sqlite` 要求 ≥22）→ 建 `/var/lib/sci-auth` → 生成 `/etc/sci-auth.env`（含随机 `ADMIN_PASSWORD` 与 `KEY_SECRET`，**管理台口令只在这一次打印**）→ 装 systemd 单元 → 装 Caddy 并写 Caddyfile → 装每日备份 cron → 起服务并跑一次自检。

**装完必做**

1. 编辑 `/etc/sci-auth.env` 填 `LLM_UPSTREAM_KEY`（不填 `/llm` 一律 503，客户端调不到模型）。
2. 云安全组只放行 `22/80/443`。`8090` 只听回环，**不要**放行。
3. SSH 改密钥登录、关掉口令登录。

**顺带把这两把技能侧的 key 也填了**（都可选，不填只是对应技能不能用；**桌面版没有别的途径拿到它们**）：

| 变量 | 给谁用 | 不填的后果 |
|---|---|---|
| `QWEN_API_KEY` | `mechanism-figure` 出机制示意图（走 `/img`） | 技能只能 `--dry-run` 做提示词、出不了图 |
| `OCR_SPACE_API_KEY` | `ocr` 图片识字（走 `/ocr`）。免费，邮箱注册即得：<https://ocr.space/ocrapi> | Windows 客户端退到本机自带的离线 OCR（能用但更不准）；服务器上跑则直接没得用 |

> **`/ocr` 这条路要求服务器版本不低于 `feat(ocr): 图片识字改走云端 /ocr 代理`（66199c78）。**版本旧于它时服务器上根本没有这个路由，客户端拿到的是 **HTTP 404**——不是 key 没配。`ocr.sh` 认得这个 404，会自动改用 Windows 内置 OCR 接着干，所以症状是"字还是出来了、但明显变差了"，容易被当成模型退步。升级服务器即可回到云端通道。

两把 key 都**只留在服务器**，与 `LLM_UPSTREAM_KEY` 同一条原则：客户端一个字节都拿不到，限额与审计都在服务端做。识字的限额分三层——档位里的 `tiers.ocr_daily`（每人每天，默认 20）、`OCR_DAILY_CAP` / `OCR_MONTHLY_CAP`（**全平台**每天/每月，默认 480 / 2400，对着免费额度留的余量；换付费 key 就都设 0）。为什么要有"全平台"这层：OCR.space 按 key + 出口 IP 计额，走代理后所有用户都从这台服务器一个 IP 出去。

## 2. 日常运维

| 事 | 命令 |
|---|---|
| 看状态 / 日志 | `systemctl status sci-auth` / `journalctl -u sci-auth -f` |
| 改配置后生效 | 编辑 `/etc/sci-auth.env` → `systemctl restart sci-auth` |
| 改管理台口令 | `ops/set-admin-password.sh`（交互输入；`--random` 随机生成）|
| 手动备份（含演练） | `ops/migrate-export.sh` |
| 只做一次自检 | `DB_FILE=/var/lib/sci-auth/sci.db SECRETS_FILE=/etc/sci-auth.env ops/selftest.sh` |
| 验证某个备份能恢复 | `ops/rehearse-restore.sh /var/backups/sci-auth/xxx.tar.gz` |
| 上线前检查脚本可执行位 | `ops/check-exec-bits.sh` |

**每日备份**已由 `setup.sh` 装成 cron（3:30 导出、保留 14 天）。它每次都会**自动做一次影子恢复演练**：把刚生成的包在临时目录 + 临时端口上真的恢复并起起来，`/healthz` 通过才算数。演练不过 → 包被改名 `.UNVERIFIED` 且 cron 任务以非零码退出。

> 强烈建议再加一条异地同步：`rsync -az /var/backups/sci-auth/ backup-host:/backups/`。同盘备份挡不住整机损坏。

## 3. 迁移到新机器

```bash
# 旧机（不必停服，SQLite 用 VACUUM INTO 热备）
MIGRATE_PASSPHRASE='一个长口令' ops/migrate-export.sh
scp /var/backups/sci-auth/sci-auth-backup-*.tar.gz  newhost:/root/

# 新机
git clone <仓库> /root/sci-agent && cd /root/sci-agent && git checkout <同一个 tag>
DOMAIN=your.duckdns.org sudo -E deploy-auth/setup.sh
sudo systemctl stop sci-auth
MIGRATE_PASSPHRASE='同一个口令' ops/migrate-import.sh /root/sci-auth-backup-*.tar.gz
sudo systemctl start sci-auth
```

包里有什么：`sci.db`（用户/档位/用量/审计）、`secrets.env`（`/etc/sci-auth.env`，设了口令则加密）、`one-api-data` 卷（装了 one-api 才有）。Caddyfile / systemd 单元 / fail2ban 全部由仓库模板生成，**不进包**。

**导入的安全次序**（每条都实测过）：
1. 先校验包内 sha256 与密钥可解密，**任何一项不过就在动数据之前中止**，本机数据不被触碰；
2. 现有库先备份成 `sci.db.bak-<时间>` 再替换；
3. one-api 卷先移到 `.rollback` 再解包，失败原样还回去；
4. **绝不无条件删 `.rollback`** —— 上次导入若在"移开之后、解包之前"被打断，数据唯一副本就在里面；
5. 导入完自动自检（起实例 + `/healthz` + 鉴权闸），不过就明确报错、别急着启服务。

⚠ **`KEY_SECRET` 必须跟着搬**。它不一致 = 全体客户端已签发的 key 立刻失效、所有人被迫重新登录。

⚠ **`DATA_DIR` 能改到别处，`one-api-data` 卷不能**：卷是按固定名字恢复的，所以在同一台机上做「模拟新机」的导入演练时，即便把 `DATA_DIR` 指到临时目录，**one-api 卷仍会被真的覆盖**（内容来自同一个包，通常无害，但要心里有数）。想完全不碰它：`ONEAPI_VOLUME=some-scratch-name ops/migrate-import.sh <包>`。纯粹只想验证包能不能恢复，用 `ops/rehearse-restore.sh` —— 它全程只读，绝不碰任何卷。

## 4. 账号发放流程（当前不做手机号注册）

1. 管理员登录 `https://<域名>/admin`（口令 + 图形验证码）。
2. 「+ 新建账号」填姓名、登录名、医院、职位、档位 → 提交。
3. 页面**只显示这一次**初始口令（12 位强随机）。当场复制，通过 OA / 企微转交给用户。库里只存 scrypt 哈希。
4. 用户在客户端用「登录名 + 初始口令」登录 → 被强制改密 → 改完才拿到可用的 key。

**找人**：搜索框支持用姓名里的**任意一个字或两个字**过滤，**姓氏优先**——输「张」，姓张的排最前，名字里带张的排后面；「欧阳」「小明」同样可用。也能用登录名 / 手机号 / 医院找，但排在姓名命中之后。

**管控**：改档位、停用、重置口令、重置 key —— 任一操作都会让该用户**已签发的 key 立刻失效**（`key_epoch++`），不必等票据自然过期。（只调额度**不**吊销：额度不在票据里，网关每单现查库，改完下一次请求就生效，不用把人踢下线。）

**按条件筛人 + 批量调整**（面向"给这一批人开通某个技能"这类成批的运营动作）

1. 列头的 **▾** 就是筛子，用法同 Excel：**档位 / 状态 / 技能授权 / 今日用量 / 最近活跃**各自勾选，**同一列多选是"或"、不同列之间是"且"**；「姓名 / 账号」列的 ▾ 里还能按**医院包含**筛。「技能授权」列除了授权形态（跟随档位 / 全部允许 / 自定义白名单），还能按**"能用这些技能"**筛（多选时要求全部满足）。筛选一律在**全体账号**上算，不是只筛当前这一页。
2. 勾选左侧复选框（表头那个只勾**本页**；命中超过一页时表格下方有「选中全部命中的 N 人」）。选择**跨页保留**。
3. 出现批量操作条后：**批量技能授权**（三态与单人编辑完全一致）、**批量改档位**、**批量停用 / 恢复**。
4. 弹窗里会**列出将要改的人名**并要求二次确认；一次最多 **500 人**（超了直接报错，请先缩小筛选范围）。审计表里**逐人一条** `user.update` + 一条汇总 `user.bulk_update`，事后按人能查到。

> 批量的三项（档位 / 技能 / 状态）都会吊销这些人的 key，他们需要重新登录。技能授权改完后客户端的模块卡片：最迟**下次登录**跟着变；正常情况下客户端 5 分钟一次的公告轮询会顺带同步档案，几分钟内自己就变了（详见 `docs/改造方案-…-2026-07-28.md` §3.3 的落地现状表）。

## 5. 客户端对接（给桌面端的接口契约）

所有接口走 HTTPS，JSON。错误统一是 `{"ok":false,"error":{"code":"...","message":"..."}}`，**客户端按 `code` 给提示，别把 message 之外的东西直接甩给用户**。

| 接口 | 说明 |
|---|---|
| `POST /api/auth/login` | `{username,password}` → `{access, refresh, expiresAt, scope, mustChangePassword, profile}` |
| `POST /api/auth/refresh` | `{refresh}` → 新的一对（**refresh 用一次即废，必须存新的**） |
| `POST /api/auth/password` | `{oldPassword,newPassword}`，首次强制改密也走它 |
| `POST /api/auth/logout` | `{refresh}` |
| `GET /api/me` | 档位、默认模型、**可选模型清单**、技能白名单、额度与用量（美元 `limits/usage` + 积分视图 `quota`） |
| `GET /api/quota` | **剩余积分**（轻口，客户端顶栏用）：`{creditUsd, daily:{limit,used,remain,unlimited,pct,limitUsd,usedUsd}, monthly:{…}, dayResetAt, monthResetAt}`。只读两行汇总，每轮对话结束刷一次、平时低频轮询 |
| `GET /api/queue` | 排队状态：`{limit, running, waiting, waitingMine, position, etaMs, waitedMs, rateLimited}`。只读内存，可每 2 秒问一次 |
| `GET /api/notice` | 最新一条公告 + `digest`（近半年每条的 `{id, level, createdAt}`，**不含正文**，用来算未读红点）+ `needUpgrade`。几分钟问一次 |
| `GET /api/notices` | 公告列表（近半年、没撤下的，**带正文**）。用户点开公告面板时才拉 |
| `GET /api/web/latest` | 界面包最新版元数据（version/sha256/size/changelog/files）。带 `X-Web-Version` 上报本机版本 |
| `GET /api/web/pack?version=` | 下载界面包 zip；响应头 `x-pack-sha256`，只发没撤下的版本 |
| `POST /api/feedback` | 提交用户反馈。body 是 zip（`feedback.json` + `files/**`），单次 ≤32MB、单附件 ≤8MB |
| `POST /llm/v1/chat/completions` | OpenAI 兼容。`Authorization: Bearer <access>` |

**约定**

- **baseURL 用 `https://<域名>/llm` 或 `https://<域名>/llm/v1` 都行**，网关会消掉重复的 `/v1`。
- `scope=pwchange` 的票据只能调 `/api/auth/password`，别的一律 403 `PASSWORD_CHANGE_REQUIRED`。
- 客户端每次请求带 `X-Client-Version`（服务端记录，后台可见）；调技能时带 `X-Skill: <技能id>`。
- 请求体里的 `model`：**在 `/api/me` 给的 `profile.models` 清单里就照办，不在清单里一律被打回该档位的默认模型**（静默，不报错——老客户端照旧能用）。清单随档案下发，管理员在后台加了模型，客户端刷新一次档案就能用上，不必重装。
- 流式调用正常传 `stream:true` 即可，`stream_options.include_usage` 由服务端注入。
- **公告是列表不是横幅**：客户端把 `/api/notice` 的 `digest` 跟本地"已读到哪个 id"比，只在入口上标未读数（**别自动弹出来打断人**）；用户点开时才拉 `/api/notices` 显示正文。桌面版就是这么做的（顶栏「公告」按钮 + 面板），见下面 §6.2。
- **并发满时请求会在服务端排队**（响应头迟迟不回就是在等位）。客户端别自己重试、别加超时——
  轮到就自然开始；期间轮询 `GET /api/queue`，把 `position` / `waiting` 显示成「正在排队，前面还有 N 个」。
  桌面版已经这么做了（本机网关每 2 秒探一次，推给前端的 chat 流），见 `web/server.mjs` 的「云端排队感知」。

**错误码**

| code | HTTP | 客户端该怎么办 |
|---|---|---|
| `BAD_CREDENTIALS` | 401 | 提示账号或口令不对 |
| `PASSWORD_CHANGE_REQUIRED` | 403 | 跳到改密页 |
| `KEY_EXPIRED` | 401 | 静默用 refresh 换新票据；换不到再引导登录 |
| `KEY_REVOKED` | 401 | 提示「账号信息已变更，请重新登录」 |
| `ACCOUNT_SUSPENDED` | 403 | 提示「账号已停用，请联系管理员」 |
| `QUOTA_EXCEEDED` | 429 | 用 `error.scope`（daily/monthly）给出明确文案。`message` 已经是**积分口径**的整句话（"今日积分已用尽（上限 30 积分），明日 0 点(UTC)恢复"），直接显示即可；`used/limit` 仍是美元（运维/老客户端读），`usedCredits/limitCredits` 是积分 |
| `SKILL_NOT_ALLOWED` | 403 | 提示该档位未开通此技能 |
| `UPSTREAM_UNAVAILABLE` | 502 | 提示稍后重试 |
| `UPSTREAM_UNCONFIGURED` | 503 | 提示联系管理员（服务端没配上游 key） |
| `RATE_LIMITED` | 429 | 按提示等待 |
| `UPSTREAM_RATE_LIMITED` | 429 | 上游在限速（不是用户的额度问题）。按 `error.retryAfterMs` 等一会儿再试 |
| `QUEUE_TIMEOUT` | 503 | 排队等到上限仍没轮到。提示「此刻人多，稍后重试」，别立刻重发 |
| `QUEUE_FULL` | 503 | 队都排满了。同上，等几分钟 |

## 5.1 客户端的路由选择（桌面版）

客户端**默认走云端网关**（`OC_GATEWAY_URL` 指到 `https://<域名>/llm`，`OC_GATEWAY_KEY` 就是登录换来的 access key）。用户在对话框输入 `api-config` 可以改成走自己的 API；弹窗顶部始终显示当前走哪条路，走自定义时会出现**「切回云端网关」**按钮，一键回到平台统一调度。

- 走网关时弹窗**不回填**网关地址与模型名——否则用户容易以为那是自己的配置，一按保存就把网关地址连同自己的 key 存成自定义路由。
- 走自己的 API 时**不计入平台额度**（请求根本不经过服务器），这一点在弹窗里明说了。
- 切换两个方向都会重启后台模型进程；有轮次在跑时会先弹二次确认。

## 5.2 模型供应商与模型目录（后台「模型供应商」页）

加一家供应商、加几个模型、勾进档位——这三步做完，**打包版客户端不用重装、不用重新登录**就能在顶部 🧠 里选到新模型。

**怎么加**（`/admin` → 模型供应商）

1. **+ 新增供应商**：填键（如 `siliconflow`）、显示名、API 地址（OpenAI 兼容端点，没写 `/v1` 会自动补）、API Key。可先点「测试连通」——它调这家的 `GET /models`，通了会报出模型个数。
2. **+ 模型**：从这家拉模型列表勾选批量接入；这家不实现 `/models` 就用「+ 新增模型」手填。**接入后务必逐个把单价改成这家的真实价**（默认填的是 env 里的全局价）。
3. **档位页**：把模型勾进对应档位的「允许用户切换的模型」。默认模型永远可用，不用重复勾；一个都不勾 = 该档位不能换模型。

**几条要点**

- API Key 只存在服务器库里（`sci.db`，0600），转发时才贴，**绝不下发客户端**；后台也只显示「有没有」，不回显。
- **同一个对外模型名可以挂多家**（各建一行，填各自的上游真实名与单价）：优先级数字小的先用，这家不行且**响应头还没发出去**时自动落到下一家。头发出去之后不再切——已经吐给客户端的字节收不回来。
  - 「这家不行」= 连不上、所有 5xx，外加 **401 / 402 / 403 / 408 / 409 / 429**——即"密钥失效、**余额不足/欠费**、超时、限流"这类换一家就能好的。
    2026-07-29 就栽在这上面：主供应商余额耗尽回 **402**，而当时只对 5xx 切家，备用明明是好的却一次没被用上。
  - **400 / 404 / 413 / 422 不切家**，原样透传：那是请求本身的问题（模型名不对、体过大…），换谁都一样，透传才有诊断价值。
- **单价按行独立**。这解决了老架构「`COST_*` 全局一张表 + 多供应商 = 账静默偏」的病根。
- **目录里没有的模型名照旧走 env 的 `LLM_UPSTREAM_*` + `COST_*`**。所以老部署一字不改也照常跑；要把它也纳入统一管理，就在后台把它加成一家供应商。
- 停用模型、停用供应商、删供应商，都会**立刻**把该模型从用户的可选清单里摘掉（网关每一单现查库）。
- 改档位的**可选模型清单不吊销 key**（它不在票据里，网关现查现判）；改额度/默认模型/技能仍会吊销该档全体用户的 key。

**这和「上游通道」页（one-api）是两套东西**：那一页管的是 one-api 里已有的渠道（只能调优先级/停启用/测试），这一页是本进程自己的供应商表。两者可以并存——把 one-api 当成其中一家供应商加进来即可。

## 6. 计量与计费口径

- 计量**只在服务端做**。上游 key 不下发给客户端，所有模型调用必须经 `/llm`。客户端自报用量不作数（见改造方案 §3.1）。
- 成本 = 新鲜输入 × 输入单价 + 缓存命中输入 × 缓存单价 + 输出 × 输出单价，单位 USD/百万 token。
  单价来自**命中的那一行模型目录**；目录里没有这个模型名时才用 env 的 `COST_INPUT/COST_OUTPUT/COST_CACHE_READ`。
- 用量明细记的是**对外模型名**（用户点的那个）+ **实际服务的供应商**（`provider` 列，空 = env 兜底上游）。上游改过名的那家回的是它自己的名字，不作为账目口径。
- 日/月额度都在**打上游之前**预检，超限直接 429，**一个字节都不会再发出去**。
- UTC 日切 / 月切（与旧架构一致，跨日自动清零）。

⚠ **上线后先对一次账**：把 `/admin` 看板的累计用量与供应商账单比一比。单价配错会让额度系统性偏，且偏得很安静。

### 6.0 积分（用户看到的额度单位）

后台的一切——档位额度、用量明细、对账、审计——**照旧全是美元**。只有下发到客户端的那一层换算成
**积分**：`1 积分 = CREDIT_USD 美元`（默认 `0.01`，即 `$0.30/天 = 30 积分/天`）。换算写在
`server/lib/credits.mjs`，`/api/quota` 与 `/api/me` 共用同一份视图，客户端不做任何除法。

- **为什么**：`$0.087 / $0.30` 没人算得清还剩几轮；整数积分才是用户能用的信息。
- **取整一律朝"用户少赚"的方向**：上限下取整、已用上取整、`remain = floor(上限 - 已用)`。
  所以绝不会出现「界面还剩 1 积分、一发消息就被 429」。日/月两条线各算各的，**哪条先见底就先挡**。
- **上限 0 = 不限**：`unlimited:true`、`remain:null`（不是 0——0 会被前端当成"用尽"）。
- **改 `CREDIT_USD` 不改任何真实额度**，只改用户看到的数字大小；但用户会以为额度被动了，改前顺手发条公告。
- 后台「档位」页每个额度旁边会显示"= N 积分"，编辑弹窗里边填边看，省得保存完再去客户端核对。
- 客户端哪里显示：聊天页顶栏常驻「剩余积分 日 X · 月 Y」（**每轮对话结束自动刷新**，用掉 ≥90% 变红，
  云端连不上时保留上一次读数并标「·未更新」）、工作台首屏账户区、账号面板的「今日/本月积分」。

## 6.1 并发与排队（后台「看板 → 并发与排队」）

上游按并发 / RPM 限速。十几个人同时让 agent 跑长任务，打过去就是一片 429，而 429 到客户端上
**只表现为「这一轮没输出」**——用户既不知道发生了什么，也不知道该等多久，往往还会连点重发把队排得更长。

所以网关自己加了一道并发闸：**超出上限的请求不打上游，先在服务端排队等位**，客户端问 `/api/queue`
就能拿到「你排第几、大概还要多久」并显示出来。

| 设置项 | 含义 | 怎么定 |
|---|---|---|
| 全站并发上限 | 同时最多几个请求在打上游。`0 = 不限`（默认，与加这层之前完全一致） | 看上游套餐允许的并发数，取**略小于**它 |
| 单用户并发上限 | 一个账号同时最多几路。`0 = 不限` | 防一个人把位子占满；档位页可逐档覆盖 |
| 最多排多少个 | 排满后新请求直接 503 `QUEUE_FULL` | 默认 200，基本够 |
| 最长等待 | 等到这么久还没轮到 → 503 `QUEUE_TIMEOUT`。`0 = 一直等` | 默认 5 分钟 |

- 改动**立刻生效**，不用重启（重启会把所有在飞的长任务连根拔掉），也不会踢任何人下线。放宽上限时
  队里的人当场被放出去。值落库（`meta.llm_limits`），重启后仍是新值；env 里那几行只作为**首次启动的初值**。
- 排队是**按到达顺序**（FIFO），但队首若受自己的单用户上限所限，会跳过他先放后面能走的人——否则
  一个人跑长任务就把全站堵死。
- 上游回 429 时：有备用供应商就自动切家；无处可切才回 `UPSTREAM_RATE_LIMITED`，同时后台这一页与
  客户端都会显示「上游限速中」。
- 页面上还有当下的实时队况（在跑几个、排几个、队首等了多久、平均单次耗时、此刻谁在占位）。

⚠ **改「最长等待」时同步看一眼 Caddy**：排队期间响应头还没发出，这段时间与之后的推理时间
**一起**算在 Caddy 的 `response_header_timeout` 里（`deploy-auth/Caddyfile.example` 现为 `15m`）。
最长等待配到接近它，就会出现"排队快轮到了却被 Caddy 以 504 掐掉"，而日志里只有一个看不出原因的 504。
老部署的 Caddyfile 里这个值可能还是 `5m`，若要把最长等待设到 3 分钟以上，先把它调大。

## 6.2 公告（后台「看板 → 公告」）

发一条 = 新增一行，**客户端能往回翻半年**。

- 客户端不再弹横幅。顶栏有个「公告」按钮，有未读就标个数字红点（紧急级标红），**默认折叠、
  不打断人**；点开是近半年的列表，打开即视为全部已读。这解决的是老设计那个真实抱怨：
  横幅点一次「知道了」就永远找不回来，第二天想确认"维护到底几点"只能问管理员。
- 「撤下」= 客户端立刻不再显示，但后台这一页仍列着（你要能查到自己发过什么）；「删除」才是真删。
- 「编辑」改的是**同一条**（id 不变）——错别字改完不会把已读的人重新标成未读。有新消息就发新的一条。
- **保留期 180 天**，每天扫一次（`NOTICE_KEEP_DAYS` 可改，最小 7 天）。列表接口按同一个天数过滤，
  不会出现"后台还列着、客户端翻不到"。
- 「最低版本」照旧：比它旧的客户端在那条公告下面多一行升级提示 + 下载链接；认不出版本号的构建
  （开发机的 `dev`）一律不催。

升级注意：老库里 `meta` 那一条**发布中**的公告会在首次启动时自动搬进新表（只搬一次，时间沿用原
`updatedAt`），所以升级当天挂着的公告不会凭空消失，用户也不会一上来就看到一条"刚刚发布"的未读。

## 6.3 界面包：小改动不用重发安装器（后台「界面包」）

改个文案、调个样式、修个按钮，原先要重新打包整个安装器再催所有人重装。现在把 `web/` 下的
**前端静态资源**打成一个版本包发布，客户端提示「更新并刷新」，点一次就换过去了。

- **不重启任何进程**：网关每次请求都从磁盘现读 `index.html`，所以装完刷新页面就是新界面，
  正在跑的任务一个都不会被打断（这正是它与技能包最大的区别）。
- **能发什么**：`web/` 下的 `.html/.css/.js/.svg/.png/.ico/.woff2` 等静态资源（顶层 + 一层子目录）。
- **发不了什么**（服务端发布闸与客户端安装器两道都拦）：
  - `web/*.mjs` —— 本机网关的服务端代码，换它要重启网关、坏了客户端直接起不来；
  - `.json` —— `sessions-meta.json` 是用户的会话归属、`package.json` 是依赖清单，冲掉哪个都是事故；
  - `node_modules/`、越界路径（`../`、绝对路径、盘符）。
  这些仍然只能重新打包安装器。
- **两条发布通道**：①「从仓库发布」（推荐）—— 服务器同步 git 检出、自动排版本号、预览要发哪些
  文件再发；②「手动上传」zip 兜底。同一版本号不许重发。
- **出问题怎么办**：后台把该版「撤下」（客户端立刻不再提示、也下不到），用户在「云端账号」面板
  一键回退；本机留最近 5 版，**出厂版永不清理**，最差也能退回"刚装完"的界面。
- 后台能看到客户端的界面版本分布（客户端每次问更新时带 `X-Web-Version` 上报）。

⚠ **鸡生蛋**：这套机制本身在客户端里，所以只有装了**含此机制的安装包**之后的客户端才能收到界面包。
第一次仍要发一版安装器；之后的前端小改动才走这条路。

**怎么让"以后真的只发前端"**：前端够不到云端（access key 在本机网关手里），所以每加一个
"前端 + 云端新接口"的功能本来都要改 `web/server.mjs`（发不了）。为此本机网关留了一个通用转发口
`POST /api/cloud/call {path, method, body}`：只准打本平台 `/api/*`、**排除 `/api/auth/*`**（凭证类
各有专门处理，绕过去会把登录态弄坏）、路径含 `..` 或以 `//` 开头一律拒。有了它，新功能只要
"云端加接口 + 前端调 `/api/cloud/call`"，客户端就不必重发。

## 6.4 用户反馈（后台「用户反馈」）

用户在客户端选中某次会话 → 点赞/点踩 + 写一句说明 + **可选**勾几个产出文件 → 提交给管理员。

- **带完整对话**：只说"这次不好用"管理员无从复现，所以提交时把那次会话的整段对话一并交上来
  （含时间戳与每轮走了哪些技能）。
- **隐私**：产出文件**默认一个都不勾**，弹窗顶部明写"管理员会看到整段对话"，涉及患者信息时
  由用户自己判断是否先脱敏。服务端只存不看；导出 HTML 全程转义。
- **后台**：按状态/赞踩/关键词筛选，点开看完整对话与附件，标记已处理 / 重开 / 删除（删除连附件一起清）。
- **导出 HTML**：单条或"当前筛选"批量，产出一个自带样式的单文件 HTML，离线可看、可转发存档。
- 上传是一个 zip（`feedback.json` + `files/**`）：单次 32MB、单附件 8MB，附件名消毒，
  下载只认库里记着的文件名。附件落在 `DATA_DIR/feedback/<id>/`，**迁移/备份别漏这个目录**。

⚠ **老部署要改一行 Caddy**：站点块里的 `request_body max_size 2MB` 是全站生效的，用户随手带一张
森林图（几 MB）就会被 Caddy 以 413 打回，而且那是 Caddy 自己的错误页、客户端拿不到结构化提示。
`deploy-auth/Caddyfile.example` 已给 `/api/feedback`（40MB）与两个上传口（80MB）单独放宽，
升级时把这两段 `handle` 抄过去，别把全站默认值改大。

## 7. 排障

| 症状 | 先看 |
|---|---|
| 服务起不来 | `journalctl -u sci-auth -n 50`。Node < 22 会在启动时明确报错 |
| 客户端一直 503 | `/etc/sci-auth.env` 的 `LLM_UPSTREAM_KEY` 没填 |
| 全员突然要重新登录 | `KEY_SECRET` 变了（换机器没带过来 / 被改写） |
| 某人一直 `KEY_REVOKED` | 刚被改过档位/额度/口令，让他重新登录即可 |
| 后台打不开（404） | `ADMIN_PASSWORD` 为空 = 管理台整个关闭 |
| 管理台口令怎么都不对 | 多半是手改时值后面跟了行尾注释（`EnvironmentFile` 不剥它），或首尾带了粘贴进来的空白。用 `ops/set-admin-password.sh` 改，它会挡住这几种 |
| 流式输出一卡一卡 | Caddy 少了 `flush_interval -1` |
| 人一多就一片「这轮没输出」 | 上游在限速。到后台「并发与排队」把全站并发上限设成略小于上游套餐的并发数——超出的会排队而不是被上游打回 |
| 大家都说在排队、其实没人在跑 | 后台这一页看「正在调用上游」：若长期非 0 而队里一直在等，说明有请求的并发位没还回来（`grep -E "排队|放行" journalctl -u sci-auth`），重启进程可复位 |
| 客户端一直「正在云端排队」但队里是空的 | 客户端探到的是几秒前的状态，最长 15 秒后自动消失；持续如此看本机网关日志 `[cloud] 云端正忙` |
| 用户选了模型却像没换 | 该模型没勾进他所在档位的允许清单 → 网关按设计打回默认模型。看 `journalctl -u sci-auth \| grep 打回` |
| 客户端只出一个**空气泡**、没有任何提示 | 上游把这一轮判错了（余额不足 402 最常见）。**客户端 ≥ 本次版本已会如实弹「⚠ 上游模型账户余额不足…」**；仍是空白说明客户端是老版本。服务端侧看 `journalctl -u sci-auth \| grep -E "切下一家\|上游错误"` |
| 明明配了备用供应商却没生效 | ① one-api 的「上游通道」页：**两条通道只有挂了同一个模型名才互为备用**，优先级只在同名之间比；② 本进程的「模型供应商」页：备用要与主用**同一个对外模型名**、优先级数字更大 |
| 加了模型客户端看不到 | ① 没勾进档位；② 客户端还没刷档案（账号面板点「刷新」，或重启客户端）；③ 供应商/模型被停用 |
| 账目对不上某家 | 后台「模型供应商」页逐行核单价；用量明细的 `provider` 列能看出每一单实际打给了谁 |
| 备份 cron 报错 | 看 `/var/log/sci-auth-backup.log`；有 `.UNVERIFIED` 说明演练没过，**那个包不能用** |
