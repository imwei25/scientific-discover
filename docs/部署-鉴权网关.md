# sci-auth 部署与运维（服务器只做鉴权 + 网关）

> 配套：[改造方案](改造方案-服务器只做鉴权与网关-2026-07-28.md)
> 代码：`server/`（应用）、`ops/`（迁移与自检）、`deploy-auth/`（部署模板）

---

## 0. 这台服务器现在做什么

```
桌面客户端 ──HTTPS──> Caddy :443 ──> sci-auth 127.0.0.1:8090 ──> one-api / 上游模型
                                        │
                                        └── /var/lib/sci-auth/sci.db（唯一状态）
```

**只有三件事**：认人（账号与 key）、放行（LLM 转发 + 计量 + 额度）、管人（`/admin`）。
用户的会话、文件、产物全在客户端本机，**不进服务器**。

---

## 1. 全新安装

```bash
git clone <仓库> /root/sci-agent && cd /root/sci-agent
git checkout <发布 tag>
DOMAIN=your.duckdns.org sudo -E deploy-auth/setup.sh
```

`setup.sh` 会：装 Node 24（`node:sqlite` 要求 ≥22）→ 建 `/var/lib/sci-auth` → 生成 `/etc/sci-auth.env`（含随机 `ADMIN_PASSWORD` 与 `KEY_SECRET`，**管理台口令只在这一次打印**）→ 装 systemd 单元 → 装 Caddy 并写 Caddyfile → 装每日备份 cron → 起服务并跑一次自检。

**装完必做**

1. 编辑 `/etc/sci-auth.env` 填 `LLM_UPSTREAM_KEY`（不填 `/llm` 一律 503，客户端调不到模型）。
2. 云安全组只放行 `22/80/443`。`8090` 只听回环，**不要**放行。
3. SSH 改密钥登录、关掉口令登录。

## 2. 日常运维

| 事 | 命令 |
|---|---|
| 看状态 / 日志 | `systemctl status sci-auth` / `journalctl -u sci-auth -f` |
| 改配置后生效 | 编辑 `/etc/sci-auth.env` → `systemctl restart sci-auth` |
| 改管理台口令 | `ops/set-admin-password.sh`（交互输入；`--random` 随机生成）|
| 手动备份（含演练） | `ops/migrate-export.sh` |
| 只做一次自检 | `DB_FILE=/var/lib/sci-auth/sci.db SECRETS_FILE=/etc/sci-auth.env ops/selftest.sh` |
| 验证某个备份能恢复 | `ops/rehearse-restore.sh /var/backups/sci-auth/xxx.tar.gz` |
| 上线前检查脚本可执行位 | `ops/check-exec-bits.sh` |

**每日备份**已由 `setup.sh` 装成 cron（3:30 导出、保留 14 天）。它每次都会**自动做一次影子恢复演练**：把刚生成的包在临时目录 + 临时端口上真的恢复并起起来，`/healthz` 通过才算数。演练不过 → 包被改名 `.UNVERIFIED` 且 cron 任务以非零码退出。

> 强烈建议再加一条异地同步：`rsync -az /var/backups/sci-auth/ backup-host:/backups/`。同盘备份挡不住整机损坏。

## 3. 迁移到新机器

```bash
# 旧机（不必停服，SQLite 用 VACUUM INTO 热备）
MIGRATE_PASSPHRASE='一个长口令' ops/migrate-export.sh
scp /var/backups/sci-auth/sci-auth-backup-*.tar.gz  newhost:/root/

# 新机
git clone <仓库> /root/sci-agent && cd /root/sci-agent && git checkout <同一个 tag>
DOMAIN=your.duckdns.org sudo -E deploy-auth/setup.sh
sudo systemctl stop sci-auth
MIGRATE_PASSPHRASE='同一个口令' ops/migrate-import.sh /root/sci-auth-backup-*.tar.gz
sudo systemctl start sci-auth
```

包里有什么：`sci.db`（用户/档位/用量/审计）、`secrets.env`（`/etc/sci-auth.env`，设了口令则加密）、`one-api-data` 卷（装了 one-api 才有）。Caddyfile / systemd 单元 / fail2ban 全部由仓库模板生成，**不进包**。

**导入的安全次序**（每条都实测过）：
1. 先校验包内 sha256 与密钥可解密，**任何一项不过就在动数据之前中止**，本机数据不被触碰；
2. 现有库先备份成 `sci.db.bak-<时间>` 再替换；
3. one-api 卷先移到 `.rollback` 再解包，失败原样还回去；
4. **绝不无条件删 `.rollback`** —— 上次导入若在"移开之后、解包之前"被打断，数据唯一副本就在里面；
5. 导入完自动自检（起实例 + `/healthz` + 鉴权闸），不过就明确报错、别急着启服务。

⚠ **`KEY_SECRET` 必须跟着搬**。它不一致 = 全体客户端已签发的 key 立刻失效、所有人被迫重新登录。

⚠ **`DATA_DIR` 能改到别处，`one-api-data` 卷不能**：卷是按固定名字恢复的，所以在同一台机上做「模拟新机」的导入演练时，即便把 `DATA_DIR` 指到临时目录，**one-api 卷仍会被真的覆盖**（内容来自同一个包，通常无害，但要心里有数）。想完全不碰它：`ONEAPI_VOLUME=some-scratch-name ops/migrate-import.sh <包>`。纯粹只想验证包能不能恢复，用 `ops/rehearse-restore.sh` —— 它全程只读，绝不碰任何卷。

## 4. 账号发放流程（当前不做手机号注册）

1. 管理员登录 `https://<域名>/admin`（口令 + 图形验证码）。
2. 「+ 新建账号」填姓名、登录名、医院、职位、档位 → 提交。
3. 页面**只显示这一次**初始口令（12 位强随机）。当场复制，通过 OA / 企微转交给用户。库里只存 scrypt 哈希。
4. 用户在客户端用「登录名 + 初始口令」登录 → 被强制改密 → 改完才拿到可用的 key。

**找人**：搜索框支持用姓名里的**任意一个字或两个字**过滤，**姓氏优先**——输「张」，姓张的排最前，名字里带张的排后面；「欧阳」「小明」同样可用。也能用登录名 / 手机号 / 医院找，但排在姓名命中之后。

**管控**：改档位、调额度、停用、重置口令、重置 key —— 任一操作都会让该用户**已签发的 key 立刻失效**（`key_epoch++`），不必等票据自然过期。

## 5. 客户端对接（给桌面端的接口契约）

所有接口走 HTTPS，JSON。错误统一是 `{"ok":false,"error":{"code":"...","message":"..."}}`，**客户端按 `code` 给提示，别把 message 之外的东西直接甩给用户**。

| 接口 | 说明 |
|---|---|
| `POST /api/auth/login` | `{username,password}` → `{access, refresh, expiresAt, scope, mustChangePassword, profile}` |
| `POST /api/auth/refresh` | `{refresh}` → 新的一对（**refresh 用一次即废，必须存新的**） |
| `POST /api/auth/password` | `{oldPassword,newPassword}`，首次强制改密也走它 |
| `POST /api/auth/logout` | `{refresh}` |
| `GET /api/me` | 档位、模型、技能白名单、额度与用量 |
| `POST /llm/v1/chat/completions` | OpenAI 兼容。`Authorization: Bearer <access>` |

**约定**

- **baseURL 用 `https://<域名>/llm` 或 `https://<域名>/llm/v1` 都行**，网关会消掉重复的 `/v1`。
- `scope=pwchange` 的票据只能调 `/api/auth/password`，别的一律 403 `PASSWORD_CHANGE_REQUIRED`。
- 客户端每次请求带 `X-Client-Version`（服务端记录，后台可见）；调技能时带 `X-Skill: <技能id>`。
- 请求体里的 `model` **会被服务端按档位覆盖**——客户端不用也不该自己挑模型。
- 流式调用正常传 `stream:true` 即可，`stream_options.include_usage` 由服务端注入。

**错误码**

| code | HTTP | 客户端该怎么办 |
|---|---|---|
| `BAD_CREDENTIALS` | 401 | 提示账号或口令不对 |
| `PASSWORD_CHANGE_REQUIRED` | 403 | 跳到改密页 |
| `KEY_EXPIRED` | 401 | 静默用 refresh 换新票据；换不到再引导登录 |
| `KEY_REVOKED` | 401 | 提示「账号信息已变更，请重新登录」 |
| `ACCOUNT_SUSPENDED` | 403 | 提示「账号已停用，请联系管理员」 |
| `QUOTA_EXCEEDED` | 429 | 用 `error.scope`（daily/monthly）与 `used/limit` 给出明确文案 |
| `SKILL_NOT_ALLOWED` | 403 | 提示该档位未开通此技能 |
| `UPSTREAM_UNAVAILABLE` | 502 | 提示稍后重试 |
| `UPSTREAM_UNCONFIGURED` | 503 | 提示联系管理员（服务端没配上游 key） |
| `RATE_LIMITED` | 429 | 按提示等待 |

## 5.1 客户端的路由选择（桌面版）

客户端**默认走云端网关**（`OC_GATEWAY_URL` 指到 `https://<域名>/llm`，`OC_GATEWAY_KEY` 就是登录换来的 access key）。用户在对话框输入 `api-config` 可以改成走自己的 API；弹窗顶部始终显示当前走哪条路，走自定义时会出现**「切回云端网关」**按钮，一键回到平台统一调度。

- 走网关时弹窗**不回填**网关地址与模型名——否则用户容易以为那是自己的配置，一按保存就把网关地址连同自己的 key 存成自定义路由。
- 走自己的 API 时**不计入平台额度**（请求根本不经过服务器），这一点在弹窗里明说了。
- 切换两个方向都会重启后台模型进程；有轮次在跑时会先弹二次确认。

## 6. 计量与计费口径

- 计量**只在服务端做**。上游 key 不下发给客户端，所有模型调用必须经 `/llm`。客户端自报用量不作数（见改造方案 §3.1）。
- 成本 = 新鲜输入 × `COST_INPUT` + 缓存命中输入 × `COST_CACHE_READ` + 输出 × `COST_OUTPUT`，单位 USD/百万 token。
- 日/月额度都在**打上游之前**预检，超限直接 429，**一个字节都不会再发出去**。
- UTC 日切 / 月切（与旧架构一致，跨日自动清零）。

⚠ **上线后先对一次账**：把 `/admin` 看板的累计用量与供应商账单比一比。单价配错会让额度系统性偏，且偏得很安静。

## 7. 排障

| 症状 | 先看 |
|---|---|
| 服务起不来 | `journalctl -u sci-auth -n 50`。Node < 22 会在启动时明确报错 |
| 客户端一直 503 | `/etc/sci-auth.env` 的 `LLM_UPSTREAM_KEY` 没填 |
| 全员突然要重新登录 | `KEY_SECRET` 变了（换机器没带过来 / 被改写） |
| 某人一直 `KEY_REVOKED` | 刚被改过档位/额度/口令，让他重新登录即可 |
| 后台打不开（404） | `ADMIN_PASSWORD` 为空 = 管理台整个关闭 |
| 管理台口令怎么都不对 | 多半是手改时值后面跟了行尾注释（`EnvironmentFile` 不剥它），或首尾带了粘贴进来的空白。用 `ops/set-admin-password.sh` 改，它会挡住这几种 |
| 流式输出一卡一卡 | Caddy 少了 `flush_interval -1` |
| 备份 cron 报错 | 看 `/var/log/sci-auth-backup.log`；有 `.UNVERIFIED` 说明演练没过，**那个包不能用** |
