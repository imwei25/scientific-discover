## ① 已修（镜像构建链）

| # | 问题 | 影响 | 修法 |
|---|---|---|---|
| 1 | **LibreOffice 整个没装**，而 `server.mjs` 的预览链路要靠 `soffice` 把 pptx/ppt/odp/doc/odt 转 PDF | 任何 Office 类产物点预览 → `501 未安装 LibreOffice`；而 **ppt-master 技能的唯一交付物就是 .pptx** → 这个技能的产物全都预览不了。`warmPreviews` 还会把失败静默吞掉，用户只在点开时才发现 | Dockerfile 加 `libreoffice-impress libreoffice-writer`（`--no-install-recommends`，不带 JRE） |
| 2 | **ppt-master 自带的 requirements.txt 没有任何构建步骤安装它** | 技能核心路径 `svg_to_pptx` 第一行 `import pptx` 就 `ModuleNotFoundError` —— 整个技能不可用 | 把**核心产出路径**用得上的合进 `deploy/requirements.txt`：python-pptx / XlsxWriter / Pillow / svglib / markdownify / EbookLib / nbconvert。刻意不装的可选项（edge-tts / curl_cffi / google-genai / flask / cairosvg）在文件里写明了原因 |
| 3 | **`/app/.venv` 在镜像里根本不存在**，但 `web/server.mjs` 的 `PYEXE` 指向它，且 `mammoth` 也没装 | docx 预览 **100% 失败**（`500 DOCX 预览转换失败`） | ① Dockerfile 创建 `/app/.venv`（`--system-site-packages`，复用系统包不重复占空间）；② `mammoth` 进 requirements；③ `PYEXE` 加回落：`.venv` 不在就用系统 `python3` |
| 4 | **AGENTS.md + 19 个 SKILL.md 都写死"Python 走项目根 `.venv`"，而镜像里没有** | agent 按路由去跑 `env-setup`，在 `mem_limit 1750m` 的容器里现装 pandas/scipy/matplotlib 全家桶：数分钟、可能 OOM，且装在**容器可写层**——每次重建容器又没了，就是那个"上周还能用，今天又不行" | 选**造 venv** 而不是改 20 个文件：一处 Dockerfile 改动，本地开发与容器的约定还能保持一致 |
| 5 | `data-integrity` 技能声称"paperconan 已装在 `.venv` 里"，但**任何 requirements 都没有它** | `paper` 流水线里的数据自查闸一调用就失败 | 加 `paperconan==0.8.2`（**已先查证 PyPI 确实存在**——写个不存在的包名会让整个镜像构建失败） |
| 6 | **`matplotlibrc` 在仓库里根本不存在** | 中文图出豆腐块。且技能自带的配方 `font.sans-serif=['Arial','DejaVu Sans','Liberation Sans']` **一个含中文字形的都没有** | 新建 `deploy/matplotlibrc` + `COPY` + `ENV MATPLOTLIBRC`。按第一轮踩出来的机制写：**逐字形回退只在 `font.family` 是多族列表时才触发**，故写 `font.family: sans-serif, Noto Sans CJK SC`（只写 `font.sans-serif` 无效——它取到第一个能解析的就不再往后找） |
| 7 | `npm install` + 没 COPY `package-lock.json` → SDK 浮动 | `package.json` 里 SDK 是 `^1.17.14`，而 opencode CLI 被钉死在 1.17.14。每次重建都可能装到不同 SDK 小版本，而网关重度依赖 SDK 细节行为（`event.subscribe` 的 signal 透传 / `session.revert` / `session.cost`），一次静默升级就可能让**流式或成本计量**失灵 | 改 `COPY web/package.json web/package-lock.json` + `npm ci --omit=dev`（已核对 lock 存在、已入库、与 package.json 一致） |

**构建期自检**：Dockerfile 里加了 `/app/.venv/bin/python -c "import pandas, matplotlib, mammoth"`——
依赖装歪就**在构建时炸**，而不是等用户点预览才发现。

**两处已自查过的坑**：
- 注释一律写在 `RUN` 之外。反斜杠续行中间夹注释虽然 Docker 解析器会剥掉，但这是个经典易踩点，
  且本机无法 `docker build` 验证 → 不赌。已用脚本扫过全文件，确认没有"续行下一行是注释"的写法。
- `deploy/matplotlibrc` 用本机 matplotlib 3.11 以 `rc_params_from_file(fail_on_error=True)` +
  警告当错误**实测解析通过**，6 项全部正确，且 `font.family` 确实解析成多族列表
  `['sans-serif', 'Noto Sans CJK SC']`——正是逐字形回退所需的形态。

## ② 已修（网关侧）

- **`.preview` 缓存被计进用户配额**：`dirSize` 递归时会把它算上，但文件列表跳过点开头的项 → 用户**看不见、删不掉、却要为它掏配额**。
  它是服务端生成的派生数据，已改为**不计入配额**。
  （顺带纠正排查 agent 的一个判断：它说"单文件删除会遗留孤儿预览"——实际预览缓存只在 `outputs/` 下生成，
  而唯一的单文件删除端点 `/api/upload/delete` 只管 `uploads/`，这条孤儿路径**不成立**。）
- **LibreOffice 临时 profile 泄漏**：每次转换都在 `/tmp` 铺一套数 MB 的 profile 且从不删除（超时被 kill 那次也留）。
  改成 `finally` 里必删。此前是潜伏的——LibreOffice 没装所以从没触发；**第 ①.1 条修好的那一刻它就会开始漏**。
- **opencode 起不来时全站静默坏掉**：网关照常监听端口、manager 只探端口 → 判定健康；
  用户登录、发消息、拿到一个没有原因的失败。现在：新增 `GET /api/health`（返回真实依赖状态，opencode 挂了回 503），
  且建会话失败时**直接给人话**（"后台模型服务尚未就绪…"）而不是 500 堆栈。
  实测：opencode 未运行时 `/api/health` → `503 {"opencode":false}`；发消息 → 503 + 中文提示。
- 顺手：docx 转换失败的 HTML 响应里，把内含文件名的错误信息做了转义（自伤级，但不留这种口子）。

## ③.5 回归审查（对第三轮改动）—— 又修了 6 处

派对抗 agent 复审本轮改动。它确认我重点担心的 7 项本身都没问题
（Dockerfile 续行夹注释合法、`--system-site-packages` 能看到 `--break-system-packages` 装的系统包、
新增包与已钉版本**逐个核过 PyPI requires_dist 无冲突**、matplotlibrc 解析正确、`npm ci` 与 lockfileVersion 3 兼容、
AGENTS.md 零损坏、`/app/.venv` 不会被卷盖掉），但抓出 6 处该改的：

| # | 严重度 | 问题 | 修法 |
|---|---|---|---|
| 1 | **高** | **LibreOffice 无全局并发闸**：后台预热走 `_warmQueue` 串行，但 `/api/preview` 直接调用、不进队列 → 用户点预览时预热正在跑、或两个标签页同时点，就会有 ≥2 个 LO 进程。单个转 pptx 峰值 300–600MB，而容器上限 1400–1750m → **OOM-kill 打死的是整个容器（opencode + 网关一起没）**，不是这一次预览。<br>**这是我装上 LibreOffice 才激活的风险** | 在最底层加全局串行闸 `withSoffice`，无论谁调用都排队。实测：5 个并发任务**峰值并发 =1**，且中间夹一个失败任务不会卡死后续 |
| 2 | **高** | `/api/health` 被挡在登录闸后面 → 没有登录票据的探针（manager/compose healthcheck/monitor）只会拿到 302 跳登录，**这个端点等于白做** | 加进 `PUBLIC_PATHS`；同时把响应里的模型名去掉（公开端点没必要透露用哪个模型），只回两个布尔 |
| 3 | **高** | `PYEXE` 在模块加载时**一次性求值**，不像 `soffice()` 那样惰性探测 → 若 `.venv` 是网关启动之后才建好的，进程整个生命周期都用系统 python3、再也切不回去 | 改成惰性 + 缓存，与 `soffice()` 同构 |
| 4 | 中 | `nbconvert` 为了「ipynb→md」拖进整个 jupyter 生态，**十几个传递依赖全不钉版本**——与我刚给 npm 加 lockfile 追求的可重复构建正好相反，镜像还要涨几百 MB | **删掉**。镜像里已有 pandoc，`pandoc x.ipynb -o x.md` 同样能转 |
| 5 | 中 | `paperconan` 只装了裸包：`pdfplumber` 挂在 `pdf` extra、`python-docx` 挂在 `docx` extra。而该技能声明的输入范围**明确含「pdf/docx 里的表格」** | 改 `paperconan[all]==0.8.2`（已查证 PyPI 上 `pdf`/`docx`/`all` extra 确实存在） |
| 6 | 中 | `.preview` 不计配额之后变成「不受限也不回收」：活跃会话里每个新文件名都生成一份缓存 PDF，只在删会话时才整目录清 → **配额显示没满、卷先写爆** | 加 LRU 裁剪（默认上限 200MB，`PREVIEW_CACHE_MAX_MB` 可调），每次写完缓存按 mtime 从最旧删起 |
| 7 | 中 | mammoth 直出的 HTML **不过滤 `javascript:` 协议**的超链接。这条路径以前因 mammoth 没装、docx 预览 100% 失败而从没真正跑过，**装上后才第一次生效** | docx 预览响应加 CSP 沙箱（与 `/api/raw` 对 html/svg 的处理一致） |

### ⚠ 阻塞项：两个未入库文件会让【下一次构建直接失败】

我核对了 Dockerfile 现在 COPY 的每个路径的入库状态：

- **`deploy/matplotlibrc` 未入库**，而我新加的 `COPY deploy/matplotlibrc /app/matplotlibrc` 依赖它
  → 服务器 `git pull` 后 `docker build` 会 **`file not found` 直接失败**。
  这是我引入的，必须提交后才能部署：`git add deploy/matplotlibrc`
- **`deploy/skills/ppt-master/` 未入库**（`deploy/skills/` 下**唯独它**是 0 个文件入库，其余技能都在）
  → 镜像里不会有这个技能，而 requirements 里为它装的 python-pptx/XlsxWriter/svglib 全白装、白撑镜像。

**`deploy/skills/ppt-master/` 整个目录没有入 git**（`git ls-files` 为空）。
→ 从干净 clone 或 CI 构建镜像，`COPY deploy/skills/` 会产出一个**没有 ppt-master 的镜像**；
现在能用纯粹是因为这台开发机上有这个目录。

不敢替你 `git add` 的原因：**12,180 个文件 / 41 MB**，其中 `templates/` 占 11,828 个，
另有 5 个 `__pycache__` 目录（不该入库）。入库前建议：
1. 先加 `.gitignore` 排除 `__pycache__/`；
2. 确认 `templates/` 这一万多个文件是否真的都要进版本库（还是应该做成可下载资源）。
