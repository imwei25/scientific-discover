### D1. `web/quota.mjs` + `web/admin.html` + `deploy/state/` 是一整套【未接线的废弃分级设计】
- 现状：`server.mjs` **未 import** `quota.mjs`，也无任何 `/api/admin/*` 路由、无返回 admin.html 的静态路由。整套"按 token 计、北京时间重置"的用户分级在运行时**零生效**；实际生效的是 server.mjs 内置的**按 USD 计、UTC 重置**的额度。真正的管理台在**宿主侧** `deploy/manager.mjs` 的 `/admin`（有 ADMIN_PASSWORD+验证码+审计）。
- 危害：① 死代码留在镜像里误导后续脚本——**本轮 export-all.sh 就是被 `./state` 带偏、差点让迁移丢数据**；② 未来若有人把 `quota.mjs` 的 `setUserTier/setTier/listAll` 接进 server.mjs 而忘了 `IS_ADMIN` 门禁，**每个注册用户都能改所有人档位**。
- **建议 1（推荐）**：删掉 `web/quota.mjs`、`web/admin.html`、`deploy/state/` 三者——它们已被宿主侧 manager.mjs 的方案取代，留着只会继续误导。
- **建议 2**：若你本就想在容器内做 token 分级，则把它接进 server.mjs 并加 `IS_ADMIN` 门禁 + 统一两套额度的计量单位(USD vs token)与重置时区(UTC vs 北京)。
- 回 1 / 2 即可推进。

### D2. `deploy/manager.mjs` 未鉴权即唤醒/驱逐容器（公网可 DoS）
- 现状：任何公网访客 `GET /alice/任意路径`（除 `/api/login`）都直接触发 `ensureUp(alice)` → `docker start`，容器**之后**才自己校验 401。`makeRoom()` 还会 LRU 停掉其它空闲容器腾位。
- 危害：无需登录、无验证码，循环打 `/alice/`、`/bob/`… 即可把容器反复冷启动（每次 10–40s）、驱逐在线空闲用户、烧 CPU。
- 这是**架构取舍**（当前设计有意让容器自管鉴权、manager 只做路由）：要堵就得在 manager 侧、`ensureUp` 之前加一道 cookie/会话校验或按源 IP 限速唤醒——会改动 manager 的信任模型。**建议**：对非 `/api/login` 的代理路径，`ensureUp` 前要求带 `lan_auth` cookie；配合按 IP 的唤醒限速。要动吗？

### D3. `deploy/setup.sh` 默认管理密码 + 重跑覆盖 systemd 单元
- D3a：`setup.sh` 把模板里的 `ADMIN_PASSWORD=change-me-a-strong-admin-password` 原样装进 systemd 单元并 `enable --now`，`ADMIN_ENABLED=!!ADMIN_PASSWORD` 为真 → **公网任何知道仓库的人过个验证码就进 /admin**（加删用户、改档位、塞网关渠道）。
- D3b：号称"幂等可重复跑"的 setup.sh **每次都用仓库模板覆写线上单元**，静默把运维改过的 `WARM_CAP=5`→2、管理密码→默认值回滚（`enable --now` 对已运行服务不重启 → 下次重启才炸，延时炸弹）。
- 这两条**偏安全修复而非纯设计**，但改法会动部署脚本行为，且你线上可能已手改过这些值——**不敢擅自改你线上的东西**，列给你定。**建议**：模板 `ADMIN_PASSWORD` 置空（默认关管理台）、setup.sh 检测到占位值/单元已存在时**告警拒装或只 diff 提示**、把 `WARM_CAP/IDLE_MS/ADMIN_PASSWORD` 挪到 `EnvironmentFile` 与单元解耦。要我按此改吗？

## ④ 回归自查（对我这批改动再派一个对抗 agent 复审）— 抓到 2 个自引入 bug，已修

- ✅ **`server.mjs` 上传 chunked 路径 inflight 泄漏（中高）**：无 Content-Length 的 chunked 上传超限掐断后，`req` 仍在 flowing、`data` 监听器继续给 `inflightUploadBytes` 加字节（`release()` 已执行完），计数只涨不回 → 最终把所有人上传卡死。修法：加 `stopped` 标志，掐断后 `data` 回调直接 return 不再累加。**实测坐实**：3× chunked 超限（curl 40MB）各 0.12s 干净 413，随后 10MB 正常上传 200 成功 → 计数每次完整归零、无泄漏。
- ✅ **`manager.mjs` 登录限额先 destroy 后回包（低中）**：`req.destroy()` 拆掉 res 共用的 socket，413 可能发不出去还触发无监听的 res error。修法：先 `writeHead(413)+end`、加 `Connection: close`、去掉 destroy，从 for-await `return` 自然停读。（manager 需 docker，静态验证 `node --check` 通过。）

审过确认无回归的点（agent 逐一核过）：/api/chat await 移位后三分支语义不变、幽灵气泡 gotAny 门控正确、RFC5987 拼接无漏、export/import 正则锚定不误匹配 + set -e 不中断计数、yaml_esc 转义顺序对、bootstrap cmp/mv 首次运行正确、backup fail 计数与 set -e 不冲突。

### D2 ✅ manager 未鉴权唤醒容器（公网 DoS）：cookie 门禁 + 冷启动限流（双层）
`deploy/manager.mjs`：

1. **门禁**：`/<user>/*` 在 `ensureUp` 之前先看有没有 `lan_auth` cookie。没有 → **不唤醒任何容器**，
   HTML 请求 302 到站点根登录页、API 回 401。
   *为何只查"cookie 在不在"而不验签*：签名密钥是各容器的登录密码，用户还能自助改密，manager 无从验证；
   真正的密码校验仍归容器。这层挡的是"从没登录过的流量"。
2. **冷启动限流**（真正的兜底，因为 cookie 可以伪造）：按来源 IP 滑动窗口，**默认 5 分钟内最多 10 次冷启动**
   （`WAKE_MAX` / `WAKE_WINDOW_MS` 可调）。只对**真实冷启动**计数——已在跑的容器走代理完全不受限，正常使用无感。
   超限回 429 + `Retry-After`，并记审计 `wake.throttled`。
- 验证：抠出真实 `wakeAllowed` 单测 → 同 IP 15 次请求放行 10 拦截 5、另一 IP 不受影响（PASS）。
  端到端需 docker，未在本机跑。

**D2 期间发现并修掉一个既有断裂**（不是本次改动引入，但正好在这条链上）：
容器自带的 `web/login.html` **不发图形验证码**，而 manager 的 `POST /<user>/api/login` **强制校验验证码**

## ⑥ 剩余项全部清零 + D1–D5 回归审查发现的问题（2026-07-19 第二批）

### 6.1 原「仍待处理」三项 —— 已全部修掉

**A10 事件流泄漏 ✅**（此前因"SDK 未装、不敢瞎改"搁置）
SDK 其实在 `web/node_modules/@opencode-ai/sdk`（之前在仓库根找，找错地方了）。读源码确认链路：
`event.subscribe(options)` → `get.sse({...options})` → `createSseClient` → `fetch(url,{signal})`，
且重试循环顶部有 `if (signal.aborted) break`。故按 AbortController 收口：每个 job 建一个 `evAbort`，
`subscribe({ signal: evAbort.signal })`，`finish()` 里 `evAbort.abort()` —— 末轮订阅不再空转到下一个事件。

**`/pub/gateway/siblings` 未鉴权 ✅**
**挪路径**而非加判断：`lan_auth` 的 Cookie `Path=/<用户名>/`，压根不会发到 `/pub/` 上，
在原路径加鉴权根本拿不到凭据。改为 `/<用户名>/pub/gateway/siblings`，由 manager 在 **D2 登录门禁之后**应答
（顺带不必为查个模型名去唤醒容器）；前端改用相对路径。顶层的未鉴权路由已删除。

**GET 起轮 → POST 起轮 ✅（同时根治 CSRF 与超长消息丢失）**
新增 `POST /api/chat/start`（正文在 body）+ 沿用 `GET /api/chat/attach` 订阅直播；**旧的 `GET /api/chat` 已删除**。
- 治 CSRF：cookie 是 SameSite=Lax，跨站顶层 **GET** 导航会带凭据，诱导点击即可替用户跑一轮长生成烧额度；改 POST 后跨站请求不再携带 cookie。
- 治静默丢消息：长正文塞 URL 撞 Node 16KB 请求头上限 → 431，而前端 SSE `onerror` 会把它当网络抖动去重连，**消息就此消失**。
- 前端配套：`sendMessage` 改为「POST 起轮 → 按返回值决定 → attach」；**气泡是否"幽灵"改由服务端返回值直接决定**
  （比原先从 SSE 事件反推更可靠，attach 续流时不会再误判），并新增 `sending` 标志防连点重复发送。
- 验证：**144KB 正文 POST → `{ok:true,sent:true}`；同样内容走 GET query → HTTP 431**（对照实测，正是原 bug）；
  旧 `GET /api/chat` → 404；空消息 → 400；5MB body → 413；浏览器实跑请求序列为 `POST api/chat/start` → `SSE api/chat/attach`；
  连点三次只发出 **1** 个 POST；服务端 500 时提示准确且气泡被正确标为幽灵；控制台无报错。
