# 0.1.33 发布说明

> 聊天接入出问题时更好查：软件会把「服务端在哪、命令怎么敲」自动写在手边，省掉来回猜的功夫。功能与上一版一致。

## 这版有什么变化

### 聊天接入：自动留下排查线索

**背景**：0.1.31 把聊天组件的数据目录换到了专属位置（那是为了修「微信发文件失败」）。副作用是——在命令行里手敲 `cc-connect` 去测试时，它会**默认去找旧位置**，那里没人接，于是报一句：

```
dial unix ...\.cc-connect\run\api.sock: connect: No connection could be made ...
```

**这句话看着像坏了，其实多半只是命令敲错了地方。** 加上机器上常常还装着另一份旧版 `cc-connect`（参数都不一样），排查一次要绕很多圈——两台机器上都真实发生过。

现在软件每次启动聊天接入，都会在 `chat-bridge` 文件夹里自动写下两个文件：

- **`cc-send.cmd`** —— 参数已经填好的现成命令，直接 `cc-send.cmd -m "hello"` 就能给自己发条消息试试。
- **`如何手动排查.txt`** —— 写明当前的数据目录、该用哪个程序、命令怎么敲；还写了**怎么确认连通又不浪费微信发送次数**（有两种报错其实代表"已经连上了"）、真出问题该看日志哪几行、以及"发送失败最常见的原因是次数用尽而不是连不上，此时越重试恢复得越慢"。

> 这两个文件每次启动都会重写，改了会被覆盖。它们只是排查用的说明，不影响正常使用——日常用软件完全不需要打开它们。

---

## 升级提示

- 桌面版会自动检查更新；也可以从软件内手动更新。
- 这版**没有**改动聊天、写作、出图等任何功能，只是加了上面的排查文件。
- 上一版（0.1.32）的「微信思考并进一条发，省发送次数」和「升级后不必先发消息也能收到定时推送」同样包含在内。
