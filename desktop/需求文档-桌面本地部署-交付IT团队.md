# 需求文档：科研医学 Agent 桌面本地部署版

> 版本：v1.0（2026-07-28）｜需求方：AI团队｜实施方：IT 团队

---

## 0. 目标

把科研医学 Agent 做成**客户 Windows 电脑上一键安装的桌面应用**：算力与数据全部在客户本机，
云端做「用户身份/鉴权 + token 计量管控」。
商业控制点 = 云端 key：不续费/停用 → 产品失能。

## 1. 背景与现状（供理解，非需求）

- **应用本体已成熟可运行**（这是本次交付的基础，应该不在 IT 改造范围内）：
  web 界面网关（node, `web/server.mjs`）→ opencode agent 引擎 → 23 个技能
  （SKILL.md 提示词 + Python/Bash 脚本，Python 栈钉版于 `deploy/requirements.txt`）。
- **云端服务是空白画布**：需求方此前个人做过一些服务器端的试验验证（不成熟、不移交、
  不必沿用），云端的正式架构由 IT 团队从零设计；试验中验证过的个别结论会在相关条目
  标注"参考"字样，仅供缩短调研，采不采用完全由 IT 决定。
- **客户端必须原样吸收应用本体与技能目录**。

## 2. 角色与职责边界

| 角色 | 负责 | 不负责 |
|---|---|---|
| **AI团队** | `.opencode/skills/` 全部技能内容、`AGENTS.md` 主控指令、`deploy/requirements.txt` Python 依赖钉版 | 打包、分发、云端服务、运维 |
| **IT 团队** | 桌面客户端（打包/安装/启动/更新）、云端服务（注册登录/key 管理/计量/后台）、发布、注册流程 | 技能内容本身 |

**接口约定（最重要的一条）**：技能目录 + AGENTS.md + requirements.txt 就是双方的全部接口。
技能负责人更新这三样 → IT 的构建管道自动吸收进下一版客户端；IT 不修改技能内容，
技能负责人不关心打包细节。技能有跨平台约束时以本文 §3.6 为准。

## 3. 需求清单

优先级标注：【必须】v1 上线前提；【应当】v1 尽量、v1.x 必须；【可选】有条件再做。

### 3.1 桌面客户端

- 【必须】一键安装
  环境（含 Python/Node/Git；WebView 运行时缺失时自动补装）。
- 【必须】自包含运行：安装后即含完整运行时（agent 引擎、Python 科研栈、文档转换工具、
  技能全集）。除 LLM 调用与文献检索外不依赖外部环境。
- 【必须】启动体验：双击图标 → 加载页 → 主界面（现有 web 界面）。后台引擎进程**全程无窗口**、
  不在任务栏出现；应用退出时后台进程**全部回收**，不留残留进程/占用端口。
- 【必须】进程与端口安全：agent 引擎端口只绑 127.0.0.1（引擎无鉴权，绝不可暴露到局域网）；
  web 网关如对局域网开放，必须有本地密码门禁（现有机制可复用）。
- 【必须】故障可诊断：后台日志落盘；提供一个客户现场可执行的自检脚本/入口，能一次性验证
  运行时完整性（Python 栈可用、文档转换可用、技能调用契约成立）。
- 【应当】客户端自动更新：新版本发布后客户端能提示/静默升级（含技能更新，见 §3.5）。
- 【应当】首次启动引导用户注册流程。

### 3.2 云端：用户身份与登录

- 【必须】注册/登录方式：**手机号 + 短信验证码**；**微信扫码**（二选一，请 IT 评估）。
- 【必须】云端维护用户档案：身份（手机号/openid）、**档位（分级）**、状态（正常/停用）、用量。
  分级管理是硬需求：不同档位对应不同模型，不同skill模块，与不同额度。
- 【必须】登录成功后云端向客户端下发一个**有效期内有效的 key**（含到期时间、可用模型、档位信息）；
  客户端缓存后，**有效期内再次启动免登录**；临近到期静默续期；过期/被停用 → 引导重新登录。
- 【必须】key 即管控点：云端可随时对单个用户**停用/调额/调档**，效果在下一次用户登录生效
  （客户端收到 401/额度耗尽时给出明确提示而非裸报错）。

### 3.3 云端：token 计量与计费

- 【必须】按用户记量：每个用户的 token 消耗可查（日/月/累计），作为计费与额度依据。
- 【必须】额度控制：按档位设额度上限，超限拒绝并提示；
- 【必须】上游模型通道管理：多渠道调度/故障切换/换模型对客户端透明。
- 【应当】用量异常告警：单账号用量突刺提醒运营（防 key 外借/泄露滥用）。

### 3.4 云端：运营后台

- 【必须】最小后台能力：用户列表（搜索）、改档位、停用/启用、发/重置 key、看用量。
  形态不限（网页后台或成熟工具皆可），但操作要简单易懂。
- 【后续】数据看板：活跃用户、总用量趋势。

### 3.5 版本与技能分发

- 【必须】构建管道：从代码仓库一键构建出安装器（技能目录、AGENTS.md、requirements.txt
  从仓库直接吸收，**不得在打包环节手工拷贝/修改技能**）。
- 【必须】版本可追溯：每个安装包有版本号；云端能看到各用户客户端版本（随 LLM 调用或心跳上报）。
- 【应当】技能热更新：仅仅是技能内容更新时不必重发整个安装包（技能目录体积 <100MB，可增量分发）；
  由此AI团队的技能更新与客户端版本解耦。
- 【可选】灰度：新版本可先发部分用户。

### 3.6 跨平台契约（技能侧已承诺、打包侧必须保障）

以下是技能正常运行的环境契约，**无论 IT 采用什么打包方案都必须成立**：

1. 项目根存在 `.venv`，且 `.venv/bin/python`（POSIX 风格路径）与 `.venv\Scripts\python.exe`
   **都能执行**并加载同一套科研 Python 栈（钉版 `deploy/requirements.txt`）；
2. 环境变量 `REPO_ROOT` 指向应用根（正斜杠路径），bash 中 `${REPO_ROOT:-/app}` 展开正确；
3. 命令行环境提供：`bash`（支持 heredoc/管道/source）、`git`、`pandoc`、裸 `python3`；
4. matplotlib 中文不出豆腐块（系统级 rc 兜底，含逐字形回退）；
5. 每个会话有独立工作目录（产物目录），agent 写裸文件名即落对应会话目录（现有网关机制）。

技能只依赖以上契约，不再引入新的系统级依赖；如需新增（例如新工具二进制），
提前与 IT 协商进包。

### 3.7 安全与合规

- 【必须】agent 引擎不对外暴露（见 §3.1）；key 传输走 HTTPS。
- 【必须】隐私口径：对外宣传"数据不出本地"时，必须同时声明"提交给 AI 分析的内容
  （含脱敏后文本）会发送至云端大模型"。产品内置 deidentify 脱敏技能，但说明文档需把
  "含患者数据先脱敏"写为客户义务。
- 【必须】云端不存储用户内容数据（会话/文件都在客户本机），只存身份/档位/用量。
- 【应当】客户端凭据保护：key 本地存储位置权限收敛（接受"无法对本机管理员保密"的现实，
  防滥用主要靠有效期+额度+可踢，见 §3.2/3.3）。

### 3.8 明确的非目标（v1 不做）

- 不做离线运行（LLM 与文献检索必须联网）。
- 不做技能内容的强 IP 保护（技能明文随包分发；护城河=云端 key + 持续更新）。
- 不做本地多账号（一机一套数据；客户内部门禁用现有局域网密码机制）。
- 不做 macOS/Linux 客户端。
- 不打包 texlive（出版级 PDF 排版）与 LibreOffice（pptx 在线预览）：体积原因刻意降级，
  客户机自装后功能自动恢复；安装器可【可选】提供"完整版"变体，由 IT 权衡。

## 4. 验收标准（全部满足即 v1 通过）

| # | 场景 | 通过标准 |
|---|---|---|
| A1 | 全新 Win11 家用机（无任何开发环境）双击安装 | 无管理员权限完成安装；桌面/开始菜单有图标 |
| A2 | 首次启动 | ≤60 秒进入主界面；无任何黑窗口闪现 |
| A3 | 注册登录 | 手机号+验证码完成注册；客户端获得 key 进入可用状态 |
| A4 | 免登录 | 重启应用不再要求登录（key 有效期内）；到期前静默续期 |
| A5 | 对话+技能 | 上传 csv → 统计分析出含中文标签的图（中文显示正常）；生成 docx 排版文件；产物在界面侧栏可下载 |
| A6 | 计量 | 云端后台能看到该用户本轮的 token 消耗 |
| A7 | 停用 | 后台停用该用户 → 客户端下一轮对话被拒并提示重新登录/联系客服；重新启用即恢复 |
| A8 | 额度 | 超出档位额度被拒并有明确提示 |
| A9 | 调档 | 后台调档 → 用户可用模型/额度随之变化 |
| A10 | 退出 | 关闭窗口后无残留后台进程、端口全部释放 |
| A11 | 安全 | 局域网内其他设备无法访问 agent 引擎端口；访问网关必须输本地密码 |
| A12 | 卸载 | 控制面板正常卸载，无残留服务 |
| A13 | 诊断 | 客户现场跑自检脚本能输出各运行时组件的通过/失败结论 |
| A14 | 技能更新 | 技能负责人改一个 SKILL.md 合入仓库 → 走管道到达客户端（热更新或下一版安装包），无手工搬运 |


## 5. 交接与协作方式

- 代码仓库、分支、PoC 全部移交 IT；AI团队保留 `.opencode/skills/`、`AGENTS.md`、
  `deploy/requirements.txt`。
- 需求疑问找需求方澄清；技术选型 IT 自主决策，以验收标准为准。
